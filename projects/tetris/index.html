Rust 게임 코어와 플랫폼 연계를 구성하고, WebAssembly 웹 클라이언트·WebSocket 멀티플레이·Three.js 보드 렌더링을 구현한 1인 프로젝트입니다.

담당 작업​

Rust 공통 게임 코어

이동·회전·벽 킥·줄 제거 규칙과 단위 테스트를 작성하고, Rust 서버와 WebAssembly 클라이언트가 같은 보드 코어를 사용하도록 구성했습니다.

WebSocket 멀티플레이

액션 복제와 보드 스냅샷 동기화, 로비·방·게임 세션 전환 및 배틀 공격 큐를 구현했습니다.

웹 렌더링과 입력

Three.js 인스턴싱으로 여러 참가자의 보드를 그리고, 키보드·모바일 터치 입력과 고정 tick 게임 루프를 연결했습니다.

인증과 서비스 배포

게스트 로그인과 JWT 세션을 게임 연결에 적용하고 웹·인증 API·WebSocket 서버의 빌드 및 배포 경로를 구성했습니다.

기술 문서​

  • Foundation1
    • Rust 보드 규칙을 서버와 WebAssembly 클라이언트에서 공유하기보드 판정 코어를 Rust crate로 분리하고 WASM 바인딩과 TypeScript 타입 생성으로 웹 클라이언트에 연결한 구조RustWebAssemblyArchitecture
  • Gameplay3
    • 테트리스 보드 규칙과 문자열 기반 단위 테스트타일 상태·회전 테이블·벽 킥·줄 제거를 구현하고 작은 보드의 기대 결과를 비교해 검증한 과정RustGameplayTesting
    • 키보드·모바일 터치 입력과 고정 tick 게임 루프입력 반복 간격을 직접 제어하고 모바일 버튼을 같은 동작 경로에 연결한 구조와 프레임 지연 처리TypeScriptInputGameLoop
    • 블록 공급·점수 계산과 배틀 공격 큐7-bag·Next·Hold에서 줄 제거와 점수 이벤트를 거쳐 상대 보드의 쓰레기 줄로 연결하는 게임 진행 구조GameplayTypeScriptRustMultiplayer
  • Network2
    • WebSocket 액션 복제와 보드 스냅샷 동기화로컬 입력을 즉시 실행하고 서버 액션을 다른 보드에 재현하는 흐름과 전체 상태 복원·예측 보정의 실제 구현 범위RustWebSocketMultiplayer
    • 로비·방·게임 세션의 생명주기 연결WebSocket 토픽과 방·게임 상태를 나눠 입장, 준비, 시작, 결과 표시, 퇴장과 백업까지 연결한 구조RustWebSocketState Management
  • Rendering1
    • Three.js 인스턴싱으로 여러 테트리스 보드 그리기보드별 상태를 종류별 인스턴스 그룹으로 합치고 두 단계 dirty 갱신과 참가자 수 기반 배치를 연결한 렌더링 구조Three.jsInstancingRendering
  • Backend1
    • Rust 인증 API·WebSocket 서버 분리와 배포 구성게스트 로그인과 JWT 세션을 게임 연결에 적용하고 WASM 웹·API·WebSocket의 빌드 및 배포 경로를 구성한 과정RustAxumPostgreSQLDocker
