# 테트리스 보드 규칙과 문자열 기반 단위 테스트

## 화면을 띄우지 않고 판정 결과를 확인하기

테트리스는 블록이 움직이는 모습을 보는 것만으로 규칙을 검증하기 어렵다. 벽 근처에서 회전할 때 어느 후보 위치를 선택하는지, 두 줄을 동시에 지운 뒤 남은 타일이 어디로 내려오는지처럼 특정 배치를 반복해서 확인해야 하는 경우가 많다.

Rust 공용 코어에 보드 규칙을 모으고, 테스트에서는 작은 보드에 필요한 장애물을 직접 배치했다. 동작 전후의 보드를 문자열로 출력해 기대 결과와 비교하고, 실패해야 하는 동작은 오류 종류를 확인했다. 렌더러나 WebSocket 서버 없이 보드 규칙을 확인할 수 있도록 한 구성이다.

## 낙하·고정·힌트를 구분하는 타일 모델

`Board`는 `Vec<Vec<Tile>>`로 행과 열을 보관한다. 빈 칸, 낙하 중인 블록, 고정된 블록, 착지 힌트를 `Tile` enum으로 구분한다.

낙하 블록은 종류뿐 아니라 `D0`·`D90`·`D180`·`D270` 회전 상태와 테트로미노 내부 타일 ID를 가진다. ID는 네 타일을 회전 테이블의 각 항목에 대응시키는 기준이다. 고정 시에는 `Placed`로 바꾸며, 힌트는 `Hint`로 저장한다.

Y는 아래로 갈수록 증가한다. 기본 보드는 10×26이고 테스트는 10×3, 10×4, 10×8 등 작은 보드도 사용한다. 다만 생성 X 좌표와 쓰레기 줄 너비는 10열을 전제로 한다.

## 생성과 이동

생성은 `SPAWN_TABLE`의 종류별 네 좌표 오프셋에 기준 위치를 더해 처리한다. `try_spawn_falling()`은 종류별 시작 X와 보드 높이에 따른 Y를 선택하고, `try_spawn_falling_at()`이 실제 타일 배치를 만든다. 이미 낙하 블록이 있다면 `FallingTileExists`를 반환한다.

좌우 이동은 각 타일의 목표 X를 검사한다. 경계를 벗어나면 `OutOfBounds`, 고정 타일에 막히면 `Blocked`다. 빈 칸과 힌트, 같은 종류의 낙하 타일은 통과 가능한 상태로 처리한다. 한 번에 하나의 낙하 테트로미노가 존재한다는 사용 전제다.

성공한 결과는 바로 보드를 바꾸지 않고 이동 계획으로 반환한다. 적용 단계에서 기존 네 위치를 먼저 지우고 새 위치를 채운다. 이 API 경계는 공용 Rust 코어와 WASM 연결 문서에서 설명한 구조이며, 여기서는 구체적인 규칙과 테스트에 초점을 둔다.

## 회전 테이블과 벽 킥 후보

회전은 매번 실수 행렬로 계산하는 대신, 종류·현재 회전 상태·타일 ID로 `RIGHT_ROTATE_TABLE`의 정수 오프셋을 조회한다. 왼쪽 회전은 다음 반시계 회전 상태의 오른쪽 회전 오프셋을 역방향으로 사용한다. O 블록은 타일 위치를 유지하면서 회전 상태만 바뀐다.

기본 회전 위치가 막히면 벽 킥 후보를 순서대로 확인한다. I 블록 전용 테이블과 JLSTZ 테이블을 나누고, 기본 `(0, 0)` 보정을 포함해 최대 다섯 후보를 검사한다. 각 후보에 대해 네 타일 모두 경계와 고정 타일을 통과해야 성공한다. 첫 성공 후보를 선택하고 모든 후보가 실패하면 오류를 반환한다.

`wall_kick_j_0` 테스트는 장애물이 쌓인 작은 보드에서 J 블록을 왼쪽으로 회전시킨 뒤 최종 배치를 비교한다. `wall_kick_t_1`부터 `wall_kick_t_8` 등도 특정 배치의 회전 결과를 확인한다. 단순히 빈 공간에서 모양이 바뀌는지뿐 아니라 장애물 때문에 회전 위치가 보정되는 사례를 테스트에 남겼다.

## 하강·고정·하드 드롭의 책임

`try_step()`은 각 낙하 타일의 바로 아래 칸을 검사한다. 바닥이면 `StepError::OutOfBounds`, 고정 타일이 있으면 `Blocked`를 반환한다. 성공 계획을 적용하면 Y가 한 칸 증가한다.

`place_falling()`은 낙하 타일을 고정 타일로 바꾸는 별도 함수다. `hard_drop()`은 `try_step()`과 적용을 실패할 때까지 반복해 최종 낙하 위치로 옮기지만, 그 자체로 고정하거나 다음 블록을 생성하지 않는다. 고정 지연, 점수, 다음 블록, Hold 같은 게임 진행 정책은 상위 로직과 구분한다.

`hard_drop()`은 하강을 시도하기 전에 카운트를 증가시켜 마지막 실패 시도도 반환값에 포함한다. 하드 드롭 테스트에서는 최종 블록 배치를 비교했다.

## 여러 줄을 지울 때 인덱스가 어긋나지 않도록

줄 제거 대상은 한 행 전체가 `Placed`인 경우다. 낙하 타일이나 힌트는 줄 완성 개수에 포함하지 않는다. `try_line_clear()`가 위에서 아래로 수집한 행 인덱스를 반환하면, 적용 시에는 역순으로 행을 삭제한다.

```rust
pub fn apply_line_clear(&mut self, to_clear_lines: Vec<usize>) {
    for to_clear_line in to_clear_lines.iter().rev() {
        self.0.remove(*to_clear_line);
    }
    for _ in to_clear_lines {
        self.0.insert(0, vec![Tile::Empty; self.x_len()]);
    }
}
```

아래쪽 행부터 지우면 아직 지우지 않은 위쪽 행의 인덱스가 바뀌지 않는다. 삭제 개수만큼 맨 위에 빈 행을 추가해 높이를 유지한다. 정렬되지 않았거나 중복된 인덱스를 외부에서 주는 API로 설계한 것이 아니라, 코어가 판정한 결과를 이어서 적용하는 흐름이다.

`line_clear3`은 2번·4번 행을 동시에 제거하고, 1번 행의 타일이 3번 행으로, 3번 행의 타일이 4번 행으로 내려온 결과를 비교한다. `line_clear2`는 한 칸이 비어 있으면 제거 후에도 보드가 그대로인지 확인한다.

## 착지 힌트와 상단 판정

착지 힌트는 현재 낙하 타일을 보관한 뒤 하드 드롭으로 도착 위치를 구하고, 그 위치에 `Hint`를 남긴 다음 원래 낙하 타일을 복원하는 방식이다. 별도 복제 보드를 계산하는 순수 조회 함수는 아니다. 힌트 제거는 보드를 순회해 `Hint`만 비운다.

`show_hint`·`remove_hint` 테스트는 원래 낙하 블록이 유지되는지와 바닥 힌트가 생성·제거되는지를 보드 문자열로 비교한다. 같은 착지 계산을 재사용하면서도 힌트가 이동 충돌을 막지 않도록 타일 상태를 구분했다.

`has_placed_above(y)`는 0번 행부터 `y` 직전 행까지 고정 타일이 있는지 확인한다. `game_over` 테스트는 기준이 2일 때 1번 행의 고정 타일은 true, 2번 행부터 있는 경우는 false인지 검사한다.

쓰레기 줄 삽입도 코어에 있다. 맨 위 행을 제거하고 구멍 하나가 있는 10열의 고정 타일 행을 아래에 넣는다. 낙하 블록 아래의 충돌 여부에 따라 낙하 블록을 한 칸 올리거나 기존 좌표에 복원하며, 최상단에 낙하 타일이 있으면 실패한다. 해당 테스트들은 출력 확인 중심이므로 검증 수준을 다른 단위 테스트와 구분한다.

## 문자열을 기대값으로 사용하는 테스트

`Display` 구현은 빈 칸을 `.`, 고정 타일을 `P`, 힌트를 `H`, 낙하 블록을 종류 문자로 출력한다. 행·열 번호를 함께 표시해 기대 결과를 코드 안에서 읽을 수 있도록 했다. 다음은 오른쪽 이동 테스트의 결과를 축약한 예시다.

```text
이동 전       이동 후
...ZZ.....    ....ZZ....
....ZZ....    .....ZZ...
```

실제 테스트는 이 두 행만 보는 것이 아니라 보드 전체 문자열을 비교한다. 실패해야 하는 상황은 `matches!`로 `MoveError::Blocked`, `MoveError::OutOfBounds`, `StepError` 등을 확인한다. 기본 회전 테스트에서는 문자열뿐 아니라 회전 상태도 비교한다.

`src/tests.rs`에 `#[test]` 함수 47개를 작성했다. 활성 코드 기준으로 40개는 assertion을 사용하고, 7개는 출력·실행 확인용이다.

| 검증 영역 | assertion이 있는 테스트 함수 수 |
| --- | ---: |
| 일곱 종류 생성 | 7 |
| 일곱 종류 기본 오른쪽 회전 | 7 |
| J·L·T 벽 킥 배치 | 11 |
| 좌우 이동·장애물·경계 | 4 |
| 하강·바닥·장애물 | 3 |
| 줄 제거 | 3 |
| 하드 드롭 최종 위치 | 1 |
| 힌트 생성·제거 | 2 |
| 상단 고정 타일 판정·낙하 타일 제거 | 2 |

assertion이 없는 함수는 `spawn_t_2`, `test_t`, `testlen`, `testspawn`, `test_garbage1`·`2`·`3`이다. 일부 `unwrap()`이 실패하면 테스트가 실패할 수는 있지만, 기대 상태·반환값의 정확성을 자동 비교하는 테스트와는 다르다.

게임 화면을 직접 조작하는 확인에만 의존하지 않고, 작은 보드에 재현 조건과 기대 배치를 기록했다. 특히 회전 보정과 여러 줄 제거처럼 수정 시 다른 배치에 영향을 줄 수 있는 규칙을 반복 확인할 기반을 만들었다.

테스트는 `back`에서 `cargo test -p tetris-lib`로 실행한다. `cargo test -p tetris-lib --features wasm`으로 WASM 기능을 포함한 네이티브 테스트도 실행할 수 있다.
