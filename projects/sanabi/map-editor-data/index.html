맵 편집 도구와 배치 데이터 저장·불러오기

좌표 수정 대신 화면에서 맵을 구성하기​

타일과 충돌 지형, 소품의 위치를 C++ 코드에 하나씩 작성하면 맵을 조정할 때마다 배치 코드를 수정해야 한다. 이를 줄이기 위해 게임과 같은 Win32 실행 환경에 맵 편집 씬을 구성했다. GUI에서 종류를 선택하고 마우스로 배치한 뒤 파일로 저장하며, 게임 씬에서 같은 데이터를 읽어 사용한다.

핵심은 이미지와 충돌을 한 덩어리로 취급하지 않는 것이다. 보이는 타일·소품과 실제 이동을 제한하는 선·사각 영역을 따로 배치한다. 사슬을 걸 수 있는 지형과 피해 영역도 외형 이미지와 독립적으로 설정한다.

기존 Win32·GDI 프레임워크에 편집 씬, 입력 처리, 배치 마커와 저장·불러오기를 추가했다.

Aseprite와 자체 편집기의 역할 구분​

원작 에셋은 AssetStudio로 추출했다. 추출한 에셋을 준비하는 과정과 게임의 동작·맵 편집 기능을 구현하는 작업을 나누어 진행했다.

프로젝트의 스프라이트 작업에는 Aseprite를 사용했다. Aseprite는 이미지·스프라이트를 다루는 외부 도구이고, 직접 구현한 맵 편집기는 게임 안에서 타일·충돌 영역·객체의 위치와 종류를 배치하는 도구다.

런타임에서는 비트맵 리소스와 프레임 정보를 이용해 이미지를 출력한다. 맵 파일은 이미지 픽셀 자체가 아니라 어떤 리소스의 어느 프레임을 어디에 표시할지 저장한다. 따라서 이미지 준비와 맵 배치 데이터의 수정은 서로 다른 작업이다.

AssetStudio는 원작 에셋 추출, Aseprite는 스프라이트 작업, 자체 편집기는 게임 내 배치에 사용했다. 런타임이 .aseprite 원본을 직접 읽는 구조는 아니다.

편집 씬의 책임 분리​

구성 요소맡은 역할
CSceneTileEdit편집 영역·GUI 구성과 화면 스크롤
CUIObjTileEditDbgPanel타일·충돌 종류·배치 항목·파일 선택, 저장·불러오기 버튼
CObjEditArea편집 영역의 마우스 이벤트, 격자 표시와 입력 위치 계산
CEditMgr현재 편집 모드·종류 보관, 객체 생성·삭제 예약, 파일 입출력
CObjThings편집용 배치 마커의 이동·삭제와 실제 객체 전환

GUI는 자체 UI 객체와 버튼 콜백으로 구성한다. 선택한 값은 CEditMgr에 전달하고, 화면 입력은 CObjEditArea를 거쳐 해당 편집 함수로 연결한다. 파일 이름 역시 자유 입력 경로가 아니라 FILE_NAME_ID와 이름 변환 함수에 등록된 항목을 선택하는 방식이다.

타일과 충돌 지형 편집​

타일 격자 크기는 TILECX, TILECY에 정의된 16×16이다. 편집 영역은 마우스의 화면 좌표를 격자 단위로 맞추고, 편집 매니저는 스크롤을 빼서 월드 배치 좌표로 변환한다.

타일을 왼쪽 버튼으로 배치하면 같은 격자 위치의 기존 타일을 찾아 삭제 예약하고 새 타일을 등록한다. 선택한 TILE_ID는 프레임 키와 이미지 내 프레임 위치로 변환된다. 누르는 동안 반복 배치·삭제하는 입력도 연결해 한 칸씩 클릭하지 않고 연속으로 편집할 수 있도록 했다.

충돌선과 사각 영역은 두 번 클릭해 구성한다. 선은 두 끝점과 중심을, 사각형은 두 점 사이의 중심과 폭·높이를 계산한다. 선에는 등반 가능 여부를, 사각형에는 등반 가능·불가능·피해 영역 종류를 저장한다. 사슬 부착과 지형 판정에서 이 종류를 사용할 수 있도록 편집 데이터에 의미를 부여한 것이다.

배치 마커와 실제 객체를 분리하기​

플레이어 시작 위치, 부유 폭탄, 플랫폼, 소품 등은 편집 중 CObjThings로 표현한다. 마커에는 종류를 나타내는 THINGS_ID와 위치가 있고, 종류 이름을 보여주는 자식 텍스트를 붙인다.

왼쪽 버튼으로 마커를 잡아 이동하고, 오른쪽 버튼으로 확인 후 마커와 자식을 삭제 예약한다. 이동 중에는 마우스 이벤트 전파를 막아 편집 영역의 배치 입력과 겹치지 않게 한다. 마커 이동에는 격자 셀 중심, 격자 경계, 자유 이동 방식이 있다. 코드의 EMPM_TILE_ORIGIN은 격자 좌표에 반 칸을 더하고, EMPM_TILE_SIDE는 격자 좌표 자체를 사용한다.

게임 씬에서는 파일을 읽은 뒤 ChangeReal()을 호출한다. 이 함수는 마커의 종류를 switch로 분기해 실제 객체를 생성하고 위치를 전달한 뒤, 편집용 마커를 자식과 함께 삭제 예약한다.

Plain Text
GUI에서 마커 배치 → THINGS_ID와 위치 저장
→ 게임 씬에서 마커 복원 → ChangeReal()
→ 실제 객체 등록 → 편집용 마커 삭제 예약

실제 생성 분기가 있는 예는 플레이어, 부유 폭탄, 넉백 플랫폼, 챕터 버튼, 숲 소품 스프라이트다. 다만 일반 몬스터 A·B·G와 화조 보스 위치 항목은 현재 switch의 내용이 비어 있다. 메뉴나 enum에 항목이 존재한다고 모든 타입이 게임 객체로 생성되는 것은 아니다.

또한 이 배치 데이터가 씬 초기화 전체를 대체하지는 않는다. 예를 들어 튜토리얼 씬은 마커를 전환한 뒤 별도로 플레이어를 생성하는 코드가 있다. 데이터의 플레이어 마커와 코드 생성이 중복되지 않도록 씬별 책임을 맞춰야 한다.

바이너리 파일 구성과 복원​

Save_File()은 ../Data/ 아래의 선택한 파일을 CreateFile로 열고 WriteFile로 기록한다. 저장 순서는 버전 값, 네 종류의 개수, 종류별 레코드다.

구간기록하는 데이터
헤더버전 0, 선·사각형·타일·배치 마커의 개수
충돌선INFO, LINE, 옵션 정수
충돌 사각형INFO, 옵션 정수
타일INFO, FRAME, FRAME_KEY_ID, 옵션 정수
배치 마커INFO, THINGS_ID

Load_File()은 같은 순서로 읽어 종류별 객체를 만들고 CObjMgr의 해당 목록에 등록한다. 선의 끝점·옵션, 사각형의 위치·크기·옵션, 타일의 위치·프레임·리소스 키, 마커의 종류·위치를 복원한다. 타일은 초기화된 고정 크기를 사용하며 저장된 INFO의 크기를 모두 적용하는 방식은 아니다.

읽기가 끝나면 파일을 닫고 전달받은 콜백을 즉시 호출한다. 편집 GUI에서는 빈 콜백으로 마커를 유지하고, 튜토리얼·몬스터 씬에서는 마커 목록을 순회하며 ChangeReal()을 호출한다. 비동기 로딩이나 다음 프레임 완료 통지가 아니라 동기 파일 읽기 후의 후처리다.

불러오기 함수 자체는 기존 맵을 지우지 않고 객체를 추가한다. GUI의 별도 비우기 기능과 구분되므로, 기존 배치 위에 반복해서 불러오면 중복될 수 있다.

구현 결과​

이 도구로 맵의 시각 요소, 이동 가능한 지형, 배치 위치를 화면에서 함께 조정하고 저장할 수 있도록 했다. 편집용 마커와 실제 객체를 나눈 덕분에 편집 중 전투 로직을 실행하지 않고도 위치를 지정하고, 게임 씬에서 필요한 타입으로 바꾸는 흐름을 만들었다.

다만 파일은 구조체와 enum의 메모리를 sizeof 단위로 기록하는 프로젝트 전용 형식이다. 멤버 배치·패딩·enum 값이 바뀌면 기존 데이터와 맞지 않을 수 있다. 버전 값은 읽지만 버전 검증이나 이전 포맷 변환에는 사용하지 않는다.
