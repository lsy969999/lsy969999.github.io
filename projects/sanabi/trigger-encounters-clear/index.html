트리거 기반 전투 구간과 클리어 흐름

개별 적을 플레이 구간으로 연결하기​

적의 이동·공격·처형 동작만으로는 하나의 전투 장면이 완성되지 않는다. 플레이어가 어디까지 이동했을 때 어떤 적이 등장하고, 어느 지점에서 다음 진행으로 넘어가는지를 함께 구성해야 했다. 이를 위해 CSceneMonster에 세 개의 전투 구간 트리거와 별도의 클리어 트리거를 배치했다.

각 전투 구간은 진입 시 준비된 적 집단을 한 번 생성한다. 추가로 감시 드론을 일정 간격으로 보충해 이동 중에도 주변에 적이 등장하도록 했다. 개별 적의 처형·폭탄 상호작용은 사슬 처형과 부유 폭탄 문서와 구분하고, 여기서는 등장 시점과 장면 진행의 연결을 다룬다.

커밋에는 전투방 웨이브라는 표현을 사용했지만, 현재 구현은 영역별 일괄 생성과 별도 주기 보충이다. 앞 웨이브의 전멸을 기다렸다가 다음 웨이브를 시작하는 범용 Wave Manager는 아니다.

반복 감지와 한 번 실행 정책의 분리​

CObjTrigger는 타깃 객체와 자신의 사각형을 IntersectRect()로 검사한다. 겹쳐 있으면 등록된 function<void()> 콜백을 Update마다 호출한다. PhysX 같은 외부 물리 라이브러리의 트리거 이벤트가 아니라 Win32 RECT 기반 검사다.

현재 제공하는 함수는 Set_TriggerLoopCallback()이다. Enter·Exit용 멤버는 주석으로만 남아 있고, 이전 프레임의 겹침 상태를 비교하는 진입·이탈 이벤트는 구현되어 있지 않다. 따라서 한 번만 적을 생성하는 정책은 트리거 자체가 아니라 씬이 갖는다.

씬은 m_bRoom1Enter, m_bRoom2Enter, m_bRoom3Enter를 초기화할 때 false로 설정한다. 해당 콜백에서 아직 진입하지 않았다면 먼저 true로 바꾸고 적을 생성한다. 영역 안에 머물거나 나갔다 다시 들어와도 같은 씬 인스턴스에서는 생성이 반복되지 않는다.

트리거에는 적 종류나 전투 규칙을 넣지 않고, 씬의 콜백이 플레이어와 진행 상태를 참조하도록 했다. 다만 트리거는 타깃 raw pointer를, 콜백은 씬과 플레이어 참조를 사용하므로 수명이 자동 보장되는 이벤트 시스템은 아니다.

세 구간의 적 조합​

세 전투 트리거의 크기는 모두 300×300이다. 좌표와 적 조합은 CSceneMonster::Initialize()에 직접 작성되어 있다. 각 적을 생성·초기화하고, 플레이어를 타깃으로 지정한 뒤 위치를 설정해 OBJ_MONSTER에 등록한다.

표는 현재 활성 코드 기준이다. 3구간의 디펜더 두 개 생성 블록은 주석 처리되어 있어 합계에 포함하지 않았다. 씬에 미리 배치된 더미 계열 적이나 이후 보충되는 감시 드론도 이 표와 별개다.

1구간은 네 트루퍼와 다른 높이의 디펜더를 배치한다. 2구간은 디펜더 한 개와 트루퍼 두 개의 조합을 서로 다른 위치에 세 묶음으로 구성한다. 3구간은 트루퍼와 양쪽에 세 개씩 배치한 워리어, 별도 위치의 디펜더를 조합한다. 종류·수량뿐 아니라 위치와 높이도 달리한 구성이다.

세 구간은 독립적인 플래그만 확인한다. 2구간이 1구간의 완료를, 3구간이 2구간의 전멸을 기다리는 조건은 없다. 생성 역시 각 콜백 한 번 안에서 연속 수행되며, 적마다 시간차를 두거나 별도 큐에서 분산 생성하지 않는다.

맵의 타일·충돌·배치 마커는 Load_File(FNI_MONSTER, ...)로 불러오지만, 이 전투 구간의 트리거와 적 조합까지 파일에서 읽는 것은 아니다. 맵 편집 도구의 데이터 배치와 C++의 진행 로직을 함께 사용하는 형태다.

감시 드론은 10초마다 한 개씩 보충한다​

씬 초기화 시 현재 Tick을 m_dwSurveyDronIntervalTime에 저장한다. 이후 씬 Update에서 CTimeMgr::Delay(..., 10000, ...)로 보충 시점을 확인한다. 메인 루프에서 검사하는 방식이며 별도 스레드 작업은 아니다.

보충 시점에는 플레이어 목록에서 첫 CObjPlayer2를 찾고, 몬스터 목록을 순회하며 감시 드론 타입의 개수를 센다. 그 수가 3보다 작으면 한 개만 생성한다. 드론이 없는 상태에서 한 번에 세 개를 채우는 방식이 아니다.

생성 위치는 플레이어를 기준으로 X에 -10099, Y에 0-99의 오프셋을 준다. 화면 좌표계에서 플레이어 주변 또는 위쪽에 나타나는 사각 범위이며, 원형 분포나 지형 회피·시야 밖 생성 검사는 없다.

Delay()는 실행 후 기준 Tick을 현재 시각으로 바꾼다. 프레임이 지연되어 여러 주기를 놓쳐도 한 번에 누락된 횟수만큼 생성하지 않으며, 적 수가 충분해 생성하지 않은 경우에도 다음 검사까지 다시 간격을 기다린다. 따라서 정확한 주기 누적 스케줄러보다 단순한 보충 간격 제어에 가깝다.

감시 드론 수는 타입 캐스팅 결과로 계산하며, 별도의 전투 구역 소속이나 살아 있는 적 전용 카운터를 사용하지 않는다. 이 제한은 이 보충 경로가 적용하는 조건이지, 프로젝트 전체에서 드론이 절대 세 개를 넘지 못하게 하는 전역 제한은 아니다.

클리어는 적 전멸이 아니라 도착 지점으로 판정한다​

별도의 100×100 클리어 트리거에 닿으면 m_bClearTriggerEnter를 설정하고 m_bMonsterClear를 true로 바꾼다. 이 콜백에는 남은 적 수, 각 방의 완료 여부, 처형 횟수 검사가 없다. 따라서 현재 장면의 완료 조건은 전투를 모두 끝냈는지가 아니라 지정 영역에 도달했는지다.

완료 상태에서 씬 Update는 CGameStorageMgr::Set_Chap2Clear(true)를 호출하고 게이트 닫기를 요청한다. 이어 메뉴 전환을 1000ms 뒤에, 게이트 열기를 1500ms 뒤에 예약한다. 이 시간은 게이트 애니메이션 종료 콜백이 아니라 타이머 설정값이다.

CObjGateSprite는 화면 크기의 스프라이트다. 여기의 게이트는 전투방 출입을 물리적으로 차단하는 문이 아니라 화면을 덮는 전환 연출이며, 열기·닫기에 효과음을 연결한다. 씬 해제에서 OBJ_GATE를 삭제 대상에서 제외해 메뉴로 넘어가는 동안에도 사용할 수 있게 한다.

챕터 완료 정보는 싱글턴의 bool로 유지한다. 챕터 버튼은 이 값을 읽어 다음 챕터의 잠금·선택 상태에 반영한다. 파일 저장이나 다음 실행에서 이어 하기까지 제공하는 영구 세이브 시스템은 아니다.

현재 코드에서 주의할 진행·수명 문제​

한 번 실행 플래그는 적 생성 콜백과 클리어 영역 콜백에는 있지만, 클리어 이후의 씬 전환 예약 분기에는 없다. m_bMonsterClear가 true인 동안 매 Update에서 타이머 두 개를 다시 등록한다. 씬이 바뀌기 전까지 여러 메뉴 전환·게이트 열기 작업이 쌓일 수 있다. 게이트 내부의 중복 닫기 방어가 타이머의 중복 등록까지 막지는 않는다.

등록한 타이머 ID도 씬에서 보관·취소하지 않는다. 따라서 전환 요청은 한 번만 발행하도록 상태를 분리하고, 씬 종료 시 취소할 작업과 다음 씬까지 유지할 전환 작업의 소유 주체를 명확히 하는 보강이 필요하다. 게이트 접근의 front()와 캐스팅 결과도 유효성을 확인하지 않아 객체가 반드시 존재한다는 전제에 의존한다.

트리거는 자신의 Update_Rect()를 호출하기 전에 겹침을 검사한다. 초기 위치가 처음 사각형에 반영되는 시점이나 타깃의 갱신 순서에 따라 이전 사각형을 사용할 수 있다. 공통 Render에서는 스크롤을 RECT에 더하므로 두 대상의 좌표 기준도 확인해야 한다. 판정 전에 월드 사각형을 확정하고 렌더용 좌표와 분리하는 방향이 적합하다.

또한 씬 해제는 마우스·게이트를 제외한 객체를 삭제 예약하고, 실제 해제는 이후 객체 매니저 갱신에 맡긴다. 콜백이 씬을 캡처하는 현재 방식에서는 이전 씬이 사라진 뒤 남아 있는 트리거가 실행되지 않도록 순서와 수명을 보장해야 한다. 현재 구현을 안전한 범용 이벤트 버스로 소개하지 않는 이유다.

결과와 확인 범위​

이 작업에서는 이미 구현한 적을 영역별로 조합하고, 플레이어의 이동에 맞춰 등장시킨 뒤 도착 판정과 챕터 전환까지 연결했다. 단일 적 테스트를 실제 진행 가능한 장면으로 구성한 점이 핵심이다. 시간차 웨이브·전멸 판정·범용 데이터 기반 Encounter 시스템은 후속 확장 범위로 구분한다.

시연은 구간 진입 시 생성, 재진입 시 중복 생성 방지, 드론 한 개씩 보충, 도착 영역에서 게이트·메뉴 전환 순서가 적합하다. 적을 남겨 둔 채 도착한 경우, 낮은 프레임률, 트리거 내 플레이어 제거, 클리어 후 예약 작업 개수는 별도 검증 항목이다. 이번 문서는 소스·Git 분석 결과이며 게임 코드를 수정하거나 실행 검증을 완료했다는 의미는 아니다.
