플레이어 이동·액션과 몸체·팔 애니메이션 전환

이동 결과와 보이는 동작을 연결​

산나비 플레이어는 달리기와 점프뿐 아니라 벽 등반, 천장 이동, 사슬팔, 피격 후 탈출을 오간다. 같은 방향키나 Space라도 현재 붙어 있는 지형과 전투 상태에 따라 다른 동작으로 해석해야 했다. 화면에서도 달리기 시작·정지, 착지 후 달리기, 벽 부착 같은 연결 동작을 구분할 필요가 있었다.

기존 Player를 CObjPlayer2와 몸체·팔 전용 스프라이트로 재구성했다. 이동·충돌 분기에 맞춰 각 파트의 애니메이션을 전환한다.

사슬팔 결속·스윙의 수식과 길이 보정은 사슬팔 이동 문서에서 설명한다. 여기서는 나머지 이동과 표현의 연결을 다룬다.

프레임마다 입력 상태를 한 번 계산​

CMainGame::Update()는 Tick 갱신 후 CKeyMgr2::Update()를 호출하고 씬을 갱신한다. 입력 매니저는 키별 이전 눌림 상태와 GetAsyncKeyState() 결과를 비교해 Down·Pressing·Up 배열을 만든다. 조회 함수는 이 배열을 읽으며, 조회 자체가 입력 상태를 소비하지 않는다.

C++
// 실제 입력 갱신 분기를 요약한 의사 코드
down = !previousPressed && currentPressed;
up = previousPressed && !currentPressed;
pressing = currentPressed;

일반 이동 분기에서 A·D의 Down은 달리기 시작 애니메이션, Pressing은 위치 이동, Up은 달리기 정지 애니메이션에 사용한다. 여러 객체가 같은 프레임의 입력을 조회해도 같은 상태를 읽을 수 있도록 구성한 것이다.

다만 왼쪽 벽 충돌의 한 경로에는 이전 CKeyMgr 조회가 남아 있다. 프로젝트 전체 입력이 새 매니저로 완전히 통일되었다고 설명하지는 않는다.

이동 모드의 우선순위​

현재 로직은 독립적인 State 클래스나 전환 테이블보다 Key_Input()의 if·else 분기와 bool 플래그로 동작한다. 헤더에 STATE enum이 있어도 실제 주요 제어는 다음 분기 순서다.

우선순위조건입력 해석
1좌우 벽 등반W·S 등반, Space 벽에서 도약
2천장 부착A·D 수평 이동, Space로 놓고 떨어짐
3사슬팔 결속A·D 스윙 조절, Space로 당겨 이동
4처형 대상 포획WASD 이동과 대상 위치 동기화
5피격 상태허용 시간 동안 방향키·Space로 탈출 대시
6일반 상태A·D 이동, Space 점프

여러 플래그가 동시에 켜졌을 때 앞선 분기가 먼저 선택된다. 이것은 상태 충돌을 자동 방지하는 구조가 아니라, 분기 우선순위로 입력을 해석하는 방식이다. 대시 테스트용 V 입력은 이 분기 바깥에 남아 있다.

일반 이동·점프·착지​

플레이어의 초기 판정 크기는 20×40, 일반 이동량은 Update당 4다. 공통 Move(angle, length)에서 X에는 코사인, Y에는 음의 사인을 사용하므로 90도는 화면 위쪽이다.

일반 Space 입력은 m_bJump가 꺼져 있을 때 JumpRoutine(90, 21)을 호출한다. 지상 여부를 직접 검사하는 조건과는 다르다. JumpRoutine()은 점프 방향·세기를 설정하고 중력·점프 누적 시간을 초기화하며 접지·벽 등반 상태를 해제한다. 몸체·팔의 점프 시작 상태도 함께 지정한다.

이동 계산은 Tick 차이로 누적한 시간을 사용하지만 표준적인 속도 적분과는 다르다. Apply_Jump()는 점프 세기와 누적 시간의 곱을, Apply_Gravity()는 누적 시간 제곱에 비례하는 값을 매 Update의 이동량으로 다시 더한다. 각각의 누적 시간은 1.5초로 제한한다. 일반 이동과 마찬가지로 프레임률에 따라 궤적이 달라질 수 있다.

바닥 충돌에서는 겹침 깊이만큼 위로 밀어내고 중력·점프 누적 시간을 초기화한다. 새 착지로 판단되면 입력에 따라 애니메이션을 선택한다.

  • A·D를 누른 상태: LAND2RUN 후 달리기로 연결
  • 방향 입력 없음: 마지막 좌우 방향의 LANDING 후 대기로 연결

착지에서 이동을 다시 시작하는 모습과 제자리로 내려앉는 모습을 구분한 구현이다. 위치는 게임 로직이 계산하고 스프라이트가 따라가므로 Root Motion 방식은 아니다.

벽·천장에서는 같은 입력을 다르게 해석​

지형 충돌은 방향과 겹침 깊이를 전달한다. 플레이어는 먼저 위치를 보정한 뒤 등반 가능한 지형에서 벽 쪽 입력을 확인해 벽 등반을 시작한다. 등반 중에는 충돌 경로에서 중력·점프 누적을 초기화하고 W·S로 위아래 이동한다.

W·S를 누르기 시작하면 등반 애니메이션을 선택하고, 놓으면 벽 슬라이딩 이름의 애니메이션 상태로 전환한다. 이 애니메이션 이름만으로 일정한 하강 속도를 별도로 구현했다고 해석해서는 안 된다. Space는 붙어 있는 면에 따라 JumpRoutine(100, 20) 또는 JumpRoutine(80, 20)으로 이어진다.

벽의 위·아래 경계를 넘으면 탈출 플래그를 세우고 이후 Update에서 위쪽 도약 또는 아래쪽 이동을 시작한다. 벽 접촉·경계 검사와 입력 분기가 함께 상태를 바꾸는 방식이다.

천장에서는 A·D를 유지하면 수평으로 이동한다. 입력 시작·종료는 팔의 천장 이동 시작·종료 상태에 반영한다. 저장해 둔 천장 사각형의 좌우 경계를 플레이어 중심이 벗어나거나 Space를 누르면 천장 부착을 해제하고 중력을 다시 켠다. 이 경로는 이름이 CEILINGSTICKJUMP인 애니메이션을 사용하지만 새로운 점프 속도를 주는 대신 낙하로 전환한다.

피격 반동에서 8방향 탈출로​

Damage()는 피해 재수신 제한 카운터가 끝났을 때 피격 상태와 탈출 대시 허용 카운터를 각각 60으로 설정한다. 카운터는 Update마다 감소한다. 60초가 아니라 프레임 수에 가까운 단위다.

반동 방향은 충돌 입사각 대신 마지막으로 바라보던 좌우 방향에 따라 정한다. 왼쪽을 향하던 경우 75도, 오른쪽이면 105도로 JumpRoutine(..., 15)를 호출하고 몸체·팔의 피격 상태를 선택한다.

피격 입력 분기에 도달한 상태에서 허용 카운터가 남아 있으면 Space와 방향키 조합으로 대시를 시작한다. 대각 조합을 먼저 검사한 뒤 상하좌우를 검사해 8방향 중 하나를 선택하고, 허용 카운터를 0으로 만들어 해당 기회를 소비한다.

대시는 선택 방향으로 Update당 30씩 3회 이동하며 점프·중력 누적을 초기화한다. 일반 상시 대시와 구분해야 한다. 코드에는 V키의 2회 테스트 대시와 처형 후 4회 대시도 별도 진입 경로로 존재한다.

몸체와 팔의 애니메이션 분리​

플레이어는 CObjPlayer2SNBSprite와 CObjPlayer2SNBARMSprite를 각각 생성하고 부모로 자신을 지정한다. 둘 다 같은 로컬 오프셋을 사용하지만 독립적인 프레임 정보와 애니메이션 상태를 갖는다. 충돌 판정 크기와 화면에 그릴 몸체 프레임 크기 120×61도 구분한다.

부모의 m_eAniStateSNB와 m_eAniStateSNBARM은 요청과 진행 상태를 겸한다. 플레이어가 시작 상태를 지정하면, 자식 스프라이트의 AniStateUpdate()가 이를 읽고 클립을 선택한 다음 부모의 상태를 다시 ING·END로 바꾼다. 단방향 이벤트나 독립 애니메이션 컨트롤러보다는 부모와 자식이 상태를 공유하는 구조다.

달리기 시작을 예로 들면 다음과 같다.

Plain Text
방향키 Down → RUNSTART_START
스프라이트 Update → 클립 선택, RUNSTART_ING
마지막 프레임 확인 → RUNSTART_END
다음 상태 처리 → RUNNING_START → RUNNING_ING 반복
방향키 Up → RUNSTOP_START → 완료 후 IDLE_START

각 스프라이트는 Update에서 상태별 프레임 진행을 처리하고, Late_Update의 Motion_Change()에서 클립 ID가 바뀌었는지 확인해 프레임 정보를 초기화한다. 비트맵의 열은 프레임 번호, 행은 모션 번호로 선택해 출력한다.

기본 Move_Frame()는 Tick 기준 재생 간격이 지났을 때 한 프레임을 진행하고 마지막을 넘으면 0으로 돌아간다. 달리기 시작·정지·착지 같은 일회성 동작은 별도 switch 분기에서 마지막 프레임을 감지해 다음 상태를 선택한다. 모든 END 항목에 자동 전환이 구현된 것은 아니며, 클립 간 블렌딩이나 크로스페이드는 사용하지 않는다.

구현 결과​

입력의 Down·Pressing·Up, 지형 충돌 방향, 애니메이션의 마지막 프레임을 각각 다른 전환 근거로 사용했다. 그 결과 단순한 이동·정지 두 상태를 넘어 달리기 시작·착지 후 달리기·벽 등반·천장 이동·피격 탈출을 구분해 표현할 수 있었다.
