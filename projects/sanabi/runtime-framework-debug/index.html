게임플레이 제작을 위한 프레임워크와 디버그 도구 보강

콘텐츠를 반복해서 확인할 수 있는 실행 환경​

사슬 이동, 보스전, 맵 배치를 구현하면서 개별 기능만큼 중요한 것은 현재 생성된 객체와 화면 위치를 확인하고, 필요한 장면을 빠르게 열어보는 환경이었다. 기존 객체·씬 관리 구조를 활용하면서 공통 스크롤 처리와 화면 밖 렌더 생략을 보강하고, 입력 상태 갱신 및 테스트 장면을 연결했다.

기존 객체·씬·비트맵 관리 구조를 기반으로 공통 렌더 처리, 입력 매니저, 스크롤 패널과 테스트 씬을 추가·보강했다.

객체 분류와 부모 관계는 별도로 관리한다​

CObjMgr는 OBJID별 list<CObj*>에 객체를 보관한다. 플레이어·몬스터·UI 같은 분류와 부모·자식 관계는 서로 다른 기준이다. 자식 역시 매니저의 목록에 개별 등록하고, 객체는 m_pParent로 부모를 참조한다.

부모별 자식 목록은 별도의 계층 맵으로 구성한다. 객체 추가와 Set_Parent() 호출, 실제 삭제 이후에 갱신하고, 특정 객체의 하위 집합은 큐 방식의 너비 우선 순회로 수집한다. 시작 객체도 결과에 포함하므로 패널 전체나 보스의 부위 집합에 일괄 처리를 적용할 수 있다.

위치 계산은 부모들의 X·Y를 따라 올라가며 누적하는 방식이다. UI 패널 아래 버튼·텍스트, 캐릭터 아래 부위 스프라이트를 상대 위치로 구성하는 데 사용한다. 회전·스케일 행렬을 합성하는 일반적인 Transform 계층은 아니다.

렌더 순서는 부모 없는 객체를 기준으로 결정한다. 각 루트의 RDO에 루트와 하위 객체를 묶고, 렌더 그룹 순서대로 출력한다. 따라서 자식의 개별 RDO로 루트와 다른 그룹에 보내는 구조가 아니며, 계층 내부 순서도 깊이 우선이 아니라 너비 우선 순회 결과다. 이 렌더 순서 기반 자체는 초기 코드에 있던 기능으로 구분한다.

삭제·비활성화의 실제 처리 시점​

Set_Dead_Cascade()는 계층에 포함된 객체들에 삭제 플래그를 설정한다. 부모의 소멸자가 자식을 직접 소유하고 해제하는 방식이 아니다. 이후 매니저 Update에서 대상들을 목록에서 분리하고, 전체 객체 갱신 순회가 끝난 뒤 수집한 포인터를 해제한다.

활성 객체는 자신의 Update()가 OBJ_DEAD를 반환해야 수집된다. 비활성 객체는 Update를 호출하지 않으므로 매니저가 삭제 플래그를 직접 검사한다. 이 처리는 Update 내부의 지연 삭제이며, 별도 FrameEnd 단계에서 처리하는 방식은 아니다.

Set_Active_Cascade(false)는 현재 하위 객체들의 활성 값을 함께 바꾼다. 비활성 객체는 Update·Late_Update·Render에서 제외되지만, 일반 Set_Active(false)는 자식에게 자동 전파되지 않는다. Visible은 렌더 여부만 제어한다. 부모가 비활성이면 모든 자식이 암묵적으로 비활성화되는 시스템으로 이해하면 안 된다.

또한 등록은 즉시 목록에 추가된다. 별도 생성 요청 큐가 없어 Update 도중 생성한 객체가 어느 순회 구간에 들어가는지는 객체 분류와 현재 반복 위치에 영향을 받는다. 부모 순환 검사나 세대 번호를 가진 안전한 핸들 체계 역시 이 구조에 포함되어 있지 않다.

보강한 공통 렌더 처리: 스크롤과 화면 밖 제외​

객체 렌더링 구조를 정리하면서 CObjMgr::Render()에 공통 스크롤 적용과 화면 경계 검사를 추가했다. 월드 스크롤을 사용하는 객체만 Get_UseMainScroll()을 켜고, 화면에 고정된 UI는 별도로 유지할 수 있도록 했다.

현재 렌더 흐름은 다음과 같다.

Plain Text
루트 RDO별 계층 목록 구성
→ Active·Visible 확인
→ 대상 객체의 RECT에 메인 스크롤 적용
→ 화면 경계 밖인지 검사
→ 객체 Render 호출

오브젝트 사각형이 화면의 왼쪽·오른쪽·위·아래 중 한쪽으로 완전히 벗어나면 Render를 호출하지 않는다. 이는 2D 사각형 기반의 출력 생략이다. 공간 분할로 후보를 줄이는 컬링 시스템이 아니며, 화면 밖 객체도 일반 Update와 Late_Update는 계속 수행한다.

스크롤은 객체의 RECT에 적용하고 다음 갱신에서 Update_Rect()로 다시 계산한다.

입력을 프레임당 한 번 갱신하기​

f6cb9fd에서는 CKeyMgr2를 추가하고 CMainGame::Update()에서 씬 갱신 전에 키 상태를 계산하도록 연결했다. 이전 누름 상태와 현재 GetAsyncKeyState() 결과를 비교해 Down·Pressing·Up을 저장한다. 각 조회 함수는 저장된 결과만 반환한다.

같은 프레임에 플레이어와 디버그 단축키가 같은 키를 여러 번 조회해도, 조회 자체로 상태가 소비되거나 다시 계산되지 않는다. 게임플레이 쪽 적용은 플레이어 액션과 애니메이션 문서에서도 다룬다. 기존 CKeyMgr 호출이 일부 남아 있어 프로젝트의 모든 입력 경로가 완전히 교체된 것으로 설명하지는 않는다.

메인 갱신은 Tick 갱신, 키 상태 갱신, 씬 Update, 디버그 패널 단축키 처리 순서다. Late_Update와 Render는 현재 씬에 위임하며, 각 씬이 객체 매니저 갱신과 필요한 충돌 목록 조합을 호출한다. 따라서 충돌 대상 조합과 씬 정리 정책은 여전히 각 씬에 명시되어 있다.

런타임에서 확인하는 패널​

패널은 외부 ImGui가 아니라 프로젝트의 CUIObjPanel·버튼·텍스트 객체로 구성한다. F1~F5는 기존 창을 토글하는 것이 아니라 패널 인스턴스를 새로 생성하므로 반복해서 누르면 여러 개가 생길 수 있다.

단축키현재 동작구현 범위 구분
F1OBJID별 개수 → 객체 목록 → 선택 객체의 계층 이름 확인초기 코드의 기본 패널 활용
F2등록된 씬을 선택해 전환기본 패널에 확장된 씬 목록 연결
F3비트맵 매니저의 등록 키 목록 확인초기 코드의 기본 패널 활용
F4스크롤 값 확인과 방향별 이동8c07478에서 추가한 스크롤 패널
F5타일·충돌 지형·배치 데이터 편집별도의 맵 편집 기능 확장

객체 목록 패널은 화면에 보이는 행 수와 스크롤 비율로 표시 구간을 계산한다. 버튼이 부족하면 추가하고 기존 행은 비활성화 후 재사용한다. 선택 객체는 Seq를 정보 패널에 전달하고, 패널 Update에서 Get_Obj_By_Seq()로 다시 조회한다. 찾지 못하면 정보 패널을 삭제 예약한다.

Seq 조회는 객체 목록 전체를 순회한다. 정보 패널은 계층과 디버그 이름을 보여주며, 임의 멤버 편집이나 비트맵 미리보기는 지원하지 않는다.

스크롤 패널은 방향 버튼에서 TILECX * 8, 즉 128 단위로 스크롤을 더하거나 뺀다. Set_ScrollX/Y()는 이름과 달리 절댓값 대입이 아니라 누적 이동이다. 맵 편집 자체의 내용은 맵 편집 도구 문서로 분리했다.

테스트 씬 확장과 전환의 경계​

씬은 SCENEID의 switch에서 해당 C++ 클래스를 생성한다. 보스, 몬스터 테스트, 엔딩 장면을 이 목록에 추가해 장면별 검증과 게임 진행에 연결했다.

현재 Scene_Change()는 이전 씬을 즉시 삭제하고 새 씬을 생성하지만, Initialize는 바로 호출하지 않는다. 전환 플래그 동안 Update·Late_Update를 건너뛰고 Render 단계에서 초기화한다. 특히 현재 코드는 새 씬의 Render를 Initialize보다 먼저 호출한다. 초기화 중 새 객체를 이전 갱신과 섞지 않으려는 의도와 별개로, 초기화 전 렌더를 모든 씬이 안전하게 처리한다는 보장은 없다.

씬 해제 시 객체 정리도 일괄 즉시 삭제가 아니다. 예를 들어 몬스터 씬은 BGM을 정지하고 마우스·게이트를 제외한 분류를 삭제 예약한 뒤 스크롤을 초기화한다. 실제 해제는 이후 객체 매니저 Update에 맡긴다. 이 때문에 전환 프레임의 이전 객체·새 객체·예약 타이머를 함께 살펴야 한다.

구현 결과​

게임플레이 제작에 필요한 공통 처리와 디버그 도구를 연결했다. 월드·UI의 스크롤 적용을 나누고, 화면 밖 출력 호출을 줄이며, 동일 프레임의 입력 결과를 공유하고, 테스트 씬과 편집 패널로 접근할 수 있게 했다.
