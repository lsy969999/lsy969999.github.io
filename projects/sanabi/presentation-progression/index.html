인트로·튜토리얼·엔딩 연출과 챕터 진행

개별 기능을 시작과 끝이 있는 게임으로 연결하기​

플레이어 이동과 전투 기능을 구현한 뒤, 로고에서 메뉴로 들어가고 챕터를 선택해 플레이한 다음 엔딩으로 이어지는 흐름을 구성했다. 장면마다 스프라이트·입력·진행 상태를 연결하고, 화면 게이트 연출로 씬 전환을 덮도록 했다.

핵심은 범용 컷신 편집기가 아니라 이미 구현한 씬·객체·프레임 재생·타이머를 활용한 C++ 시퀀스 구성이다. 사운드 호출 자체는 사운드 연동 문서, 씬 매니저의 내부 생명주기는 프레임워크 문서에 맡기고 여기서는 진행 조건을 설명한다.

Plain Text
로고 씬 — P키 → 순차 로고 → 챕터 메뉴
  ├─ 챕터 1: 튜토리얼 → 도착 판정 → 메뉴·챕터 2 해금
  ├─ 챕터 2: 몬스터 전투 → 도착 판정 → 메뉴·챕터 3 해금
  └─ 챕터 3: 화조 보스 → 격파 연출 완료 신호 → 마리 엔딩
                                                    └─ L키 → 메뉴

챕터 완료 후 바로 다음 챕터를 자동 시작하는 것이 아니라 메뉴로 돌아와 선택하게 한다. 진행 정보는 실행 중 메모리에 유지하며 파일 저장을 통한 이어 하기는 구현되어 있지 않다.

인트로: 타이머로 로고를 순차 교체​

CSceneLogo는 검은 배경을 출력하고 P키 입력을 받으면 인트로를 시작한다. NEOWIZ·WONDER POTION 로고는 프레임을 진행하는 스프라이트로, 한글 SANABI 로고는 프레임 진행을 켜지 않은 이미지로 구성한다. 이미지 자체를 새로 창작했다는 주장이 아니라 준비된 리소스의 재생·배치·전환 구현이다.

P키 입력 이후 설정 시간수행하는 작업
즉시인트로 효과음 요청, 첫 로고 등록
2500ms첫 로고 삭제 예약, 두 번째 로고 등록
5000ms두 번째 로고 삭제 예약, 한글 로고 등록
7500ms화면 게이트 등록, 추가 전환 타이머 등록
추가 1500ms 뒤메뉴로 전환하고 게이트 열기 요청

마지막 단계는 7500ms 콜백 안에서 다시 타이머를 등록하므로 정상적인 진행에서 시작 후 약 9초에 해당한다. 타이머는 프레임 갱신 중 검사되므로 실제 시각은 프레임 지연에 따라 달라질 수 있다. 로고 애니메이션 완료 이벤트에 맞춰 교체하는 방식은 아니다.

두 번째·세 번째 로고와 게이트는 처음 P키를 눌렀을 때 미리 생성하지만, 매니저에는 각 타이머 시점에 등록한다. 이 방식은 연출 순서를 간단히 표현하지만, 등록 전 객체의 소유권과 연출 취소 시 해제 책임을 별도로 보강해야 한다.

m_bStart를 true로 설정하는 코드는 있으나, P키 처리 조건에서 이 값을 검사하지 않는다. 따라서 인트로 진행 중 P키를 다시 누르면 새로운 객체와 타이머가 중복 생성될 수 있다. 재진입 방지나 스킵을 갖춘 완성형 시퀀스 플레이어로 설명하지 않는다.

챕터 메뉴: 배치 데이터와 진행 상태의 결합​

메뉴는 배경을 생성한 뒤 FNI_MENU 파일을 읽고, 배치 마커의 ChangeReal()을 호출해 챕터 버튼을 만든다. 위치 구성에는 맵 편집 데이터가 사용되고, 각 버튼의 선택 가능 여부와 이동할 씬은 C++ 로직으로 결정한다.

CObjGameUiChapterBtn의 옵션 0·1·2는 튜토리얼·몬스터 전투·화조 보스 씬에 대응한다. 마우스가 버튼 안에 있는지와 이전 챕터 완료 여부에 따라 선택·비선택·잠금 프레임 상태를 고른다.

버튼활성화 조건선택 시 목적지
챕터 1이전 챕터 조건 없음SC_TUTORIAL
챕터 2IsChap1Clear()SC_MONSTER
챕터 3IsChap2Clear()SC_BOSS

현재 진행 저장소의 완료 bool들은 모두 false로 시작한다. 마우스 위치 이벤트에서 잠금 상태를 갱신하고, 클릭 처리는 현재 상태가 LOCKED이면 반환한다. 클릭 시 저장소의 해금 조건을 다시 검증하는 방식이 아니라 UI 상태를 신뢰하므로 입력·상태 갱신 순서도 고려해야 한다.

선택한 버튼은 게이트 닫기를 요청하고 1000ms 뒤 목적지 씬 전환, 1500ms 뒤 게이트 열기를 예약한다. 선택 처리 후 마우스 이벤트 전파를 막고 선택음을 요청한다. 중복 클릭 전체를 막는 별도의 전환 중 플래그는 없다.

튜토리얼: 월드에 놓인 조작 예시​

CObjTutoAni는 크기 156×157의 스프라이트 시트에서 옵션에 해당하는 프레임 구간을 선택한다. 옵션은 Initialize 전에 지정하고, Update에서 프레임을 진행한다.

옵션선택하는 안내 동작
0천장 부착
1점프
2벽 점프
3벽 상하 이동
4사슬 감기
5스윙 대시
6사슬 감기 변형

이는 플레이어 조작을 단계별로 판정하는 튜토리얼 미션 시스템이 아니라, 동작 예시를 재생하는 안내 객체다. 특정 입력을 성공했는지 검사하거나 성공 후 다음 안내로 자동 전환하지 않는다.

현재 CSceneTutorial::Initialize()가 직접 생성하는 안내는 옵션 1의 점프 안내 하나다. Set_UseMainScroll(true)로 설정해 화면에 고정된 HUD가 아니라 월드 위치에 배치한다. 일곱 옵션을 지원한다는 것과 일곱 안내가 모두 실제 레벨에 배치되어 있다는 것은 구분한다.

씬은 별도로 맵 배치 데이터를 읽고 플레이어, 딸 캐릭터, 풍선 등 장면 요소를 구성한다. 완료는 딸이 배치된 위치 부근의 100×100 트리거 진입으로 판단한다. 점프·벽 이동·스윙을 모두 수행했는지 개별 평가하는 조건은 없다.

완료 신호를 받으면 챕터 1 완료 값을 설정하고 게이트를 거쳐 메뉴로 복귀한다. 몬스터 전투 씬의 챕터 2 완료도 도착 영역을 기준으로 하며, 세부 생성·클리어 조건은 전투 구간 문서에 설명했다.

보스 격파와 엔딩의 접점​

보스 격파 연출 객체 CObjBossFirebirdEndSprite는 프레임 번호가 57에 도달하면 Set_BossDeadEnd(true)를 호출한다. 보스 씬은 이 신호를 읽어 챕터 3 완료 값을 설정하고, 게이트를 닫은 뒤 1000ms 후 SC_ENDING으로 전환하며 1500ms 후 게이트를 연다.

즉 마지막 타격 즉시 씬을 교체하지 않고 격파 연출의 지정 프레임까지 진행한 뒤 전환으로 연결한다. CSceneBoss::Initialize()에서 격파 연출 완료 신호를 false로 초기화해 재진입 시 이전 완료 신호가 남지 않도록 한다. 보스 전투와 폭탄 명중 처리 자체는 기존 보스·사슬 문서의 범위다.

격파 완료 신호는 범용 애니메이션 종료 이벤트가 아니라 고정 프레임 번호 검사다. 시트의 프레임 구성을 변경할 때 종료 조건도 함께 확인해야 한다.

마리 엔딩의 구성과 복귀​

CSceneEnding은 검은 화면 위에 800×600 배경 스프라이트와 290×400 마리 스프라이트를 배치한다. 배경은 화면 중심, 마리는 중심에서 왼쪽으로 200 떨어진 위치다. 두 객체 모두 메인 스크롤을 사용하지 않고 프레임 진행을 켠다.

이는 영상 파일 재생이나 카메라 컷 편집이 아니라 두 스프라이트의 프레임 재생을 합성한 장면이다. 엔딩 BGM을 시작하고, L키를 누르면 게이트를 통한 메뉴 복귀를 예약한다. 일정 시간이 지나면 자동 종료하거나 크레딧 다음 단계로 넘어가는 로직은 없다.

씬 해제에서는 엔딩 BGM을 정지하고 마우스·게이트를 제외한 객체를 삭제 예약한다. 게이트를 씬 사이에 유지해 전환 도중 사용할 수 있지만, 게이트 목록의 첫 객체가 반드시 존재한다는 전제에 의존한다.

전환 구조의 한계와 보강 방향​

현재 여러 씬에 게이트 닫기·전환 예약·게이트 열기 코드가 반복된다. 특히 튜토리얼 완료와 보스 격파 완료 분기는 완료 값이 true인 동안 매 Update 타이머를 추가한다. 트리거의 최초 진입 플래그가 있다고 해서 전환 예약까지 한 번만 실행되는 것은 아니다.

공통 보강은 전환 요청을 한 번만 발행하는 상태, 현재 전환의 취소·완료 처리, 타이머 ID와 객체 수명 관리다. 인트로 P키·챕터 반복 클릭·엔딩 L키 역시 전환 중 입력을 어떻게 처리할지 정책이 필요하다. 타이머가 나중에 사용할 객체 포인터와 등록 전 생성 객체도 이 수명 범위에 포함해야 한다.

현재 씬 매니저는 초기화를 Render 단계로 지연하며 새 씬의 Render가 Initialize보다 먼저 호출되는 경로가 있다. 따라서 이 연출 구성을 완전히 독립적이고 안전한 전환 시스템으로 소개하지 않는다. 이번 문서 작성은 현재 구현을 분석한 것이며 이 생명주기를 수정한 것은 아니다.

또한 진행 저장소는 메모리의 완료 플래그다. 실행을 종료한 뒤의 저장·복원, 챕터별 체크포인트, 실패 후 재시작 규칙까지 갖춘 진행 시스템은 후속 범위로 남긴다.

결과와 확인 범위​

로고·메뉴·안내·전투·엔딩을 따로 보여주는 데서 끝내지 않고, 입력과 완료 조건을 연결해 시작부터 엔딩까지 이동할 수 있는 흐름을 구성했다. 프레임 완료를 기다리는 보스 격파와 시간으로 순서를 정하는 인트로를 구분하고, 메뉴 배치 데이터에 챕터 진행 상태를 결합했다.

주요 근거는 Start/CSceneLogo.cpp, CSceneMenu.cpp, CObjGameUiChapterBtn.cpp, CObjTutoAni.cpp, CSceneTutorial.cpp, CSceneBoss.cpp, CObjBossFirebirdEndSprite.cpp, CSceneEnding.cpp, CGameStorageMgr.cpp·.h, CObjSprite.cpp다. 기반 씬·프레임 출력 코드를 활용한 부분과 본인 커밋에서 추가한 장면·연결을 구분했다.

시연은 인트로 시작, 초기 잠금 메뉴, 튜토리얼 안내와 완료 후 해금, 보스 격파 신호, 마리 엔딩·메뉴 복귀 순서가 적합하다. 조작 안내 전체 배치, 연속 입력, 씬 조기 종료, 게이트 없는 테스트 진입, 챕터 재진입은 별도 확인 항목이다. 이번 문서는 소스·Git 분석 결과이며 게임 전체 진행을 새로 실행 검증했다는 의미는 아니다.
