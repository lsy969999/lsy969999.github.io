사슬팔 결속과 스윙·당겨 이동

목표와 담당 범위​

산나비의 사슬팔을 단순한 원거리 이동 버튼이 아니라, 지형에 걸고 흔들리다가 원하는 순간 당겨 올라가는 이동 수단으로 구현했다. 마우스 조준, 갈고리 비행, 지형 결속, 스윙, 당겨 이동과 천장 부착이 하나의 조작 흐름으로 이어지도록 구성했다.

물리 라이브러리의 Rope나 Joint를 사용하지 않았다. 플레이어와 갈고리를 별도 게임 객체로 두고, 결속점과 줄 길이에서 플레이어 위치를 계산하는 게임 로직이다. 줄의 장력·늘어남·장애물 감김을 푸는 범용 로프 시뮬레이션과는 구분한다.

개인 프로젝트의 본인 확장 코드와 커밋을 기준으로 작성했다. 초기 Win32 프레임워크 전체를 이 기능의 신규 설계로 포함하지 않으며, 실제 튜토리얼·보스 씬에서 생성하는 CObjPlayer2 경로를 중심으로 설명한다.

객체별 역할​

클래스역할
CObjPlayer2조준·발사 입력, 결속 여부, 스윙 계산, 길이 보정·당겨 이동
CObjPlayer2Grab갈고리 이동, 충돌 위치 보정, 플레이어에 결속 알림
CObjPlayer2GrabSprite갈고리 방향에 맞는 스프라이트 애니메이션
CCollisionMgr사각형 겹침 검사와 충돌 방향·겹침 깊이 전달

몸체와 팔도 각각 CObjPlayer2SNBSprite, CObjPlayer2SNBARMSprite로 분리한다. 플레이어 로직에서 스윙·스윙 해제·천장 부착에 맞춰 두 애니메이션 상태를 함께 바꾼다.

조준에서 결속까지​

마우스 위치는 화면 좌표이고 플레이어 위치는 월드 좌표다. On_Mouse_Pos()에서는 플레이어 위치에 스크롤 오프셋을 더해 같은 화면 좌표계에서 차이를 계산하고, atan2(dy, dx)로 발사 방향을 구한다. 조준선 끝은 최대 안내 거리로 제한한다.

왼쪽 버튼을 누르면 기존 갈고리를 제거 예약하고 새 갈고리를 플레이어의 월드 위치에 생성한다. 계산한 방향과 플레이어 포인터를 전달하고 OBJ_PLAYER 목록에 등록한다. 갈고리 자식 스프라이트도 별도 등록된다.

갈고리는 Update마다 다음 방식으로 전진한다.

C++
m_tInfo.fX += cosf(m_fRadian) * m_fSpeed;
m_tInfo.fY += sinf(m_fRadian) * m_fSpeed;

초기 속도는 45이며, 초당 속도가 아니라 Update 한 번당 이동량이다. 플레이어는 자신과 갈고리 사이 거리가 400을 넘으면 갈고리를 제거 예약하고 관련 이동 플래그를 해제한다. 조준선 제한만으로 실제 비행이 끝나는 것은 아니다.

지형 충돌은 Raycast가 아니라 Collision_RectEx()의 사각형 겹침 검사다. 갈고리는 전달받은 방향·겹침 깊이로 위치를 밀어내고 속도를 0으로 만든다. 지형 옵션과 천장·좌우 충돌 정보를 보관한 뒤 m_GrabSend로 중복 알림을 막아 플레이어의 Grab(this)를 호출한다.

플레이어는 지형 옵션이 ERI_CLIMABLE일 때만 결속을 받아들인다. 그 외 지형에는 계속 매달리지 않고 갈고리를 제거한다. 몬스터 충돌은 ExcGrab()로 별도 연결되며, 포획·처형은 이 문서의 지형 이동과 구분한다.

사거리와 스윙 길이를 분리​

멀리 있는 지형을 겨냥할 수 있는 거리와, 결속 후 흔들리는 줄 길이는 서로 다른 값으로 관리한다.

값현재 초기값실제 역할
m_fHookGuideLength400조준선 길이 제한과 갈고리 거리 초과 제거
m_fHookMaxLength200먼 곳에 결속했을 때 자동 당김을 종료할 기준
m_fHookMinLength100최소 길이 확인 분기만 존재하며 강제 보정은 미구현

결속 당시 거리가 200보다 크면 m_bGrabHookResize를 켠다. GrabHookResize()는 플레이어를 갈고리 방향으로 Update당 30씩 이동시키고, 이동 후 거리가 200 미만이면 그 지점의 실제 거리·각도로 스윙을 초기화한다.

따라서 줄 길이를 정확히 200으로 clamp하는 구현은 아니다. 고정 이동량으로 당긴 결과에 따라 200보다 짧은 길이에서 스윙이 시작한다. 100이라는 최소값 역시 현재 코드에서 보장되는 하한으로 설명하면 안 된다.

결속점을 중심으로 스윙 계산​

Grab() 또는 자동 길이 보정이 끝나는 순간 다음 값을 저장한다.

  • 결속점: 갈고리의 월드 위치
  • 길이 L: 결속점과 플레이어 사이 거리
  • 시작 각도 theta0: 아래쪽 수직축 기준 atan2(dx, dy)
  • 경과 시간 t: 0으로 초기화한 후 Tick 차이를 초 단위로 누적

스윙은 Apply_Pend()가 아니라 실제 Update() 분기 안에 구현되어 있다. Apply_Pend()의 본문은 비어 있다. 현재 계산을 간추리면 다음과 같다.

C++
const float omega = sqrtf(1100.f / length);
const float angle = startAngle * cosf(omega * elapsed);

playerX = anchorX + sinf(angle) * length;
playerY = anchorY + cosf(angle) * length;

길이로 회전 반경을 정하고, 시간에 따라 코사인으로 각도를 바꿔 원호 위 위치를 직접 구한다. 화면에서 Y가 아래로 증가하므로 각도 0이면 결속점 바로 아래다. 1100은 코드에서 사용하는 운동 조절 상수이며 실제 지구 중력 단위로 설명하지 않는다.

단진동 형태의 근사식이다. 매 프레임 힘과 각가속도를 적분하는 구현은 아니며, 큰 각도까지 물리적으로 정확한 진자 운동을 재현하는 것도 아니다.

스윙 위치 적용은 결속 중이면서 당겨 이동·천장 부착·자동 길이 보정 상태가 아닐 때 수행한다. 여기에 현재 결속점 거리가 L - 10보다 커야 한다는 조건이 있다. 조건을 통과하면 중력·점프 누적 시간을 초기화하고 계산 위치를 적용한다. 항상 같은 길이를 강제하는 제약 솔버는 아니다.

A·D 입력은 플레이어가 결속점 어느 쪽에 있는지에 따라 시작 각도 값을 1도씩 바꾸고 좌우 이동도 적용한다. 힘을 가하는 대신 스윙 진폭을 직접 조절하는 조작 방식이다. 시간 기반 각도 계산과 프레임 단위 입력 보정이 함께 사용된다.

당겨 이동과 천장 부착​

결속 중 Space를 누르면 m_bGrabLoad가 활성화된다. GrabLoad()는 현재 위치에서 갈고리로 향하는 방향을 다시 계산해 Update당 30씩 이동한다. 자동 길이 보정과 달리 200 거리에서 멈추지 않고 플레이어와 갈고리의 사각형이 겹칠 때까지 접근한다.

갈고리가 천장 아래에 걸린 경우에는 천장 부착 상태로 전환하고 중력을 끈다. 저장한 천장 사각형의 아래 경계에 플레이어 반높이를 더해 몸이 천장 안으로 들어가지 않도록 위치를 맞춘다. 이후 갈고리를 제거하고 천장 이동 로직으로 이어진다.

좌우 벽 도착 분기에는 별도의 벽타기 전환 코드가 주석으로 남아 있다. 이 함수만으로 모든 방향의 지형 도착 전환이 완성되었다고 설명하지 않는다. 일반 벽 충돌·등반 처리는 플레이어의 다른 충돌·입력 분기와 함께 확인해야 한다.

해제와 시각적 피드백​

일반 결속에서 왼쪽 버튼을 놓으면 갈고리를 자식과 함께 제거 예약하고 포인터·결속·당김 상태를 해제한다. 중력을 다시 켜고 점프·중력 누적 시간을 초기화하며 몸체·팔의 스윙 해제 애니메이션을 선택한다. 천장 부착 중에는 일반 해제 분기를 건너뛴다.

현재 일반 해제 경로에는 스윙의 각속도에서 접선 속도를 계산해 다음 이동으로 넘기는 코드가 없다. 해당 위치의 관성 관련 시도는 주석으로 남아 있다. 따라서 기능 설명은 스윙 후 해제·낙하 전환이며, README의 관성 이동 표현만으로 운동량 보존을 완성 기능으로 주장하지 않는다.

화면에서는 미결속 시 점선 조준 가이드를, 결속 시 갈고리와 플레이어를 잇는 실선을 GDI로 그린다. 스크롤을 두 끝점에 동일하게 적용한다. 갈고리의 상하좌우 스프라이트와 발사·결속 효과음을 함께 연결해 비행과 매달림 상태를 구분한다.

결과와 한계​

구현의 핵심은 지형 충돌 결과를 이동 상태로 바꾸고, 결속점 기반 스윙을 자동 당김·천장 부착·해제까지 연결한 것이다. 외부 물리 엔진 없이도 사슬팔을 중심으로 한 이동 흐름을 구성했다.

현재 소스에서는 다음 보강 여지가 확인된다.

  • 갈고리 비행·당김·입력 진폭 보정은 프레임 단위이고 스윙은 시간 기반이다. 프레임률이 달라도 모든 조작이 동일하다고 보장할 수 없다.
  • 갈고리는 현재 위치의 사각형 겹침을 검사한다. 빠르게 이동하며 얇은 지형을 건너뛰는 경우를 막는 Sweep 검사는 없다.
  • 최소 줄 길이가 강제되지 않고, 길이 0을 분모로 사용하는 상황에 대한 명시적인 방어가 필요하다.
  • 결속점은 스윙 시작 시 위치를 저장한다. 움직이는 지형을 상대 좌표로 계속 추적하거나 줄이 장애물을 감싸는 처리는 아니다.
  • 여러 bool 플래그로 전환을 관리한다. 사거리 초과·재발사·지형 거부·당김 종료 같은 경로에서 상태가 일관되게 정리되는지 별도 확인이 필요하다.

주요 근거는 Start/CObjPlayer2.cpp, CObjPlayer2Grab.cpp, CObjPlayer2GrabSprite.cpp와 각 헤더다. CCollisionMgr.cpp의 지형 충돌 전달과 CSceneTutorial.cpp·CSceneBoss.cpp의 Player2 생성·충돌 연결도 확인했다.

제출용 영상은 짧은 거리 결속 → 먼 거리 결속 후 자동 당김 → A·D로 스윙 조절 → Space로 천장 접근 → 해제 후 낙하를 나누어 보여주는 구성이 적합하다. 경계 검증에는 결속 불가 지형, 사거리 초과, 재발사, 얇은 지형과 서로 다른 프레임률 비교를 포함한다.

이번 문서는 소스와 커밋 이력 분석으로 작성했다. 게임 실행이나 프레임률별 물리 검증을 새로 완료했다는 뜻은 아니다.
