갈고리 포획·처형과 부유 폭탄 공략 연계

이동 수단을 전투와 공략으로 확장​

사슬팔은 지형에 매달리는 이동 수단인 동시에 적에게 접근하고 제압하는 전투 수단이다. 갈고리 명중 후 플레이어가 대상 위치로 접근하고, 포획 상태에서 방향을 정해 처형하며 빠져나가는 흐름을 구현했다.

같은 조작을 부유 폭탄에도 적용했다. 일반 적은 처형으로 사망하지만 부유 폭탄은 반대 방향으로 발사되어 보스를 공격한다. 보스 공격으로 플랫폼이 파괴되면 폭탄이 생성되도록 연결해, 적의 공격을 공략 기회로 바꾸는 흐름을 구성했다.

지형 결속·스윙은 사슬팔 이동, 플레이어의 대시·애니메이션 구조는 이동·액션 문서에서 설명한다. 여기서는 대상별 반응과 게임플레이 연결에 집중한다.

대상별 반응을 공통 호출로 연결​

CObjMonster에 다음 가상 함수를 두고 대상마다 다르게 구현했다. Excuted는 현재 코드에 사용된 철자다.

C++
virtual void Grabbed(CObj* pPlayer) = 0;
virtual void Excuted(CObj* pPlayer, float fRad) = 0;

플레이어는 구체적인 적 종류별 사망 연출을 직접 선택하지 않는다. 대상에 Grabbed()로 포획을 알리고, 처형 입력에서는 조준 각도와 함께 Excuted()를 호출한다. 대상은 이 호출을 사망 애니메이션, 즉시 폭발, 발사 중 하나로 해석한다.

플레이어와 갈고리는 CObjMonster로 dynamic_cast해 접근한다. RTTI 없는 구조나 별도의 범용 상호작용 인터페이스를 구현한 것은 아니다. 부유 폭탄도 이 기반 클래스를 상속해 같은 흐름에 참여한다.

갈고리 명중에서 포획 유지까지​

CObjPlayer2Grab::On_Collision()은 일반 사각 충돌에서 상대가 CObjMonster인지 확인한다. 아직 Get_Excuted()가 false이면 갈고리를 멈추고 대상 중심에 배치한다. m_bMonsterExcSend로 반복 통지를 막아 플레이어의 ExcGrab(this, target)을 호출한다.

별도의 체력 임계값이나 기절 게이지는 검사하지 않는다. 처형 완료 여부를 기준으로 명중을 수락한다.

플레이어 쪽 진행은 다음과 같다.

  1. ExcGrab()에서 접근 플래그를 켜고 대상에 Grabbed()를 호출한다. 대상 포인터를 보관하고 감아 당기는 애니메이션과 효과음을 시작한다.
  2. ExcGrabLoad()가 플레이어를 갈고리 방향으로 Update당 30씩 이동시킨다. 이 과정에서 중력·점프 누적 시간을 초기화한다.
  3. 플레이어와 갈고리의 사각형이 겹치면 갈고리 중심에 위치를 맞추고 m_bExc를 켠다. 갈고리는 자식과 함께 제거 예약한다.
  4. 포획 유지 중 ExcStart()가 중력을 끄고 점프를 해제한다. 해당 입력 분기에서는 WASD로 이동하며 대상 위치를 플레이어 위치에 맞춘다.

포획 유지 애니메이션은 현재 도착 경로에서 오른쪽 상태로 지정한다. 또한 대상 위치 동기화는 부모 연결이나 물리 조인트가 아니라 플레이어가 직접 Set_Pos()를 호출하는 방식이다.

버튼을 놓는 순간 처형과 이탈​

포획 상태에서 왼쪽 마우스 버튼을 놓으면 플레이어의 화면 위치와 마우스 위치 차이로 방향을 계산한다. 플레이어 월드 위치에 스크롤을 더해 두 좌표계를 맞춘다.

C++
// 실제 처리의 핵심만 간추린 코드
const float dx = mouseX - (playerX + scrollX);
const float dy = mouseY - (playerY + scrollY);
const float rad = atan2f(dy, dx);
target->Excuted(this, rad);

이어서 플레이어는 같은 화면 방향으로 대시한다. 대시 함수의 각도 규약에 맞춰 라디안을 도로 변환한 뒤 부호를 바꾸고, Update당 30씩 4회 이동하도록 설정한다. 피격 후 8방향 탈출과 달리 여기서는 마우스 방향을 사용한다.

마지막으로 포획 플래그와 대상 포인터를 비우고 중력을 다시 켠다. 대상의 사망 애니메이션이 모두 끝날 때까지 플레이어를 붙잡아 두는 구조가 아니라, 대상의 처형 반응과 플레이어의 이탈을 동시에 시작한다.

일반 적은 어떻게 종료되는가​

대상Grabbed()Excuted() 이후
Trooper·Warrior포획 시작 상태와 포획 플래그 설정처형 완료 플래그·사망 애니메이션 설정, 사망 END에서 제거 예약
Defender포획 유지 상태와 포획 플래그 설정사망 애니메이션 완료 후 제거 예약
Survey Drone포획 시작 상태와 포획 플래그 설정즉시 제거 예약 후 별도 폭발 스프라이트 생성
Floating Bomb현재 본문이 비어 있음조준 반대 방향으로 이동하는 발사 상태 전환

일반 적의 이동·발사 코드에는 포획 플래그를 확인하는 분기가 있다. 그러나 공통 기반 클래스가 모든 AI와 물리를 일괄 정지시키지는 않는다. 포획 중 행동 중단 범위는 각 파생 클래스 구현에 달려 있다.

Trooper·Warrior·Defender는 스프라이트가 사망 마지막 프레임을 확인해 부모의 상태를 DEAD_END로 바꾸고, 부모 Update에서 Set_Dead_Cascade()를 호출한다. Survey Drone은 폭발을 별도 객체로 만들어 자신이 제거된 뒤에도 연출할 수 있게 한다.

새 대상을 포획할 때 이미 저장된 대상이 있으면 이전 대상에 Excuted(this, 0.f)를 호출하는 보강도 있다. 단순히 포인터만 덮어쓰지 않도록 한 처리지만, 일반적인 취소·놓아주기와는 다르다. 폭탄이라면 각도 0 처형이 발사로 해석된다.

부유 폭탄은 처형 대신 반대 방향으로 발사​

폭탄의 Excuted()는 제거하지 않고 실행 상태와 발사 각도를 설정한다.

C++
m_bExcuted = true;
m_fExcutedRad = fRad + PI;

이후 Update에서는 이 각도의 방향으로 3씩 이동한다. 화면 기준 플레이어가 마우스 쪽으로 빠져나가는 동안 폭탄은 반대쪽으로 날아간다. 따라서 보스 쪽으로 폭탄을 보내려면 플레이어가 이탈할 방향, 즉 보스 반대쪽을 조준하는 관계다.

이는 물리 충돌의 운동량 교환이나 반사 벡터를 계산한 결과가 아니다. 플레이어와 폭탄에 반대 방향의 이동을 각각 설정해 반동 공략을 표현한 것이다.

미처형 폭탄은 대각선 방향으로 Update당 3씩 움직이고 화면 경계·플랫폼 충돌에서 방향값을 전환한다. 처형 후에는 m_fExcutedRad를 사용하므로 기존 m_iAngle만 바꾸는 반사 분기는 발사 궤적을 바꾸지 않는다.

플랫폼 파괴에서 화조 격파까지​

보스 씬의 CObjUnstableKnockbackPlatformA는 보스 탄환·사격 폭발·몸통 공격과의 충돌에 반응한다. 대기·경고·이중 경고 단계의 애니메이션 상태를 거쳐 파괴 분기에 도달하면 등반 불가 옵션을 설정하고 폭탄 생성을 시도한다.

이때 OBJ_MONSTER 목록에 부유 폭탄이 하나라도 있으면 새 폭탄을 만들지 않는다. 별도의 풀이나 공급 큐가 아니라 목록을 순회해 존재 여부를 확인하는 방식이다. 폭탄 유무와 관계없이 해당 플랫폼은 파괴 처리되므로, 생성이 막힌 플랫폼이 나중에 자동으로 폭탄을 보충하는 구조는 아니다.

발사된 폭탄과 화조가 겹치면 폭탄 쪽에서 m_bExcuted && !m_bExploded를 검사한다. 조건을 통과하면 다음 순서로 처리한다.

  1. 폭발 플래그를 켜고 폭탄·자식 스프라이트를 제거 예약한다.
  2. 현재 위치에 512×512 폭발 스프라이트를 별도 생성하고 폭발음을 재생한다.
  3. 보스에 넉백과 폭탄의 진행 방향을 전달한다.

이 경로는 폭발 반경 안의 모든 적을 검사하는 범위 피해 시스템이 아니다. 직접 충돌한 보스에 넉백을 전달하는 개별 연동이다.

보스는 Set_Knockback() 호출 횟수를 누적한다. 두 번째에는 파손 외형 상태를 선택하고, 세 번째에는 넉백 카운터를 200으로 늘리며 종료 시작 플래그를 켠다. 종료 넉백이 끝나면 보스 종료 스프라이트를 생성한다. 해당 스프라이트는 57번 프레임에서 게임 진행 관리자의 BossDeadEnd를 설정한다.

따라서 이 공략 경로는 체력 수치를 폭발 데미지만큼 깎는 방식이 아니라 명중 횟수에 따른 파손·격파 전환이다. 상세 보스 공격 패턴과 엔딩 장면 진행은 별도 주제로 분리한다.

구현 결과​

플레이어의 공통 포획·처형 호출을 유지하면서 대상별 반응을 분리했다. 같은 사슬팔 조작이 일반 전투에서는 적 제거와 이탈로, 보스전에서는 폭탄을 이용한 반격으로 이어진다. 플랫폼·폭탄·보스가 연결되어 공략에 필요한 물체를 전투 중 공급하는 흐름도 구성했다.
