# 물고기 행동·피격·포획과 잠수 기록 연결

## 배경과 목표 {/* #해결하려던-문제 */}

여러 어종이 같은 바다에서 유영하면서 플레이어 접근에 반응하고, 공격을 받거나 포획되면 잠수 결과에 반영되어야 했다. 어종마다 이동·피격·획득 처리를 복제하면 수정 범위가 커지고, 화면의 물고기와 플레이어가 보유한 어획물 정보도 어긋나기 쉬웠다.

공통 행동을 `CFishGameObject`에 모으고 어종별 클래스에서 리소스와 수치를 설정했다. 감지 영역과 실제 접촉 영역을 나누고, 물고기 측 포획 완료 처리를 플레이어 무게·획득 알림·잠수 기록에 연결했다.

공통 물고기의 이동·상태 처리, 충돌에 따른 행동 요청, 피격·획득 처리를 구현했다. 플레이어 전투·작살 미니게임·손질 애니메이션과 카메라 줌 감속·Frustum Culling은 팀원의 기능과 연결했다.

## 어종 데이터와 공통 행동 분리

`FishInclude.h`에는 BlueTang, Clownfish, TitanTriggerfish 등 23개 어종 클래스가 연결되어 있다. 어종별 초기화에서 이름·Spine 리소스, 일반형/공격형 구분, 체력·이동 수치, 무게·길이·등급·별 수와 획득 정보를 설정하고 실제 Update는 공통 클래스에 위임한다.

이는 외부 파일로 모든 어종을 정의하는 데이터 주도 시스템은 아니다. 현재 구성은 C++ 파생 클래스의 초기값과 공통 구현을 재사용하는 방식이다.

생성은 `Fish::AddLayer_Fish<T>()`에서 물고기와 두 콜라이더 객체를 함께 구성한다. 물고기를 레이어에 등록하고 선택적으로 부모를 지정한 뒤, 콜라이더의 부모를 물고기로 설정한다. 콜라이더가 보관하는 연결 포인터로 충돌 대상 물고기를 찾는다.

| 구성 | 역할 |
| --- | --- |
| 어종별 클래스 | 리소스·속도·체력·획득 데이터 설정 |
| `CFishGameObject` | 현재 상태, 목표점 이동, 피격·사망·획득 처리 |
| `CFishAABBCollider` | 물고기 위치를 따라 충돌 영역 갱신·그룹 등록 |
| `CFishHQ` | 플레이어와 감지·피격 영역의 교차를 검사하고 행동 요청 |
| `CFishTankCollider` | 유영 범위와 이탈 복귀 판단에 사용하는 부모 영역 |

## 접근 감지와 실제 접촉을 나눈 이유

물고기가 플레이어를 발견하는 거리와 실제 몸이 닿는 범위는 다르다. 감지 영역은 도주·추적 시작에 사용하고, 피격 영역은 접촉 공격이나 사체 획득에 사용했다.

`Coll_FishesDetectBox`와 `Coll_FishesHitbox`를 별도 그룹으로 등록한다. 생성 함수에서 Hitbox Extents는 전달받은 스케일을 곱하지만 Detectbox는 해당 곱셈을 적용하지 않는다. 외형이 커진다고 감지 거리도 자동으로 같은 비율로 커지는 구조는 아니다.

`CFishAABBCollider`는 매 Update에 부모 위치를 읽고 오프셋을 더한다. 부모 회전 적용은 선택 사항이며, 감지 콜라이더는 이를 끈다.

`CFishHQ::LateUpdate_GameObject()`는 플레이어 콜라이더와 각 그룹을 순회하며 `Intersect()`를 검사한다. 감지 영역과 겹치면 일반형에는 `RunFrom()`, 공격형에는 `AttackTo()`를 요청하고, 벗어나면 감지 플래그를 내린다. 공간 분할 검색이나 범용 AI 센서 시스템이 아니라 그룹별 순회 검사다.

## 실제 상태 처리 방식

`CFishStateMachine` 등의 파일은 있지만, 공통 초기화의 상태 등록 코드는 주석 처리되어 있다. 실제 실행 경로는 `m_eFishState`와 `Update_GameObject()`의 조건 분기다. 별도 상태 클래스가 전환을 관리하는 완성된 State Pattern으로 포장하지 않는다.

| 상태 | 실행 중 하는 일 |
| --- | --- |
| `SWIM` | 부모 영역 안에서 주기적으로 목표점을 골라 일반 속도로 이동 |
| `RUNFROM` | 플레이어 반대 방향 목표점으로 이동, 감지 해제 시 유영 복귀 |
| `ATTACKTO` | 플레이어 근처 목표점으로 이동, 감지 해제 시 유영 복귀 |
| `QTE` | 작살과 플레이어 방향으로 만든 짧은 목표점까지 이동 |
| `FORCEMOVE` | 유영 영역에서 이탈한 물고기를 내부 목표점으로 복귀 |
| `DIE` | 사망 재생·어두워짐·제거 타이머 처리, 획득 중이면 목표점 이동 |
| `STOP` | 해당 상태 분기에서는 이동하지 않음 |

`RunFrom()`은 플레이어에서 물고기로 향하는 방향을 구해 현재 위치에서 10만큼 떨어진 목표점을 만든다. `AttackTo()`는 충분히 거리가 있을 때 플레이어 위치에서 물고기 쪽으로 0.5 떨어진 점을 목표로 둔다. 두 함수는 현재 상태가 달라질 때 애니메이션을 요청해, 감지 검사마다 같은 애니메이션을 처음부터 재생하지 않도록 했다.

도주·공격 타이머가 있다고 해서 각각 1초·0.2초 후 반드시 유영으로 돌아오는 것은 아니다. 해당 타이머 분기의 `Swim()` 호출은 주석 처리되어 있고, 실제 복귀에는 감지 플래그를 사용한다.

## 목표점 이동과 좌우 방향 전환

여러 상태가 `MoveTo()`를 함께 사용한다. 목표점까지 방향과 거리를 구하고 이번 프레임의 이동량인 `현재 속도 × DeltaTime`을 계산한다. 남은 거리가 이동량보다 작으면 목표점으로 직접 설정해 지나치는 현상을 막는다.

이동 중 외형 회전은 별도로 처리한다. 현재 Right 방향과 이동 방향의 X 부호가 반대이면 X 스케일의 부호를 바꾸어 좌우를 뒤집고, Z 회전 부호도 함께 조정한다. 이후 내적으로 목표 방향과의 각도를 구하고 외적으로 회전 방향을 정해 현재 회전 속도만큼 기울인다. 기울기에는 한계를 둔다.

위치는 목표 방향으로 이동하고 외형이 그 방향을 따라 기울어지는 구조다. 물리 힘으로 헤엄치거나, 회전 반경을 고려해 곡선 경로를 계산하거나, 장애물을 피하는 Navigation을 구현한 것은 아니다.

유영 목표점은 부모 위치·스케일로 만든 직사각형 영역에서 고른다. 갱신 간격도 난수로 정한다. 별도로 LateUpdate에서는 부모가 `CFishTankCollider`인 경우 물고기 Hitbox와 부모 AABB가 더 이상 교차하지 않으면 `FORCEMOVE`로 전환한다. 내부 목표점을 선택하고 도착하거나 약 2초가 지나면 유영으로 돌아간다.

이 검사는 완전한 내부 포함이 아니라 교차 여부다. 경계에 걸친 부분 이탈은 허용될 수 있으며, Update에 남아 있는 `if (false && ...)` 블록이 아니라 LateUpdate의 활성 경로를 기준으로 설명한다.

## 피격·접촉 공격·사망의 연결

`Damaged()`는 사망 상태를 제외하고 무적 타이머 조건을 통과했을 때 체력을 감소시킨다. 피격 시 무적 타이머를 0.5초로 설정하고 흰색 표시를 켜며, 흰색 표시는 Update에서 약 0.1초 후 해제한다. 체력이 0 이하가 되면 `Die()`로 상태를 바꾸고 비반복 사망 애니메이션을 요청한다.

피격 시에는 기존 파티클 매니저에 혈흔 생성을 요청한다. 피격 흰색 표시와 렌더 연결은 [Spine 엔진 통합](/projects/dave-the-diver/spine-dx9-integration)에 정리했다.

공격형 물고기가 공격 상태에서 플레이어와 Hitbox가 겹치면 `TryAttackTimer()`로 공격 간격을 검사하고 `CDiveDave::On_Hit()`을 호출한다. 타이머는 물고기 Update에서 누적하며 1.5초를 초과한 경우 초기화하고 공격을 허용한다. 플레이어의 최종 피해·무적 처리는 플레이어 측 책임이다.

사망한 물고기는 밝기를 줄이고, 사망 타이머가 7초 이상이면 주기적으로 렌더 여부를 바꿔 제거가 가까움을 표시한다. 10초를 초과하면 `Set_DeadCascade()`를 요청한다. 즉 사망과 즉시 삭제를 동일하게 취급하지 않고, 획득 가능한 사체 상태를 유지했다.

## 포획 방법은 달라도 같은 획득 정보로 연결

일반 사체 획득에서는 플레이어와 Hitbox가 겹치고 사망 후 1초가 지났을 때 `CFishHQ`가 `AcquireTo()`를 호출한다. 이 함수는 외형 회전을 끄고 이동 속도를 9로 설정한다. 거리가 0.1 미만이면 획득 처리하고, 그렇지 않으면 플레이어 위치를 목표점으로 저장한다.

`DIE` 상태를 유지하면서 `m_bDieAndAcquire` 플래그로 이동을 허용한다. 목표 위치는 `AcquireTo()` 호출 시 갱신한다.

작살 쪽에는 물고기가 제공하는 `QTE()`, `QTERelease()`, `JacksalAcquire()` 연결 지점이 있다. `QTE()`는 작살과 플레이어 위치로부터 짧은 이동 목표를 만들고, 해제 시 유영으로 복귀한다. `CProjectileReturn`에서는 해제·획득 함수를 호출한다. 본 문서의 범위는 이 물고기 측 반응이며 작살 입력 판정 전체가 아니다.

손질이 필요한 어종은 일반 흡수 획득 대신 플레이어에게 `Set_SlicableFish()`로 대상을 전달한다. 플레이어 손질 로직에서 `SliceComplete()`를 호출하면 물고기 측 획득 처리를 수행한다.

각 획득 완료 경로가 전달하는 결과는 같다.

```text
일반 사체 도착 / 작살 획득 / 손질 완료
  → 물고기 이름·무게·등급·별 수를 획득 알림에 전달
  → 플레이어 Change_Weight() 호출
  → DIVE_FISH에 이름·무게·길이·고기 수·초밥 정보 저장
  → 현재 잠수 기록의 Add_FishFront() 호출
  → 물고기와 자식 객체 제거 요청
```

이 데이터는 잠수 중 보유 목록과 귀환 후 결과 UI가 사용하는 입력이다. 화면의 물고기를 없애는 것에서 끝내지 않고, 이후 UI와 정산에서 필요한 정보를 넘기도록 연결했다. 후속 집계와 인벤토리 표시는 [잠수 결과·획득 목록 문서](/projects/dave-the-diver/dive-result-inventory)에서 다룬다.

## 구현 결과 {/* #구현에서-얻은-점과-남은-한계 */}

공통 상태·이동 함수를 두어 어종을 추가할 때 동일한 행동 코드를 반복하지 않도록 했다. 감지와 접촉을 분리해 어종 성향에 따른 반응을 구성했고, 포획 결과를 잠수 데이터로 넘겨 전투와 UI 담당 코드 사이의 연결 지점을 마련했다.
