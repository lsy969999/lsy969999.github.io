# 아이템 접근 안내와 장비 획득 UI 연동

## 배경과 목표 {/* #해결하려던-문제 */}

잠수 중 바닥에 놓인 아이템에 접근했을 때 무엇인지 알 수 있어야 하고, 획득한 뒤에는 어떤 장비나 재료를 얻었는지 확인할 수 있어야 했다. 접근 안내와 획득 알림은 내용이 비슷해도 수명과 표시 조건이 다르다.

접근 안내는 장면에 둔 공용 패널의 내용을 바꾸고 표시 여부를 제어했다. 획득 알림은 획득 시점에 별도 객체를 생성하고 등장·유지·퇴장 애니메이션 후 제거했다. 일반 잡템은 알림뿐 아니라 플레이어 무게와 잠수 기록에도 반영했다.

본인 작업은 설명·획득 UI 구현과 기존 아이템 흐름에 연결한 부분이다. 아이템 상자의 개봉·드롭, 플레이어 줍기 상태 전체, 무기 교체와 사용 아이템 슬롯 시스템은 팀원 구현이며 연동 지점으로만 다룬다.

## 접근 안내와 획득 알림을 구분

| 구분 | 접근 안내 | 장비 획득 알림 |
| --- | --- | --- |
| 클래스 | `CDiveItemDescUI` | `CDiveGetWeaponUI` |
| 생성 시점 | 잠수 씬의 UI 레이어 구성 시 | 개별 아이템의 획득 처리 시 |
| 표시 정보 | 이름·설명 | 이미지·이름·설명 |
| 표시 제어 | 공용 패널의 `Set_Render()` | Tween 진행과 완료 시 제거 요청 |
| 여러 요청 처리 | 패널 하나를 공유 | `GetWeaponUI` 목록의 맨 앞부터 재생 |

기존 [획득 목록·인벤토리 문서](/projects/dave-the-diver/dive-result-inventory)는 이미 얻은 데이터를 보관하고 귀환 결과로 보여 주는 흐름이다. 여기서는 월드 아이템에 접근하고 획득하는 순간의 피드백을 설명한다.

## 공용 설명 패널과 아이템별 내용

`CDive`는 UI 레이어에 `CDiveItemDescUI::Create(0.f, -150.f)`로 패널을 만들고 `DiveItemDescUI` 이름으로 등록한다. 개별 아이템은 패널을 매번 생성하지 않고 `0_UI_Layer`에서 찾아 이름과 설명을 설정한다.

`CDiveItem`에 가상 함수 `OpenItemDesc()`를 마련하고, 무기·산소 캡슐·일반 잡템의 파생 클래스가 내용을 채우도록 했다. 공통 아이템 클래스는 표시 시점을 판단하고, 어떤 문구를 보여 줄지는 해당 아이템이 정한다.

현재 문구는 C++에 직접 들어 있다. 외부 데이터 테이블이나 지역화 시스템으로 관리하는 구조는 아니다.

기존 충돌 검사에서 플레이어와 아이템이 겹치면 `OnCollisionEnter()`가 호출된다. 여기에 아이템 상태가 `DROPPED`인 경우에만 `OpenItemDesc()`를 호출하는 연결을 추가했다. 아이템에서 벗어나는 `OnCollisionExit()`와 공통 `GetItem()`에서는 설명 패널을 숨긴다.

함수 이름과 달리 현재 충돌 루프는 겹치는 동안 `OnCollisionEnter()`를 반복 호출한다. 실제 Enter 이벤트를 한 번만 발행하는 구조는 아니다. 각 아이템의 `OpenItemDesc()`는 패널이 표시 중인지 검사해, 숨겨져 있을 때 제목·설명을 넣고 켠다.

## 화면 UI로 렌더링

설명 패널은 자신의 렌더 플래그가 켜졌을 때만 `RENDER_ORTHO_UI` 그룹에 등록한다. 배경 텍스처의 종횡비로 사각형 크기를 맞추고, 제목·설명은 Transform 위치에 오프셋을 더한 뒤 화면 좌표로 변환해 폰트로 출력한다.

월드 아이템 위에 붙어 따라다니는 말풍선이 아니라 화면의 고정된 UI 위치를 사용하는 구성이다. 배경과 폰트는 서로 다른 렌더 호출로 구성되어 있어 텍스트를 배경 이미지에 미리 합칠 필요가 없다.

## 획득 완료 시 알림 생성

TripleAxel과 PentaAxel의 `GetItem()`은 먼저 `CDiveItem::GetItem()`을 호출해 획득 상태와 설명 패널을 처리한다. 이어서 `CDiveGetWeaponUI`를 생성하고 이미지 리소스 키·이름·설명을 넣은 뒤 `Ready_AfterCreate()`를 호출한다.

```text
플레이어 측 획득 처리
  → 아이템의 GetItem()
  → 공통 획득 상태 처리 + 접근 안내 숨김
  → 알림 객체 생성
  → 이미지 키·이름·설명 설정
  → Ready_AfterCreate()로 이미지 자식 구성
  → 레이어에 GetWeaponUI로 등록
```

`Create()` 이후 내용을 설정하고, 이미지 자식은 그다음 단계에서 생성한다. `Ready_AfterCreate()`가 선택된 이미지 키를 읽기 때문에 호출 순서가 중요하다. 현재 API는 재호출 시 중복 자식 생성을 막는 구조로 작성되지는 않았다.

클래스 이름에는 Weapon이 들어 있지만 산소 캡슐에서도 같은 알림을 사용한다. 아이템 효과를 실행하는 클래스가 아니라 이미지와 설명을 보여 주는 UI이기 때문에 공유할 수 있다. 산소 회복이나 무기 공격 방식은 이 알림의 역할이 아니다.

## 여러 획득 알림의 순차 재생

팝업은 화면 오른쪽 바깥의 X 좌표 `640 + 250`에서 시작한다. Tween은 전달받은 목표 X까지 500ms 동안 이동하고, 같은 위치에서 1,000ms 유지한 뒤, 500ms 동안 오른쪽으로 퇴장한다.

Update에서는 `GetWeaponUI` 목록의 맨 앞 객체가 자신인 경우에만 Tween을 진행한다. 기다리는 객체는 오른쪽 바깥에 두고, 앞선 팝업이 완료되어 제거된 뒤 다음 객체가 진행할 수 있도록 했다. 각 팝업의 실제 재생 시간은 약 2초이며, 대기 시간을 포함한 전체 생존 시간과는 다르다.

별도 알림 큐 매니저를 만든 것은 아니다. 기존 레이어의 객체 목록과 `front()` 비교를 이용한 순차 처리다. 대기 객체도 Update와 렌더 그룹 등록은 수행하므로 대기 중 객체의 계산을 완전히 생략하는 최적화로 설명하지 않는다.

Tween 진행에는 `int(fTimeDelta * 1000.f)`를 전달하고, 진행률이 1 이상이면 `Set_DeadCascade()`를 요청한다. 이는 초 단위 DeltaTime을 정수 밀리초로 변환한 방식이며, 소수 밀리초까지 보존하는 타이밍 구현은 아니다.

## 팝업 이미지의 부모 연결

`Ready_AfterCreate()`는 `CDiveGetWeaponUIImg`를 생성하고 팝업을 부모로 설정한다. 이미지 객체는 매 Update에 부모 위치를 읽고 자신이 가진 X·Y 오프셋을 더해 따라간다. 별도의 Tween을 이미지마다 만들지 않아도 패널과 함께 이동한다.

이미지 크기는 선택한 텍스처의 종횡비로 설정한다. 이때 부모의 전체 행렬을 합성하는 것이 아니라 위치에 오프셋을 더하는 방식이다. 부모 회전·스케일까지 모두 전파되는 범용 UI 레이아웃은 아니며, 현재의 평면 슬라이드 팝업에 맞춘 구현이다.

## 일반 잡템을 잠수 데이터에 연결

일반 잡템은 무기 알림과 다른 `CGetItemUI`를 사용한다. `CCommonItemWood::GetItem()`은 이미지·이름·무게를 알림에 넣고, 잠수 기록 구조인 `DIVE_FISH`에 잡템 정보를 저장한다.

구조체 이름은 물고기 중심으로 남아 있지만 `bFish = false`로 잡템을 구분한다. 나무 예제는 무게 0.1, 이름, 썸네일 키와 `sItemDesc`를 기록하고 `Add_FishFront()`로 현재 잠수 기록에 추가한다. 플레이어에는 같은 무게로 `Change_Weight()`를 호출한다.

이를 위해 팀원의 `CDiveDavePickUp::Clear()`에 `COMMONITEM` 분기를 추가해 해당 아이템의 `GetItem()`을 호출하도록 연결했다. 기존 무기 분기의 `Change_Gun()`과 사용 아이템 슬롯 배정은 본인이 새로 구현한 부분이 아니다.

잡템을 획득할 때 곧바로 선박 인벤토리 슬롯에 배치하는 것은 아니다. 잠수 기록에 남겨 둔 정보를 귀환 결과 UI가 집계하고 인벤토리로 연결한다. 이 후속 과정은 기존 결과 문서에서 설명한 경로를 재사용한다.

## 결과와 한계 {/* #구현의-의미와-남은-한계 */}

이번 구현은 기존 게임플레이를 다시 만드는 대신 필요한 지점에 UI를 연결한 작업이다. 접근 중에는 공용 패널을 재사용하고, 획득 후에는 독립 알림을 순서대로 재생해 두 종류의 피드백을 다른 수명으로 관리했다. 잡템도 화면 알림만 띄우는 데서 끝내지 않고 후속 결과가 사용할 설명·무게 정보를 남겼다.

현재 구조에서 보강할 부분은 다음과 같다.

- 공용 설명 패널에는 자신이 어느 아이템을 표시 중인지 식별하는 정보가 없다. 여러 아이템이 겹치면 기존 패널의 표시 플래그 때문에 새 내용이 반영되지 않거나, 한 아이템의 Exit가 다른 아이템의 안내를 숨길 수 있다. 표시 대상 선정과 소유자 확인이 필요하다.
- 공통 `GetItem()`은 획득 가능 여부를 반환하지 않는다. 이미 획득한 객체의 파생 `GetItem()`이 다시 호출되면 알림·기록 추가까지 중복으로 실행될 여지가 있다.
- 알림은 기존 객체 목록과 고정 화면 좌표에 의존한다. 해상도별 배치, 요청 합치기, 최대 대기 개수, 취소 정책을 제공하는 범용 알림 시스템은 아니다.
- 나무의 기록·무게 추가는 알림을 넣을 레이어를 찾은 조건문 안에 있다. UI 준비 실패가 게임 데이터 반영까지 막지 않도록 데이터 처리와 알림 생성을 분리할 여지가 있다.
- 현재 잠수 기록의 `.back()`과 UI 레이어가 존재한다는 전제가 있다. 임의 시점의 호출까지 안전한 인터페이스로 설명하지 않는다.

## 시연·검증 자료

1. 바닥 아이템 접근 → 이름·설명 표시 → 범위를 벗어나면 숨김.
2. 아이템 획득 직후 접근 안내가 사라지고 종류에 맞는 알림이 나오는 장면.
3. 장비를 연속 획득했을 때 오른쪽 팝업이 겹치지 않고 순서대로 등장·퇴장하는 장면.
4. 일반 잡템 획득 후 플레이어 무게와 잠수 중 보유 목록의 정보 비교.
5. 여러 아이템이 겹친 경우, 이미 획득한 아이템을 다시 처리한 경우를 별도 경계 테스트로 확인.

이번 문서는 소스와 커밋 분석으로 작성했다. 위 항목은 제출용으로 확보할 시연·검증 자료이며, 이번 작성 중 게임 실행이나 중복 획득 테스트를 새로 완료했다는 뜻은 아니다.
