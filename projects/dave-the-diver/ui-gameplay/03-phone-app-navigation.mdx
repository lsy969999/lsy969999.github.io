# 스마트폰 UI의 회전·앱 선택과 포커스 전환

## 배경과 목표 {/* #해결하려던-문제 */}

선박의 스마트폰은 고정된 버튼 목록이 아니라 화면 아래에서 올라와 기울어진 상태로 보이고, 앱을 실행하면 중앙으로 이동하며 정면을 향하는 UI다. 이때 아이콘은 스마트폰의 움직임을 따라가면서도 자신의 크기를 유지해야 하고, 클릭 판정도 실제 표시 위치와 일치해야 한다.

스마트폰 본체와 아이콘을 GameObject로 나누고, 아이콘 렌더링과 OBB에 같은 합성 행렬을 사용했다. 위치·회전의 Tween과 앱 화면의 생성 시점도 연결해 단순 화면 교체가 아닌 전환 동작으로 구성했다.

스마트폰 본체·아이콘·앱의 열기와 닫기를 구현했다. 장비 구매는 [iDiver UI](/projects/dave-the-diver/idiver-upgrade-ui), 보관 화면은 [결과·인벤토리](/projects/dave-the-diver/dive-result-inventory)에 정리했다.

## 진입 버튼·본체·아이콘의 책임

| 객체 | 역할 |
| --- | --- |
| `CShipPhoneIcon` | 스마트폰 진입 버튼의 AABB 피킹, 본체 생성과 닫기 요청 |
| `CShipPhone` | 본체 Transform, 열기·닫기·포커스 Tween, 앱 화면 생성·정리 |
| `CShipPhoneApp` | 앱 아이콘의 선택 표시, OBB 피킹, 실행 요청 |

진입 버튼에서 마우스 Ray가 AABB와 교차하고 클릭되면 스마트폰을 연다. 이미 열린 상태에서는 닫기를 요청한다. 본체가 실제로 Scene에서 사라진 것은 이후 Update의 태그 조회로 확인해 `m_bPhoneOpen`을 갱신한다.

`Open_Phone()`은 본체를 생성한 뒤 아이콘 23개를 네 열로 배치한다. 아이콘의 부모를 본체로 지정하고 모두 같은 Scene Layer에 등록한다. 아이콘 배치는 `i % 4`, `i / 4`를 이용한 고정 격자이며 반응형 자동 레이아웃은 아니다.

## 부모의 위치·회전만 아이콘에 전달

본체 크기는 텍스처의 폭·높이를 130으로 나눈 값으로 정한다. 아이콘에 본체 행렬을 그대로 곱하면 본체의 크기까지 아이콘에 다시 적용된다.

이를 피하기 위해 `CShipPhoneApp::Update_GameObject()`는 부모 World Matrix의 Right·Up·Look 벡터를 각각 정규화한다. 이동 성분은 유지하고 정규화한 축을 다시 채운 뒤 아이콘의 로컬 행렬과 곱한다.

```text
아이콘 로컬 행렬
  × 부모 World Matrix에서 축 길이를 정규화한 행렬
  = 아이콘 렌더링·충돌 판정용 행렬
```

행렬 계산의 핵심은 다음과 같다. 설명을 위해 축 추출·재대입 부분은 생략했다.

```cpp title="CShipPhoneApp.cpp · 행렬 합성 핵심"
D3DXVec3Normalize(&vRight, &vRight);
D3DXVec3Normalize(&vUp, &vUp);
D3DXVec3Normalize(&vLook, &vLook);
// 정규화한 세 축을 parentWorld에 다시 대입한다.
m_matNewWorld = myLocal * parentWorld;
```

본체가 기울어지거나 이동해도 아이콘은 함께 움직이고, 아이콘 크기는 별도로 조절할 수 있다.

## 그리는 행렬과 클릭하는 행렬 일치

아이콘은 `m_matNewWorld`를 DirectX 9의 World Transform으로 설정해 그린다. OBB도 같은 행렬로 변환하고 `Coll_Phone` 그룹에 등록한다.

실제 아이콘 클릭은 각 아이콘의 LateUpdate에서 자신의 OBB에 마우스 Ray를 검사한다. 그룹에 등록했다고 해서 중앙 Manager가 가장 가까운 UI 하나만 골라 입력을 소비하는 구조는 아니다.

선택되지 않은 아이콘을 클릭하면 형제 앱 아이콘의 선택을 해제하고 자신을 선택한다. 선택된 아이콘을 다시 클릭하면 실행 분기를 확인한다. 시간 제한이 있는 더블클릭이 아니라 선택 상태에 따른 두 단계 동작이다.

선택 피드백은 두 방법을 함께 사용한다.

- 크기를 `(0.3, 0.4125, 0.3)`에서 `(0.35, 0.48125, 0.35)`로 변경한다.
- `Tex_PhoneAppAlpha` 대신 `Tex_PhoneApp`의 같은 Index 텍스처를 사용한다.

## 표시 아이콘과 실행 가능한 앱의 구분

현재 실행 분기는 다음 세 Index에만 있다.

| 아이콘 Index | 포커스 이름 | 생성하는 화면 |
| --- | --- | --- |
| 7 | `Weapon` | `CShipPhoneWeaponBG` |
| 11 | `IDiver` | `CShipPhoneIDiverBG` |
| 22 | `Stock` | `CStockMarket` |

23개 아이콘 전체에 앱 기능을 구현한 것은 아니다. 실행 경로도 앱 Registry나 Factory에 등록한 방식이 아니라 Index와 문자열을 비교하는 분기다. 주식 앱은 열기·닫기를 연결했고 내부 기능은 팀원이 담당했다.

## Tween과 앱 생성 시점

Tweeny를 사용해 여러 Transform 값을 함께 보간한다. `step(int(fTimeDelta * 1000.f))`로 밀리초 단위 진행량을 전달한다.

| 전환 | 보간하는 값 | 설정 시간 |
| --- | --- | --- |
| 열기 | Y: -10 → 0, X 회전: 0 → 10°, Y 회전: 0 → -15° | 500ms |
| 포커스 | X: -5 → 0, 기울어진 회전 → 0° | 300ms |
| 포커스 해제 | X: 0 → -5, 회전 → X 10°·Y -15° | 300ms |
| 닫기 | Y: 0 → -10 | 100ms |

포커스의 Y 값은 양 끝 모두 0이다. 카메라를 줌하는 것이 아니라 스마트폰 객체의 위치·회전을 바꿔 정면의 앱 화면으로 전환한다.

```text
선택한 앱 클릭
  → Focus_App: 대상 이름 저장 + 포커스 Tween 시작
  → 300ms 보간 완료: m_bFocus = true
  → OnFocus_App을 한 번 실행
  → 선택한 앱 화면을 Scene Layer에 생성
```

`m_bOnFocus`는 포커스 상태가 유지되는 매 프레임마다 앱을 생성하지 않게 하는 진입 플래그다. `OnFocusing_App()`라는 반복 호출 함수도 있지만 현재 유효한 처리는 없다.

## 앱에서 돌아오기와 정리

앱 화면은 뒤로 가기 입력 등에서 `UnFocus_App()`을 호출한다. 이 함수는 포커스 해제 Tween을 켜는 동시에 `m_bFocus`를 바로 false로 바꾼다. 다음 본체 Update에서 `OnUnFocus_App()`이 실행되어 앱 화면의 계층 삭제를 요청한다.

즉, 열 때는 중앙 이동이 끝난 뒤 앱을 만들지만, 돌아올 때는 이동 완료를 기다리지 않고 앱부터 정리한다. `OnUnFocus_App()`은 iDiver·무기·주식 화면을 태그로 찾고 `Set_DeadCascade()`를 호출한다.

앱 화면 자체는 본체의 자식으로 생성하지 않고 Scene Layer에 독립 등록한다. 그래서 본체의 자식인 아이콘 정리와 별개로 앱 화면 정리가 필요하다. 스마트폰 닫기 Setter도 이 정리 함수를 호출한 뒤 본체의 닫기 Tween을 진행한다. 닫기 완료 후 본체에 계층 삭제를 요청한다.
