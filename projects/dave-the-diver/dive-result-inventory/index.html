잠수 결과 UI와 획득 목록·인벤토리 연결

배경과 목표​

잠수 중에는 지금 무엇을 들고 있고 얼마나 무거운지 확인해야 하고, 귀환 후에는 이번 탐험의 성과와 가져온 재료를 보여 줘야 한다. 이 화면들이 각각 데이터를 소유하면 물건을 버린 결과가 정산에 남거나, 화면을 닫는 순간 기록이 사라지는 문제가 생길 수 있다.

잠수 기록을 UI 밖에서 관리하고 보유 목록·결과 화면·선박 인벤토리가 같은 데이터를 읽도록 연결했다. 전투·맵 아이템·초밥집 경영은 팀원 기능과 획득 데이터를 주고받는다.

장비 구매로 다음 잠수의 설정을 바꾸는 흐름은 iDiver 업그레이드 UI에서 설명한다. 여기서는 잠수 중 생긴 결과를 확인하고 가져오는 흐름에 집중한다.

같은 데이터, 서로 다른 화면​

구성 요소사용하는 정보와 역할
CGameMemMgr::CDiveInfo한 번의 잠수 시간·수심·획득 횟수·보유 목록
CHoldFishUI·CHoldFishUIItemGroup잠수 중 보유 목록, 중량 확인과 버리기
CDiveResultUI이번 기록과 이전 최고 기록, 가장 큰 물고기와 잡템 표시
CDaveInfo::Get_Inventory()선박에서 조회하는 아이템 슬롯 데이터
CShipDiverBoxInventory슬롯 아이콘·수량·선택 테두리·설명 표시

공용 CGameMemMgr에 잠수 기록과 잡템 전달을 연결했다. 상태는 Scene과 별도로 메모리에 보관하며, 파일 저장·복원은 구현하지 않았다.

잠수 기록의 표현​

CDiveInfo는 DIVE_FISH 목록을 가진다. 이름과 달리 물고기뿐 아니라 일반 아이템도 들어가며 bFish로 구분한다. 이름·썸네일·별 등급·무게·길이·수량 및 아이템 설명 등이 기록에 포함된다.

추가한 Add_FishFront()는 목록 앞에 값을 넣고 물고기이면 포획 횟수, 일반 아이템이면 획득 횟수를 증가시킨다.

Plain Text
획득 데이터
  → Add_FishFront
  → 최신 항목이 목록 앞에 삽입
  → 물고기 / 일반 아이템의 누적 획득 횟수 증가

두 카운터는 현재 목록 크기나 재료 수량의 합이 아니라 함수가 호출된 횟수다. 잠수 중 항목을 버려도 카운터를 감소시키는 코드는 해당 UI 제거 경로에 없으므로, 결과의 포획·획득 횟수와 현재 보유 개수는 다를 수 있다.

잠수 시작 시 기록을 추가하고, CDive::Free()의 연결 부분에서는 플레이어가 가진 최고 수심을 기록한 뒤 DiveEnd()를 호출한다. 시간은 clock()의 시작·종료 차이를 CLOCKS_PER_SEC로 나눈 값이다. 게임 Delta Time을 누적하는 방식이나 슬로우 배율을 직접 반영하는 타이머와는 구분한다.

잠수 중 보유 목록과 버리기​

CHoldFishUIItemGroup은 마지막 잠수의 목록을 읽고 각 항목에 대응하는 UI 객체를 생성한다. 썸네일·이름·별·수량·무게·등급을 전달하며, 같은 어종도 이 단계에서는 하나의 요약 행으로 합치지 않는다.

보유 중량 표시는 현재 목록의 fWeight를 합산하고, 최대 중량은 CDaveInfo의 적재 설정을 읽는다. iDiver의 화물함 업그레이드와 보유 목록 UI가 같은 설정을 사용하도록 연결한 부분이다.

선택 항목에서 Space를 누르면 버리기 확인 패널을 연다. 확인 패널이 있는 상태에서 다시 처리되면 다음 동작을 수행한다.

  1. 선택된 행과 확인 패널에 계층 삭제를 요청한다.
  2. 플레이어에게 버린 항목의 무게만큼 음수 변화량을 전달한다.
  3. 실제 잠수 보유 목록에서 해당 항목을 제거한다.
  4. 남은 UI 행을 재배치한다.

화면에서 아이콘만 지우는 것이 아니라 데이터와 플레이어 중량을 함께 변경하는 흐름이다. 다만 선택 행과 데이터의 연결은 영구 ID가 아니라 UI 순회 순서와 목록 Iterator의 대응에 의존한다.

귀환 후 결과 화면 구성​

선박의 Update는 잠수 기록이 있고 결과 창을 아직 열지 않은 경우 타이머를 누적한다. 1초를 넘으면 m_bResultOpend를 설정하고 결과 창을 생성한다. 이 조건은 선박 객체의 표시 제어이며 잠수 ID별 영구 정산 완료 표시는 아니다.

CDiveResultUI::Ready_AfterCreate()는 가장 최근 CDiveInfo를 복사해 화면용 문자열과 이미지 정보를 준비한다.

표시 내용계산 기준
잠수 회차잠수 기록 배열 크기
포획·획득기록에 저장된 누적 횟수
수심종료 시 전달한 최고 수심
시간기록의 시작·종료 시각 차이
가장 큰 물고기현재 목록에서 물고기만 남기고 길이 내림차순 정렬

가장 큰 물고기를 찾을 때 원본 보유 목록을 정렬하지 않고 복사본에서 필터와 정렬을 수행한다. 이름·길이·썸네일·별을 결과 화면에 사용한다. 여기서 최대 물고기는 현재 기록에 남아 있는 물고기 기준이므로, 이미 버린 물고기까지 포함한 전체 포획 이력의 최대값은 아니다.

현재 기록과 이전 최고 기록 비교​

잠수가 두 번 이상이면 마지막 기록을 제외한 이전 기록들에서 시간·포획·수심·획득의 최댓값을 각각 구한다. 하나의 최고 회차를 선정하는 것이 아니라 항목마다 서로 다른 회차가 최고가 될 수 있다.

이번 값이 이전 최댓값보다 크면 현재 기록 쪽에 PinkBest 이미지를 붙이고, 그렇지 않으면 이전 최고 기록 쪽에 Best를 붙인다. 동률도 후자에 해당한다. 첫 잠수는 별도 분기로 현재 기록 쪽에 배지를 배치한다.

결과 UI를 준비할 때 잠수 기록을 순회해 최고 기록을 집계한다.

잡템 집계와 선박 인벤토리 반영​

결과 화면 하단은 전체 물고기 목록이 아니라 bFish == false인 일반 아이템을 추린다. 같은 sFishName을 키로 Map에 모으고, 그 결과를 아이콘 배치와 인벤토리 전달에 사용한다.

현재 집계에서는 처음 만난 항목의 수량을 1로 설정하고, 뒤에 같은 이름이 있으면 그 항목의 iMeatCnt를 더한다.

선박 인벤토리 전달은 다음 규칙이다.

Plain Text
일반 아이템을 이름별로 집계
  → 인벤토리 0~31번에서 같은 썸네일 Asset Name 검색
  → 있으면 수량 증가
  → 없으면 수량이 0인 첫 슬롯에 이름·설명·이미지·수량 저장

집계 키는 이름이고 슬롯 병합 키는 썸네일 Asset Name이다. 서로 독립적인 Item ID를 사용한 구조는 아니다. 빈 슬롯이 없을 때 실패를 반환하거나 대기 보관하는 처리도 해당 경로에는 없다.

결과 아이콘은 Map 순서로 한 줄에 8개씩 배치한다. 코드의 8 × 4 주석과 별개로 생성 반복문에는 최대 32개로 자르는 조건이 없으므로, 인벤토리 저장 용량과 결과 화면 표시 용량을 동일하다고 가정하지 않는다.

선박 인벤토리에서 다시 읽기​

CShipDiverBoxInventory는 일반 아이템 슬롯 031을 8열·4행으로 만든다. 별도로 3236번 장비 표시 영역을 구성하며, 이번 잡템 반영은 그 장비 영역을 사용하지 않는다.

Update에서는 CDaveInfo::Get_Inventory()를 읽어 슬롯 이미지의 Asset Name과 수량을 갱신한다. 선택 슬롯에 맞춰 테두리의 부모와 크기를 바꾸고, 설명 패널에는 해당 슬롯의 이름·설명을 전달한다. 마우스 Ray와 슬롯 AABB로 선택 Index를 바꾼다.

결과 화면이 만든 임시 아이콘을 그대로 선박으로 옮기는 것이 아니라, 저장된 슬롯 데이터를 선박 UI가 다시 읽는 구조다.

화면 등장과 종료​

결과 창과 선박 인벤토리의 등장에는 Tweeny를 사용했다. Y 위치를 -10에서 0으로 바꾸는 during(200) 보간에 int(fTimeDelta * 1000)을 전달하므로 의도한 재생 시간은 약 0.2초다. 정수 밀리초로 바꾸는 과정에서 프레임별 소수 부분은 버린다.

결과 창은 Space 입력에서 CToSushiUI의 존재 여부에 따라 생성 또는 삭제를 요청하고 자신을 닫는다. 이 버튼은 후속 화면으로 전환하는 역할만 맡는다.

선박 인벤토리는 C 입력에서 닫기 Tween을 시작하고 완료 시 Set_DeadCascade()를 호출한다. 두 화면 모두 같은 시점에 같은 종료 애니메이션을 사용하는 것은 아니다.
