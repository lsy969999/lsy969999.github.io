부모·자식 계층 기반 업데이트와 오브젝트 디버그 GUI

배경과 목표​

UI 패널과 이미지, 물고기와 충돌 영역처럼 서로 연결된 객체는 부모의 변경 결과를 자식이 사용하는 경우가 많았다. 레이어에 넣은 순서만으로 업데이트하면 이 관계를 명시하기 어렵고, 부모를 제거할 때 함께 정리할 대상도 따로 관리해야 한다.

CGameObject에 부모 포인터와 자식 목록을 추가하고, 씬에서 계층 관계를 기준으로 업데이트 순서를 구성했다. 같은 관계를 하위 객체의 제거 표시에 재사용하고, ImGui에서 실제 저장 목록과 부모·자식 구조를 각각 확인할 수 있도록 했다.

객체의 계층 연결·순회와 디버그 GUI를 구현했다. 실제 삭제를 프레임 끝의 CScene::EndOfFrame()으로 옮긴 처리는 팀원이 추가했다.

보관 구조와 계층 관계를 분리​

레이어는 태그별 list<CGameObject*>를 보관한다. Add_GameObject()는 같은 태그가 있으면 목록 뒤에 추가하므로, 하나의 이름으로 여러 객체를 등록할 수 있다. 레이어의 Free()는 등록된 객체를 순회하며 해제한다.

부모·자식 관계는 이 저장 구조와 별개다.

구성역할
씬의 레이어 맵레이어와 그 안의 객체를 찾는 진입점
레이어의 태그별 객체 목록객체 등록·조회와 해제 대상 보관
객체의 부모 포인터상위 객체 참조, 루트 여부 판별
객체의 자식 목록하위 순회와 일괄 처리 대상 연결

Set_Parent()는 레이어를 옮기거나 객체의 참조 수를 늘리지 않는다. 부모가 자식을 독점 소유하는 스마트 포인터 트리가 아니라, 레이어에 등록된 객체 사이의 관계를 원시 포인터로 표현한 구조다.

실제 UI 구성에서도 패널과 이미지를 각각 레이어에 넣은 뒤 이미지의 부모를 패널로 설정한다. 부모 연결만 하고 레이어 등록을 생략하면 계층 순회에서는 도달하더라도 레이어 기반 정리 대상에서는 빠질 수 있으므로 등록 책임을 별도로 지켜야 한다.

자체 참조 카운팅으로 객체 수명 유지​

엔진 객체의 수명에는 CBase 기반 참조 카운팅을 사용했다. shared_ptr의 별도 제어 블록 대신 객체 내부의 m_dwRefCnt를 AddRef()·Release()로 관리하는 침투형 참조 카운팅이다. 객체를 보관하는 곳에서 필요한 참조를 추가하고, 사용이 끝나면 반환한다.

이 구현의 카운터는 0부터 시작하며, 최초 소유 외에 추가된 참조 수를 나타낸다. Release()는 호출 시점의 값이 0이면 Free()와 delete this를 실행하고, 0보다 크면 감소 전 값을 반환한다.

CBase.inl
CBase::CBase() : m_dwRefCnt(0)
{
}

unsigned long CBase::AddRef()
{
    return ++m_dwRefCnt;
}

unsigned long CBase::Release()
{
    if (0 == m_dwRefCnt)
    {
        Free();
        delete this;
        return 0;
    }

    return m_dwRefCnt--;
}

예를 들어 레이어가 보관한 객체를 렌더 그룹에도 등록하면 다음 순서로 수명을 유지한다.

시점카운터처리
생성 후 레이어에 등록0최초 소유를 레이어에 맡긴다.
렌더 그룹 등록1Add_RenderGroup()에서 AddRef()한다.
렌더 그룹 정리0Release()가 1을 반환하고 객체는 유지된다.
이후 레이어에서 해제삭제0인 상태에서 Release()하므로 실제로 소멸한다.

레이어가 먼저 참조를 반환하더라도 렌더 그룹의 참조가 남아 있으면 메모리는 유지된다. 렌더러는 프레임의 출력이 끝난 뒤 Clear_RenderGroup()에서 등록된 참조를 반환한다. 객체를 목록에 넣는 것만으로는 수명이 연장되지 않으므로, 이 등록·해제의 짝이 중요하다.

Safe_Release()는 null을 검사한 뒤 Release()를 호출하고, 반환값이 0일 때만 전달받은 포인터를 null로 바꾼다. 추가 참조가 남았다면 포인터 값은 그대로이므로, 참조를 반환한 호출자는 해당 포인터를 다시 소유한 것처럼 사용하면 안 된다. 렌더 그룹은 반환 후 목록 자체를 비운다.

Free()는 파생 클래스의 컴포넌트·리소스·객체 관계를 정리하는 가상 함수다. 실제 메모리 삭제는 CBase::Release()가 담당한다. 호그와트 레거시의 커스텀 삭제자처럼 부모 Free() 안에서 delete this를 수행하는 방식과는 구분된다.

부모·자식 포인터는 이 참조 수를 늘리지 않는 연결이다. 따라서 참조 카운팅은 소유자가 붙잡은 객체의 수명을 관리하고, Set_Dead()는 게임에서 제거할 대상을 표시하며, 부모·자식 목록은 업데이트 관계를 나타낸다. 세 역할을 따로 다뤘다.

카운터는 일반 정수이므로 여러 스레드에서 동시에 증감하는 용도로는 사용할 수 없다. 참조 반환 누락은 누수로, 중복 반환은 조기 삭제로 이어지며 순환 소유도 자동으로 해소하지 못한다. 생성·등록·해제 경로에서 수동으로 규약을 맞춰야 하는 구조다.

부모 변경과 연결 해제​

Set_Parent(newParent)는 기존 부모가 있으면 그 부모의 자식 목록에서 자신을 제거한다. 이후 새 부모 포인터를 저장하고 새 부모의 자식 목록에 자신을 추가한다. nullptr를 전달하면 이전 부모 목록에서 자신을 빼고 부모 포인터를 비운다.

양쪽 연결을 함께 바꾸기 때문에 정상적인 재연결에서는 이전 부모의 자식 목록에 잔여 포인터가 남지 않도록 했다. 같은 부모를 다시 지정하는 경우도 제거 후 재추가하므로 형제 목록의 순서가 달라질 수 있다.

복사 생성자는 원본의 부모 관계를 복사하지 않고 부모 포인터를 nullptr로 시작한다. 복제된 객체가 원본 계층에 자동으로 연결되는 것을 피하고, 생성하는 쪽에서 관계를 다시 설정하도록 한 것이다.

부모부터 업데이트하기​

CScene::Update_Scene()은 모든 레이어와 태그별 목록을 순회해 부모가 없는 객체를 모은다. 각 루트에서 TreeLevelTraversal()로 계층 목록을 만든 뒤 그 순서대로 Update를 호출하는 구조다.

순회 의도는 큐를 사용하는 너비 우선 탐색이다. 예를 들어 하나의 트리가 다음과 같으면 실행 목록은 Panel → Image → Button → Label 순서가 된다.

Plain Text
Panel
├─ Image
└─ Button
   └─ Label

루트를 모두 합친 하나의 전역 깊이 순서가 아니라, 루트 하나의 하위 트리를 처리한 다음 다음 루트로 넘어간다. 따라서 서로 다른 트리 사이의 의존성까지 정렬하는 일반적인 위상 정렬 시스템은 아니다.

Update 중 Get_Dead()가 true인 객체는 건너뛰고, 반환값이 OBJ_DEAD이면 해당 객체에 제거 표시를 한다. LateUpdate에서도 루트와 계층 목록을 새로 구성해 살아 있는 객체만 호출한다.

계층 목록은 해당 루트의 객체 Update를 시작하기 전에 만든다. 자식 리스트를 순회하면서 곧바로 Update하는 방식과 달리 현재 목록을 확보한 뒤 실행하지만, 모든 루트의 관계 변경을 안전하게 일괄 적용하는 스냅샷 시스템은 아니다. Update 중 부모를 바꾸면 이미 확보한 목록과 이후 루트·LateUpdate에서 얻는 관계가 달라질 수 있다.

업데이트 계층과 Transform 상속은 다르다​

Set_Parent() 자체는 위치·회전·크기를 계산하지 않는다. 공통 CTransform도 부모 행렬을 자동으로 곱하지 않는다. 계층을 연결하면 부모의 Update를 먼저 처리할 수 있지만, 실제로 어떤 값을 따라갈지는 자식 클래스가 정한다.

예를 들어 획득 팝업 이미지는 부모 위치에 고정 오프셋을 더한다. 스마트폰 아이콘은 부모의 기준 벡터를 정규화한 행렬을 사용해 크기 영향을 조정한다. 물고기 콜라이더는 부모 위치와 선택적인 회전을 읽는다.

이처럼 계층은 서로 다른 추종 로직이 같은 부모 관계를 사용할 수 있는 기반이다. 자동 월드 행렬 전파·Dirty Flag·KeepWorld 재부모화까지 제공하는 Transform Scene Graph는 아니다. 부모 우선 호출만으로 모든 월드 행렬의 최신 상태를 보장하지도 않으므로, 각 클래스가 Transform 값을 변경하고 계산하는 시점도 맞춰야 한다.

제거 표시와 실제 수명 종료​

Set_Dead()는 자기 자신의 플래그만 바꾼다. Set_DeadCascade()는 자기 자신을 루트로 하위 순회를 수행해 자손에게도 같은 표시를 한다. 팝업과 이미지처럼 함께 사라져야 할 객체 묶음에서 사용한다.

표시하는 순간 객체를 삭제하지는 않는다. 현재 통합 코드에서는 팀원이 추가한 CScene::EndOfFrame()이 레이어 목록을 순회하며 Dead 객체를 Safe_Release()하고 목록에서 제거한다.

CGameObject::Free()는 자신을 부모의 자식 목록에서 제거하고, 남아 있는 자식의 부모 포인터를 nullptr로 바꾼다. 자식 객체를 그 자리에서 직접 해제하지는 않는다. 따라서 부모에게만 Set_Dead()를 호출하면 자식은 함께 죽는 것이 아니라 부모가 해제된 뒤 분리되어 남을 수 있다. 함께 제거하려면 Cascade 표시를 사용해야 한다.

단일 객체가 OBJ_DEAD를 반환하는 경로도 자동 Cascade가 아니다. 또한 부모만 Dead 상태여도 순회 목록에는 살아 있는 자식이 포함될 수 있어, Dead 부모를 기준으로 전체 하위 트리 업데이트를 중단하는 정책과 구분해야 한다.

RAW와 TREE로 같은 객체를 다르게 보기​

CManagement::Update_ImGui()에 두 가지 보기를 마련했다.

RAW는 레이어 → 객체 태그 → 등록된 객체 순서로 보여 준다. 태그별 목록의 크기를 라벨에 표시하므로 같은 이름으로 몇 개가 등록되어 있는지 확인할 수 있다. 객체의 실제 보관 위치를 확인하는 용도다.

TREE는 모든 등록 객체의 포인터에 태그_인덱스 라벨을 만들고 루트를 찾는다. 이후 재귀적으로 Childs를 펼쳐 부모·자식 관계를 보여 준다. 트리 노드는 객체 포인터를 ImGui ID로 사용하므로 표시 이름이 같더라도 해당 노드를 구분할 수 있다. 라벨의 인덱스는 목록 순서이며 영속적인 객체 식별자는 아니다.

게임 업데이트는 큐 기반 레벨 순회로 처리하고, GUI에서는 재귀적으로 계층을 펼친다.

객체에서 컴포넌트 GUI로 연결​

각 객체의 Update_ImGui()는 컴포넌트를 STATIC·DYNAMIC 그룹으로 나누어 보여 주고, 컴포넌트 이름을 펼치면 해당 컴포넌트의 Update_ImGui()를 호출한다. 기본 객체 화면에서는 ViewZ도 조절한다.

CTransform은 위치·회전·크기를 DragFloat3로 노출한다. 상위 GUI가 모든 컴포넌트의 속성을 직접 알 필요 없이, 각 컴포넌트가 자신의 편집 항목을 구현하는 방식이다.

이 GUI는 런타임 상태 확인·수치 편집에 사용한다. 부모를 드래그해 재연결하거나, 편집 내용을 파일에 저장하고 Undo하는 씬 에디터까지 제공하지는 않는다. RAW 보기에서는 객체별 ID 범위를 따로 두지 않고 동일한 위젯을 연속 호출하므로, 같은 그룹의 여러 객체를 펼칠 때 ImGui ID 충돌도 점검 대상이다.
