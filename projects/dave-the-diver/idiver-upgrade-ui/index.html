iDiver 장비 업그레이드 UI와 플레이어 수치 연동

배경과 목표​

선박에서 장비를 업그레이드하면 목록의 숫자만 바뀌는 것이 아니라 다음 잠수의 산소량·최대 수심·적재 한도까지 달라져야 한다. 장비 선택, 현재·다음 레벨 비교, 비용 확인, 결과 알림이 서로 다른 화면에 있어도 같은 상태를 보여 주는 것이 중요했다.

이를 위해 iDiver 화면을 GameObject 단위로 나누고, 장비별 레벨 정의와 현재 진행 상태를 UI 객체 밖에 두었다. UI는 이 데이터를 읽어 표시하고, 구매 시 레벨과 플레이어 설정을 변경한다.

이 글은 본인이 작성한 iDiver UI·장비 정보와 능력치 연결 부분을 다룬다. 플레이어의 이동·전투 구현이나 공동 관리된 CGameMemMgr 전체를 본인 구현 범위로 포함하지 않는다.

화면을 역할별 객체로 구성​

구성 요소담당 역할
CShipPhoneIDiverBG네 장비 목록 구성, 선택 위치와 비교 창 열기
CShipPhoneIDiverItem현재·다음 레벨 표시와 선택용 AABB
CShipPhoneIDiverSelectEdge선택 항목 테두리
CShipPhoneIDiverUpgrade비교 화면, 구매 입력, 상태 변경
CShipPhoneIDiverUpgradeBtn구매 가능 여부에 따른 버튼 이미지
CShipPhoneIDiverUpgradeSuccess변경된 레벨·수치와 성공 설명 표시

각 UI 객체는 CTransform과 사각형 버퍼를 사용하는 GameObject다. 아이콘·버튼에는 부모를 설정해 화면의 구성 요소로 연결하면서, Scene의 0_GameLogic_Layer에도 등록해 Update와 Render 경로에 참여시킨다.

비교 창은 Create() 후 선택 장비의 Asset Name을 설정하고 Ready_AfterCreate()에서 버튼과 아이콘을 만든다. 즉, 공통 컴포넌트 초기화와 선택 장비가 정해진 뒤의 화면 구성을 나눈 방식이다. 생성만으로 준비가 모두 끝나는 API는 아니므로 호출 순서가 필요하다.

장비 정의와 현재 상태 분리​

장비 정보는 IDiverInfo.cpp의 중첩 Map에 정의했다.

Plain Text
장비 Asset Name → Level → IDIVER_INFO

IDIVER_INFO에는 단계·비용·실제 능력치인 iAmount와 화면에 사용할 제목·레벨명·단위·설명·성공 메시지가 함께 들어간다. 산소통, 잠수복, 화물함, 작살의 네 초기화 함수가 레벨별 정보를 채운다.

예를 들어 산소통은 1레벨의 능력치가 90, 2레벨이 115이며 2레벨 비용은 65다. 목록과 비교 창은 동일한 정의에서 현재 레벨과 다음 레벨을 조회하고, 성공 창은 변경된 현재 레벨을 다시 조회한다.

반면 현재 장비 레벨·보유 금액·플레이어 설정은 CGameMemMgr에서 조회한다. UI 객체가 닫혀도 그 객체의 멤버에만 진행 상태가 남는 구조가 아니다. 이 분리는 메모리상의 상태 유지이며, 디스크 저장 기능을 의미하지 않는다.

장비 식별자로 텍스처 Asset Name을 함께 사용하는 것은 당시 구현을 단순하게 만든 선택이다. 다만 이미지 이름 변경이 게임 데이터 조회에도 영향을 주므로 독립적인 장비 ID를 둔 구조와는 구분한다. 레벨 정의 역시 외부 JSON이 아니라 C++ 초기화 코드다.

마우스 선택을 UI 항목에 연결​

장비 항목은 AABB_IDiverItem 태그의 AABB를 만들고, Update에서 자신의 World Matrix로 변환해 Coll_IDiver 그룹에 등록한다.

배경 객체의 LateUpdate는 마우스 위치에서 Ray를 만들고 그룹의 Collider와 교차 검사한다. 클릭한 Collider의 사용자 포인터에서 항목 Index를 얻어 선택 위치를 갱신한다.

  • 다른 항목을 클릭하면 해당 항목으로 선택을 옮긴다.
  • 이미 선택된 항목을 클릭하면 비교 창이 있는지 확인한 뒤 생성한다.
  • 처음 선택 Index가 0이므로 첫 항목은 최초 클릭부터 비교 창이 열릴 수 있다.

따라서 시간 간격을 판정하는 더블클릭 시스템이 아니라, 현재 선택 상태에 따른 클릭 분기다. 테두리는 네 Index에 대응하는 고정 위치로 이동한다. 범용 자동 레이아웃이나 최근접 UI Ray Hit 정렬을 구현한 것으로 설명하지 않는다.

비교 화면과 구매 처리​

의도한 사용자 흐름은 다음과 같다.

Plain Text
장비 선택 → 현재·다음 레벨 비교
  → Space로 구매 → 비용·레벨·능력치 변경
  → 성공 화면 확인 → Space로 닫기

비교 창은 현재 장비 레벨과 보유 금액을 읽어 구매 버튼의 일반 이미지 또는 비활성 이미지를 선택한다. 실제 구매 입력은 버튼 객체가 아니라 비교 창의 Key_Down(DIK_SPACE) 분기가 처리한다. C 입력은 비교 창을 닫는 데 사용한다.

현재 코드의 실행 순서는 다음과 같다. 아래 순서는 개선안을 대신 적은 것이 아니라 구현된 순서다.

  1. 성공 창의 존재 여부를 확인한다.
  2. 성공 창이 없는 상태에서 Space 입력을 받는다.
  3. 보유 금액이 다음 레벨 비용보다 큰지 비교한다.
  4. 금액을 차감한다.
  5. 현재 단계가 종료 단계가 아니면 레벨을 증가시키고 능력치를 기록한다.
  6. 성공 창을 생성하고 기존 비교 창에 Set_DeadCascade()를 요청한다.

성공 창은 비교 창의 부모를 자신의 부모로 사용한다. 교체되는 비교 창의 자식으로 생성하지 않아, 비교 창을 닫는 계층 정리와 성공 화면의 수명을 분리한다.

목록·비교·성공 창은 장비 정보를 다시 조회하므로 문자열을 각 화면에 따로 수동 갱신할 필요가 줄어든다. 생성부에는 임시 제목·수치 Setter 호출도 남아 있지만, 주요 표시 경로는 IDiver::Get_Info()의 값을 사용한다.

구매 결과를 다음 잠수에 전달​

구매가 처리되면 선택 장비의 새 iAmount를 플레이어 설정에 기록한다.

장비UI에서 기록하는 값확인한 소비 경로
산소통Set_GonggiVolume()잠수 Scene 준비 시 CDiveDave::Set_MaxHp()
잠수복Set_JamsuDepth()잠수 Scene 준비 시 Set_MaxDepth()
화물함Set_JeokjaeWeight()잠수 Scene 준비 시 Set_MaxStorageWeight()
작살Set_JaksalDamage()설정 기록까지 확인; 전투 피해 반영은 별도 확인 필요

CDive::Ready_Scene()에서 추가한 연결 코드는 다음과 같다.

CDive.cpp · 능력치 연결 부분
const auto daveInfo = CGameMemMgr::GetInstance()->Get_DaveInfo();
pDave->Set_MaxHp(daveInfo.Get_GonggiVolume());
pDave->Set_MaxDepth(daveInfo.Get_JamsuDepth());
pDave->Set_MaxStorageWeight(daveInfo.Get_JeokjaeWeight());

이 부분은 본인 커밋 7ce2d01에서 확인된다. 플레이어 객체가 준비된 뒤 설정을 전달하는 연결이며, 플레이어 자체의 산소 소비·수심 판정·중량 처리 구현을 이 문서의 기여로 포함하지 않는다.

작살 설정은 같은 구매 분기에 저장되지만 위 세 Setter와 동일한 전투 적용 경로는 확인되지 않았다. 따라서 네 장비 모두 실제 전투까지 완전히 연동되었다고 일반화하지 않는다.

이미지와 텍스트 배치​

이미지는 DirectX 9의 World Transform과 Texture를 설정한 후 사각형 버퍼로 그린다. 비교 창의 크기는 텍스처 폭·높이를 기준값 284·260으로 나누어 계산하며, 버튼·아이콘·선택 테두리는 고정 상대 위치를 사용한다.

문자는 UI 위치에 항목별 Offset을 더하고 CHelper::GetScreenPointFromWorld()로 화면 좌표를 구한 뒤 Font 리소스로 출력한다. 비교 창은 현재 레벨과 다음 레벨의 값, 비용과 설명을 배경 이미지 위에 배치한다.

m_fViewZ와 RENDER_ALPHA 등록으로 화면 요소의 렌더 순서에 참여한다. 웹 UI처럼 문서 흐름에 따라 배치하는 시스템이 아니라, 게임의 Transform·렌더 그룹·폰트 출력을 조합한 화면이다.

결과와 한계​

핵심은 장비 정의를 여러 화면에서 공유하고, 구매 결과를 UI 안에만 두지 않고 다음 잠수의 플레이어 설정까지 전달한 것이다. 소스 점검에서는 아래 경계도 확인했다. 이 문서 작성 과정에서 게임 코드를 수정하지는 않았다.

  • 비용 비교가 >=가 아니라 >이므로 비용과 같은 금액만 가진 경우 구매되지 않는다.
  • 비교 창의 비용 글자 색은 현재 레벨 비용을 보고, 표시 금액과 구매 판정은 다음 레벨 비용을 본다. 색과 구매 가능 여부가 다를 수 있다.
  • 최대 단계 검사가 금액 차감보다 뒤에 있고, Get_Info()는 Map의 operator[]로 조회한다. 없는 다음 레벨을 읽을 때 기본 항목이 삽입될 수 있어, 조회·검증·차감 순서의 보강이 필요하다.
  • 창 존재 여부를 태그 조회와 bool로 판단한다. 중앙 집중식 모달 입력 관리가 아니므로 성공 창이 열린 동안 배경 입력까지 모두 차단된다고 보장할 수는 없다.

다시 설계한다면 읽기 전용 장비 조회와 TryUpgrade() 같은 상태 변경 함수를 나누고, 최대 단계·정확한 비용을 먼저 검증한 뒤 한 번만 반영하는 방식으로 정리할 수 있다. 이는 개선 방향이지 현재 적용한 구현은 아니다.

시연·검증 자료​

포트폴리오에는 다음 장면을 이어 붙이면 화면 제작과 실제 게임 데이터 연동을 함께 설명할 수 있다. 현재 목록은 촬영·검증할 항목이며 실행 검증 완료를 뜻하지 않는다.

  1. 장비 선택 후 현재·다음 단계 비교 화면을 연다.
  2. 구매 전후 금액·레벨·수치와 성공 메시지를 보여 준다.
  3. 비교 창을 닫았다 다시 열어 변경된 값을 확인한다.
  4. 잠수에 진입해 산소량·최대 수심·적재 한도 설정을 확인한다.
  5. 비용 직전·동일·초과 금액, 최대 단계와 팝업 중 입력을 별도 검사한다.
