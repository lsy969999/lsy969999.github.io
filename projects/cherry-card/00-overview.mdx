# C\*erry Card 관리자페이지 충전·환불 업무 구현

## 개요 {/* #article-introduction */}

C\*erry Card는 경제적 지원이 필요한 아동이 교육·식사 등에 사용할 수 있는 선불형 기부카드다. 매일 사용한 금액을 보충하되, 충전 후 잔액이 최대 보유 한도인 50만 원을 넘지 않도록 관리한다.

관리자페이지에서 자동충전과 환불 대상을 계산하고 카드사에 전달할 요청 데이터를 구성했다. 기관의 예치금, 카드별 한도, 여러 지원 사례와 처리 이력을 함께 반영해야 했다.

| 항목 | 내용 |
| --- | --- |
| 경력 구간 | 2020.10 – 2022.12, 이\*넷 C\*erry 부서 |
| 주요 기술 | Spring Boot, PostgreSQL, SQL |
| 핵심 작업 | 자동충전 대상·금액 계산, 환불 대상 선정, 외부 전문 연계 |
| 고려한 데이터 | 기관 예치금, 카드와 사례의 관계, 충전·환불·승인·취소 이력 |

## 추천 문서 {/* #먼저-읽을-대표-사례 */}

### 자동충전 대상 선정과 한도·잔액 계산

하나의 카드에 여러 사례의 요청이 연결되고, 기관 예치금과 카드 한도를 동시에 지켜야 했다. CTE로 계산 단계를 나누고 윈도 함수로 카드별·기관별 누적 요청을 계산했다.

[계산 단계와 가상 금액 예시 읽기](/projects/cherry-card/automatic-charge)

최초 충전 요청과 예치금 경계 조건까지 나누어 금액을 계산했다.

## 역할 분담 {/* #담당-작업의-경계 */}

| 단계 | 구성 |
| --- | --- |
| 내부 계산 | 업무 상태와 거래 이력으로 충전·환불 후보를 구하는 SQL |
| 요청 구성 | 최초 요청 분리와 충전·환불 결과의 구분 |
| 외부 연계 | 고정 길이 텍스트 전문 형식의 카드사 연계 업무 |

## 관련 문서 {/* #이어서-읽기 */}

[환불 대상 선정과 카드사 전문 연계](/projects/cherry-card/refund-message-integration)에서는 해지·거래 이력에 따른 환불 후보 선정과 외부 요청 데이터의 경계를 다룬다. 자동충전 문서와 함께 읽으면 금액 계산부터 충전·환불 요청 구성까지 이어진다.

같은 팀의 기부 플랫폼 기능은 [C\*erry](/projects/cherry/overview), 팀 공통 배포 업무는 [배포·브랜치 관리](/projects/cherry/release-branch-management)에 정리했다.
