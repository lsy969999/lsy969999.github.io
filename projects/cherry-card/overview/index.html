C*erry Card 관리자페이지 충전·환불 업무 구현

개요​

C*erry Card 관리자페이지에서 자동충전과 환불 대상을 계산하고 외부 카드사 연계에 필요한 데이터를 다루는 작업을 수행했다. 기관의 예치금, 카드별 한도, 여러 지원 사례와 처리 이력을 함께 반영해야 하는 업무였다.

항목내용
경력 구간2020.10 – 2022.12, 이*넷 C*erry 부서
주요 기술Spring Boot, PostgreSQL, SQL
핵심 작업자동충전 대상·금액 계산, 환불 대상 선정, 외부 전문 연계
고려한 데이터기관 예치금, 카드와 사례의 관계, 충전·환불·승인·취소 이력

추천 문서​

자동충전 대상 선정과 한도·잔액 계산​

하나의 카드에 여러 사례의 요청이 연결되고, 기관 예치금과 카드 한도를 동시에 지켜야 했다. CTE로 계산 단계를 나누고 윈도 함수로 카드별·기관별 누적 요청을 계산했다.

계산 단계와 가상 금액 예시 읽기

업무 규칙을 데이터 처리 단계로 나누는 역량을 보여 주는 사례다. 최초 충전 요청의 분리와 예치금 경계 조건도 포함하며, 대상 선정 SQL만으로 동시 실행과 재전송까지 해결했다고 설명하지 않는다.

담당 작업의 경계​

단계이 문서에서 설명하는 범위
내부 계산업무 상태와 거래 이력으로 충전·환불 후보를 구하는 SQL
요청 구성최초 요청 분리와 충전·환불 결과의 구분
외부 연계고정 길이 텍스트 전문 형식의 카드사 연계 업무
검증이 필요한 영역동시 배치 실행, 외부 재전송, 최종 정산과 대사 전체의 보장

대상 선정 SQL이 있다는 것과 금융 처리 전 과정의 정확히 한 번 실행을 보장한다는 것은 다르다. 공개 문서는 남아 있는 구현과 기록이 뒷받침하는 범위까지만 설명한다.

관련 문서​

환불 대상 선정과 카드사 전문 연계에서는 해지·거래 이력에 따른 환불 후보 선정과 외부 요청 데이터의 경계를 다룬다. 자동충전 문서와 함께 읽으면 금액 계산부터 충전·환불 요청 구성까지 이어진다.

같은 팀의 기부 플랫폼 기능은 C*erry, 팀 공통 배포 업무는 배포·브랜치 관리에 정리했다.

작성 근거와 확인 범위​

당시 업무 노트의 자동충전 SQL과 외부 카드사 전문 연계 기록을 기준으로 작성했다. 설명용 금액은 실제 고객 데이터가 아닌 가상 예시다. 운영 테이블명, 카드 식별자, 내부 상태 코드와 전문 명세 원문은 공개하지 않는다. 이번 정리 과정에서 운영 배치 실행이나 금융 데이터 검증을 새로 수행한 것은 아니다.
