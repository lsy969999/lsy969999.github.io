# 환불 대상 선정과 카드사 전문 연계

## 개요 {/* #article-introduction */}

자동충전과 함께 해지 카드의 환불 대상을 선정하는 로직을 다뤘다. 카드가 해지 상태라는 이유만으로 매번 환불 요청을 만들면 안 되므로, 상태 변경일과 기존 환불 이력을 함께 확인했다. 내부 계산 결과는 외부 카드사 연계에서 사용하는 요청 데이터와 구분해 다뤘다.

## 환불 대상의 조건

원본 SQL의 환불 CTE는 다음 조건을 함께 적용한다.

| 검사 | 원본에서 확인되는 처리 |
| --- | --- |
| 카드 상태 | 해지 상태인 카드 선정 |
| 변경 시점 | 전일 상태 변경 대상 선정 |
| 사례 연결 | 해당 필터 결과에서 카드가 하나의 사례에 연결된 대상만 유지 |
| 환불 금액 | 완료된 충전·환불 및 승인·취소로 계산한 금액이 양수인지 확인 |
| 관련 이력 | 갱신할 자동충전 이력이 존재하는지 확인 |
| 중복 후보 제외 | 같은 카드에 기존 유효 환불 요청·완료 이력이 없는지 확인 |

전일 상태 변경 조건은 해지된 카드를 매번 다시 고르지 않기 위한 필터다.

## 충전 가능액과 환불 가능액의 차이

환불은 실제로 남은 금액을 반환하는 작업이므로 충전 후보 계산과 동일한 상태 집계를 그대로 사용하지 않는다. 원본은 환불 금액을 구할 때 충전 완료 이력을 기준으로 합산한다.

```text
환불 후보 금액
  = 완료 충전 - 완료 환불 - 승인 + 승인 취소
```

계산한 금액이 양수인 대상만 남긴다. 여기에 해지 상태·사례 연결·기존 요청 여부 조건을 더해 환불 후보를 만든다. 금액 계산이 가능하다는 것과 최종 환불 요청을 보낼 수 있다는 것은 별개의 검사다.

## 충전과 환불 결과를 같은 출력 구조로 구성

원본 SQL은 충전과 환불 CTE에서 만든 결과를 합치고, 각 행의 요청 종류를 구분한다. 최초 충전의 1원 분리처럼 실제 요청 금액과 내부 계산 금액을 구분할 필요가 있는 데이터도 유지한다.

대상 선정 결과를 후속 연계 단계에서 사용할 수 있는 행 데이터로 구성한다.

## 외부 전문과의 경계

BC카드의 고정 길이 텍스트 전문 규격에 맞춰 충전·환불 요청 파일을 구성했다. DB에서 대상을 계산하는 부분과 외부 규격에 맞춰 파일을 생성하는 부분을 나눴다.

```text
상태·거래 이력 조회 → 충전/환불 후보와 금액 계산 → 외부 전문 규격에 맞춘 요청 구성
```

## 구현 결과 {/* #회고-후보-제외와-중복-실행-방지는-다르다 */}

해지 상태와 지원 사례의 연결 관계, 거래 상태를 함께 반영해 환불 대상을 선정하고 외부 카드사 연계에 필요한 데이터를 구성했다.
