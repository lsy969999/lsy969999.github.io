# Flappy Bird 프로젝트 개요와 기술 문서 안내

## 개요 {/* #article-introduction */}

Rust와 Bevy로 Flappy Bird의 한 판 플레이를 구현하고, 공통 게임 코드를 Desktop·Android·iOS·Web 진입점에 연결한 개인 프로젝트다. 클릭으로 새를 띄우는 조작뿐 아니라 안내·일시정지·득점·결과 UI·기록 저장과 실행 환경 구성을 함께 다뤘다.

| 구현 범위 | 게임 진행, UI·애니메이션, 플랫폼 FFI, 빌드·배포 연결 |
| 플랫폼 구성 | Desktop · Android · iOS · Web |
| 후속 작업 | 2025년 GitHub Pages 배포 구성과 웹 경로·화면 보정 |

Bevy와 Avian2D, 원작 리소스를 활용해 게임 시스템을 구성하고 여러 플랫폼의 실행 환경에 연결했다.

## 핵심 구현

### 1. ECS로 한 판의 실행 조건 구분

State로 안내·플레이·정지·결과 구간을 나누고, Event로 충돌 결과를 점수와 화면 전환에 전달했다. 새는 물리 임펄스로 상승하고 파이프는 두 쌍을 재배치해 사용한다. 장애물 접촉과 득점 통과를 서로 다른 역할의 센서로 구분했다.

### 2. 화면 배치와 결과 연출 연결

144×256 기준 좌표를 부모 Transform 배율로 맞추고 주변을 마스크 Sprite로 가렸다. 충돌 플래시, Game Over 문구, 점수 패널, 카운트와 메달을 Tween 완료 이벤트와 Timer로 연결해 결과를 단계적으로 보여 주도록 구성했다.

### 3. 플랫폼 저장소와 콜백 통합

공통 `Ffi::get/set`에서 JSON 최고 점수를 사용하고, 파일·SharedPreferences·UserDefaults·localStorage로 각각 연결했다. 네이티브·JavaScript에서 돌아오는 응답은 채널에 넣어 Bevy 갱신 흐름으로 전달했다.

### 4. 공통 게임을 실행 가능한 결과물로 전달

Android 공유 라이브러리, iOS 정적 라이브러리, WebAssembly를 각 호스트가 사용하는 형식으로 만들고 에셋을 배치했다. 이후 Web 빌드와 Pages 게시를 GitHub Actions로 연결했다. 모바일 스토어 배포까지 자동화한 것은 아니다.

## 기술 문서 읽는 순서

전체 흐름은 아래 순서로 읽으면 된다. 각 문서는 구현 상세와 현재 코드의 제한을 함께 설명한다.

1. [입력·충돌·게임 진행](/projects/flappy-bird/ecs-gameplay-loop) — 입력이 물리 이동으로 바뀌고, 충돌이 점수·게임 종료로 이어지는 과정을 설명한다.
2. [화면 대응과 결과 UI 연출](/projects/flappy-bird/responsive-result-animation) — 기준 좌표, 부모 계층, Tween 완료 이벤트로 화면과 피드백을 구성한 방법을 설명한다.
3. [플랫폼 FFI와 최고 점수 저장](/projects/flappy-bird/ffi-score-storage) — JNI·Swift C ABI·wasm-bindgen 경계와 콜백 전달, 문자열 소유권 문제를 설명한다.
4. [빌드·패키징과 Web 배포](/projects/flappy-bird/build-packaging-web-deploy) — 같은 게임을 플랫폼별 바이너리·에셋·호스트에 연결하고 배포하는 과정을 설명한다.

## 구현 범위 {/* #구현-범위와-검증-수준 */}

게임과 UI는 한 개의 플레이 화면을 기준으로 구성했다. 파이프는 두 쌍을 번갈아 재배치해 사용한다.
