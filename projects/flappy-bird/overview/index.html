Flappy Bird 프로젝트 개요와 기술 문서 안내

개요​

Rust와 Bevy로 Flappy Bird의 한 판 플레이를 구현하고, 공통 게임 코드를 Desktop·Android·iOS·Web 진입점에 연결한 개인 프로젝트다. 클릭으로 새를 띄우는 조작뿐 아니라 안내·일시정지·득점·결과 UI·기록 저장과 실행 환경 구성을 함께 다뤘다.

항목내용
초기 개발 기간2024.08.23 – 2024.09.01
개발 인원1명 · 임성윤
주요 기술Rust 2021, Bevy 0.14.1, Avian2D 0.1.2
구현 범위게임 진행, UI·애니메이션, 플랫폼 FFI, 빌드·배포 연결
플랫폼 구성Desktop · Android · iOS · Web
후속 작업2025년 GitHub Pages 배포 구성과 웹 경로·화면 보정

작은 게임 규칙을 여러 환경에서 사용할 수 있는 구조로 연결한 경험에 초점을 맞췄다. Bevy·Avian2D 자체나 원작 리소스를 제작한 기여와, 이를 활용해 게임 시스템을 구성한 기여는 구분한다.

핵심 구현​

1. ECS로 한 판의 실행 조건 구분​

State로 안내·플레이·정지·결과 구간을 나누고, Event로 충돌 결과를 점수와 화면 전환에 전달했다. 새는 물리 임펄스로 상승하고 파이프는 두 쌍을 재배치해 사용한다. 장애물 접촉과 득점 통과를 서로 다른 역할의 센서로 구분했다.

2. 화면 배치와 결과 연출 연결​

144×256 기준 좌표를 부모 Transform 배율로 맞추고 주변을 마스크 Sprite로 가렸다. 충돌 플래시, Game Over 문구, 점수 패널, 카운트와 메달을 Tween 완료 이벤트와 Timer로 연결해 결과를 단계적으로 보여 주도록 구성했다.

3. 플랫폼 저장소와 콜백 통합​

공통 Ffi::get/set에서 JSON 최고 점수를 사용하고, 파일·SharedPreferences·UserDefaults·localStorage로 각각 연결했다. 네이티브·JavaScript에서 돌아오는 응답은 채널에 넣어 Bevy 갱신 흐름으로 전달했다.

4. 공통 게임을 실행 가능한 결과물로 전달​

Android 공유 라이브러리, iOS 정적 라이브러리, WebAssembly를 각 호스트가 사용하는 형식으로 만들고 에셋을 배치했다. 이후 Web 빌드와 Pages 게시를 GitHub Actions로 연결했다. 모바일 스토어 배포까지 자동화한 것은 아니다.

기술 문서 읽는 순서​

전체 흐름은 아래 순서로 읽으면 된다. 각 문서는 구현 상세와 현재 코드의 제한을 함께 설명한다.

  1. 입력·충돌·게임 진행 — 입력이 물리 이동으로 바뀌고, 충돌이 점수·게임 종료로 이어지는 과정을 설명한다.
  2. 화면 대응과 결과 UI 연출 — 기준 좌표, 부모 계층, Tween 완료 이벤트로 화면과 피드백을 구성한 방법을 설명한다.
  3. 플랫폼 FFI와 최고 점수 저장 — JNI·Swift C ABI·wasm-bindgen 경계와 콜백 전달, 문자열 소유권 문제를 설명한다.
  4. 빌드·패키징과 Web 배포 — 같은 게임을 플랫폼별 바이너리·에셋·호스트에 연결하고 배포하는 과정을 설명한다.

시간이 짧다면 1번과 3번을 먼저 읽으면 게임 로직 구성과 플랫폼 통합 경험을 볼 수 있다. UI 구현에 관심이 있다면 2번을, 실행 결과물과 배포 과정에 관심이 있다면 4번을 이어 읽으면 된다.

구현 범위와 검증 수준​

게임과 UI는 한 개의 플레이 화면을 전제로 한 구현이며, 범용 엔진이나 연출 편집기로 소개하지 않는다. 파이프 재사용 역시 이 게임의 두 쌍을 순환시키는 구조이지 범용 풀 매니저는 아니다.

플랫폼 연결 코드에는 iOS 문자열 소유권, FFI 이벤트 종류 분기, 빌드 실패 처리처럼 보강이 필요한 부분이 남아 있다. 일반 결과 화면의 광고 버튼 생성은 비활성화된 상태이며, 연결 테스트·호스트 코드가 남아 있다는 사실과 일반 플레이의 활성 기능을 구분한다.

문서 내용은 현재 소스와 Git 이력을 기준으로 정리했다. 이번 포트폴리오 작성 과정에서 게임 실행, 모바일 실기기 검증, 저장 테스트, 신규 배포나 성능 측정은 수행하지 않았다. 성능 향상률·모든 기기 지원·저장 안정성 보장 같은 검증되지 않은 성과는 적지 않았다.

검증 계획​

다음 세 장면을 짧게 묶으면 문서의 구현 설명을 보여 주기 좋다. 아직 이 개요에 새 시연 자료를 추가한 것은 아니다.

  • 첫 입력부터 파이프 통과, 일시정지·재개, 충돌과 결과 표시까지 한 판의 흐름.
  • 창 비율을 바꿨을 때 플레이 영역과 UI 배치가 유지되는 모습.
  • 기록 저장 후 재실행과 플랫폼별 동일한 게임 흐름을 보여 주는 장면.

개발 기간과 인원은 저장소 README를, 세부 기여와 후속 배포 작업은 각 기술 문서에 기재한 소스·커밋을 기준으로 확인했다.
