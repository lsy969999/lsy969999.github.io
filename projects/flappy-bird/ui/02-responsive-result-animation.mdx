# 기준 해상도 대응과 Tween 이벤트 기반 결과 UI 연출

## 화면 배치와 게임 종료 피드백 구성

FlappyBird에서는 플레이 가능한 영역의 비율을 유지하면서 창 크기 변화에 대응해야 했다. 게임이 끝났을 때도 점수만 즉시 표시하는 대신, 충돌 플래시와 Game Over 문구, 점수판 이동, 점수 카운트, 메달이 순서대로 나타나도록 구성했다.

이 작업은 **기준 좌표계와 부모 Transform으로 화면 배치를 유지하고, Tween 완료 이벤트와 Timer를 조합해 결과 UI의 등장 순서를 제어한 구현**이다. Sprite 기반 게임 화면에 필요한 연출을 ECS로 구성했다.

## 144×256 기준 좌표를 부모 배율로 조정

`ORIGINAL_WIDTH`와 `ORIGINAL_HEIGHT`는 각각 144와 256이다. 화면 리사이즈 시 창의 너비·높이가 기준 해상도의 몇 배인지 계산하고, 작은 쪽을 공통 배율로 사용한다.

```rust
let scale_x = window.width() / ORIGINAL_WIDTH;
let scale_y = window.height() / ORIGINAL_HEIGHT;
let scale = scale_x.min(scale_y);
```

`Resizable`이 붙은 엔티티의 Transform X·Y 스케일을 이 값으로 바꾸고 Z 스케일은 유지한다. 게임 화면에서는 배경 루트가 이 역할을 맡고, 새·지면·파이프·버튼·점수와 결과 패널을 자식으로 배치한다. 개별 UI 좌표를 창 크기에 맞춰 각각 다시 계산하기보다 부모 배율을 상속하도록 한 것이다.

예를 들어 288×512 창에서는 배율이 2이고, 512×512 창에서도 높이가 제한하므로 배율은 2다. 후자의 플레이 영역은 288×512를 유지하며 양옆에 여유가 생긴다. 이는 직사각형 영역을 창 안에 비율 유지해서 맞추는 방식이지, 가로·세로를 서로 다른 비율로 늘리는 방식이 아니다.

`ResizePlugin`은 운영체제의 `WindowResized`뿐 아니라 프로젝트의 `ResizeEvent`도 처리한다. `game_enter()`에서 화면 엔티티를 생성한 후 내부 이벤트를 보내므로, 사용자가 창을 다시 조절하지 않아도 새 화면에 배율을 적용할 수 있다. 같은 갱신에서 들어온 여러 리사이즈 이벤트는 플래그로 모아 한 번 계산한다.

배율은 `ResizeScale` Resource에도 저장하고 중력 크기 조정에 사용한다. 입력 임펄스와의 연결은 앞선 게임 진행 문서에서 다뤘으며, 여기서는 UI 배치와 같은 배율을 공유한다는 점이 중요하다.

## 바깥 마스크와 전환 마스크 구분

`spawn_mask()`는 별도의 Resizable 부모 아래에 마스크 Sprite 다섯 개를 만든다.

| 구성 | 목적 |
| --- | --- |
| 왼쪽·오른쪽 | 기준 영역 양옆을 회색 Sprite로 덮기 |
| 위쪽·아래쪽 | 기준 영역 위아래를 회색 Sprite로 덮기 |
| MaskCenter | 평소에는 투명하게 두고 화면 전환·충돌 플래시에 사용 |

주변 마스크는 기준 사각형 경계 바깥에 위치한다. `MaskCenter`는 144×256 크기이며, 연출할 때 Z를 앞으로 이동시키고 색상·알파를 Tween으로 바꾼다. 완료 콜백에서는 다시 뒤쪽으로 이동시킨다.

화면 앞에 Sprite를 그려 기준 영역 밖을 가린다.

## 전환이 끝난 시점에 다음 화면 생성

메뉴에서 게임으로 이동할 때 중앙 마스크를 0.5초 동안 투명에서 검정으로 바꾸고, 이어 0.5초 동안 다시 투명하게 만든다. 첫 Tween 완료에 `TWEEN_MENU_TO_GAME`을 붙이고 콜백에서 `Game::Init`을 예약한다. 검게 가려진 시점에 게임 화면 생성을 연결하는 구조다.

`TweenCallbackPlugin`에 등록된 시스템들은 `TweenCompleted`를 읽고 `user_data` 값을 비교한다. 화면을 생성하는 함수에서 매 프레임 경과 시간을 확인하는 대신, 필요한 연출 완료를 이벤트로 전달한다.

이벤트 값은 프로젝트의 상수로 구분하며 콜백은 전역 Query로 마스크·패널을 찾는다. 따라서 독립적인 결과 창 여러 개를 동시에 재생하는 범용 연출 인스턴스 시스템보다는, 한 개의 게임 화면을 전제로 한 구현이다.

## 결과 화면의 단계별 등장

충돌 시 `on_result()`가 중앙 마스크를 0.3초 동안 흰색으로 만들고, 다음 0.3초 동안 투명하게 되돌린다. 이 과정의 마지막에 `TWEEN_DEATH_WHITE`를 보낸다.

Tween과 Timer에 지정한 시간에 따라 다음 순서로 재생한다.

| 충돌 기준 시점 | 연출과 연결 |
| --- | --- |
| 0~0.6초 | 흰색 플래시가 나타났다가 사라짐 |
| 약 0.6초 | 완료 콜백에서 결과 계층 생성·사망 효과음 재생 |
| 약 0.6~1.1초 | Game Over 문구의 위치 Tween, 별도로 0.3초 알파 증가 |
| 약 1.1~1.6초 | 0.5초 대기한 점수 패널이 Y -300에서 0까지 상승 |
| 약 1.6초 | 패널 완료 이벤트에서 점수 카운트와 보상 표시 예약 |
| 약 2.6초 이후 | OK 버튼·메달·신기록 표시·반짝임이 각자의 지연 후 등장 |

Game Over 문구는 부모에 위치 Animator를 두고 자식 Sprite에 색상 Animator를 둔다. 부모가 Y 55→60→50으로 움직이는 동안 자식은 투명에서 흰색으로 바뀐다. 계층을 이용해 이동과 페이드를 함께 재생한 것이다.

점수 패널은 `Delay`와 위치 Tween을 `.then()`으로 연결하고, 이동 완료에 `TWEEN_PANEL_UP_END`를 보낸다. 이 콜백에서 다음 단계의 엔티티와 Timer를 추가한다. 결과 화면 전체에 하나의 거대한 경과 시간 분기를 두는 대신 단계 완료를 연결 지점으로 삼았다.

## 폰트 대신 숫자 Sprite로 점수 표시

현재 점수와 최고 점수는 숫자 이미지들을 자식 엔티티로 나열한다. 결과 화면에서는 중간 크기 숫자를 8 단위 간격으로 배치하고, 자릿수에 따른 전체 폭의 절반을 빼서 기준 X 37 주변으로 정렬한다.

점수 증가 연출을 시작할 때 반복 Timer 간격을 `1000 / (score + 1)` 밀리초로 정한다. 0부터 목표 점수까지 약 1초에 걸쳐 보여주려는 설정이다. 매 타이머 완료 시 기존 숫자 자식을 제거하고 현재 표시할 숫자 Sprite를 다시 생성한다.

최고 기록은 패널 완료 콜백에서 FFI 저장소의 `score`를 읽어 비교한다. JSON 해석에 실패하면 기존 기록을 0으로 취급하며, 새 기록이면 표시 애니메이션이 끝나기 전에 실제 점수를 저장한다. 화면의 카운트와 저장 데이터 갱신 시점을 분리한 셈이다. 플랫폼별 저장 구현은 이 문서의 범위에서 제외한다.

점수 카운트는 Timer의 `just_finished()`가 참일 때 한 단계씩 진행한다.

버튼과 메달은 점수 카운트와 별개로 1초 Delay 이후 등장한다.

## 메달과 신기록에 추가 피드백 부여

메달은 실제 최종 점수를 기준으로 선택한다. 현재 기준은 동메달 1점, 은메달 20점, 금메달 30점, 플래티넘 40점이다. 동메달 기준 미만이면 메달과 반짝임 계층을 붙이지 않는다.

OK 버튼과 메달의 등장은 알파 페이드가 아니라 Z 위치를 뒤에서 앞으로 이동시키는 방식이다. 반면 신기록 `new` 표시는 새 기록일 때만 생성하고, 1초 대기 후 0.1초 동안 알파를 올린다. 서로 다른 연출 수단을 사용하므로 모두 같은 페이드 처리로 묶지는 않는다.

OK 버튼에는 Pointer Down에서 Y를 1만큼 내리고 Up·DragEnd에서 되돌리는 반응을 넣었다. 클릭하면 메뉴 복귀 이벤트를 보내며, 화면 전환 마스크와 연결된다. 광고 버튼을 구성하는 코드는 남아 있지만, 생성하는 부분이 주석 처리되어 결과 화면에는 표시되지 않는다.

## Atlas와 Timer로 날개·반짝임 반복

자산 생성 단계에서 새 이미지 3장과 반짝임 이미지 3장을 각각 `TextureAtlasBuilder`로 묶고, 생성된 이미지와 레이아웃 Handle을 Resource에 보관한다. 매 프레임 이미지 파일을 다시 로드하는 방식이 아니다.

날개와 반짝임은 Timer가 끝날 때 `TextureAtlas.index`를 증가시키고 전체 프레임 수로 나머지를 구한다. 반짝임은 알파 등장 Tween이 끝나야 반복 Timer가 부착되며, 프레임 인덱스가 0으로 돌아올 때 위치를 X·Y 각각 `[-8, 8)`에서 다시 뽑는다. 메달 주변에서 위치를 바꾸며 빛나는 느낌을 만든다.

이들 애니메이션도 Timer 완료 여부로 한 프레임씩 진행한다. 정확한 시간 샘플링이나 누락된 프레임을 따라잡는 별도 재생기는 아니다. Atlas를 사용해 프레임별 리소스를 하나로 묶었다.
