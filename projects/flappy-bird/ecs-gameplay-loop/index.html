Bevy ECS와 Avian2D로 구성한 입력·충돌·게임 진행

작은 게임에서 한 판의 흐름 완성하기​

FlappyBird는 클릭·터치로 새를 띄우고 파이프 사이를 통과하는 개인 프로젝트다. Rust와 Bevy로 입력, 물리, 점수, 게임 종료를 연결하고, 안내 화면부터 일시정지와 결과 화면까지 한 판의 흐름을 구성했다.

핵심은 모든 동작을 하나의 갱신 함수에 넣는 대신 Component로 역할을 구분하고, State로 실행 구간을 제한하며, Event로 충돌 결과를 전달한 것이다. 현재 소스의 의존성 선언은 Bevy 0.14.1, Avian2D 0.1.2다. 여기서는 플랫폼 연결보다 실제 게임 진행 구현에 집중한다.

상태에 따라 실행되는 시스템 구분​

MyStates는 자산 로딩, 메인 메뉴, 게임 상태를 표현한다. 게임 내부는 Init, Guide, Game, GuidePause, GamePause, Result로 나눈다. 별도 하위 상태 머신이 아니라 MyStates::Game(Game::Guide)처럼 enum을 중첩한 하나의 State다.

구간주요 처리
Init배경·새·파이프·지면·안내·점수 UI를 생성하고 Guide 예약
Guide날개 애니메이션과 지면 스크롤을 실행하며 첫 입력 대기
Game파이프 이동·새의 충돌 확인·부활 연출 갱신 추가 실행
GuidePause / GamePause게임 시스템 실행 조건에서 제외하고 물리 시간·새의 회전 Tween 정지
Result게임 진행 시스템 대신 결과 점수 카운트와 반짝임 연출 실행

GamePlugin에서 run_if(in_state(...))로 실행 조건을 등록한다. ScoreUpEvent와 ResultEvent의 소비 시스템에는 .after(bird_colliding_check)를 지정해 충돌 확인 이후 결과를 처리하도록 했다.

NextState는 상태 전환을 예약하는 수단이다. 이벤트를 보냈다고 즉시 모든 시스템이 종료되거나 엔티티 변경이 동기적으로 완료되는 구조는 아니다.

첫 입력에서 안내와 실제 플레이 연결​

배경 Sprite에 On<Pointer<Down>>을 연결해 JumpPickingEvent를 보낸다. 입력 시스템은 Guide와 Game에서만 실행한다. Pause 버튼 입력이 상승 입력으로 처리되지 않도록 전달된 picking 깊이를 비교하는 예외도 있다.

Guide에서는 새를 Static 강체로 생성해 첫 입력 전에 떨어지지 않게 한다. 첫 상승 입력을 받으면 안내 엔티티를 재귀 제거하고 새를 Dynamic 강체로 바꾼 뒤 Game 상태를 예약한다. 같은 입력으로 상승까지 수행하므로 시작 버튼과 첫 점프가 분리되지 않는다.

새에는 반지름 8.5의 원형 Collider, 질량 5.0, 회전 잠금을 설정한다. 상승할 때는 이전 LinearVelocity를 0으로 바꾸고, 1000 × ResizeScale의 위쪽 ExternalImpulse를 적용하도록 Component를 삽입한다.

이는 상승 속도를 계속 누적하기보다 입력 시점마다 상승 조건을 다시 만드는 방식이다. 화면 리사이즈 처리에서는 중력도 800 × scale 크기로 설정한다. 단순한 Y좌표 덧셈이 아니라 화면 배율과 물리 설정을 함께 조정했다. 다만 이 수치만으로 모든 화면 환경에서 완전히 같은 조작감이 검증됐다고 보지는 않는다.

물리 이동과 시각적인 기울기 분리​

상승 입력에는 회전 Tween을 함께 넣는다.

  1. 0.2초 동안 위쪽 45도로 회전한다.
  2. 0.1초 대기한다.
  3. 0.3초 동안 아래쪽 90도로 회전한다.

물리 회전은 잠그고 Transform Tween으로 기울어지는 모습을 제어한다. 원형 Collider이므로 방향에 따른 충돌 외형 변화는 없으며, 실제 상승·낙하와 화면에 보이는 자세를 다른 처리로 구성할 수 있다.

입력마다 Tween을 새로 삽입하고 시작 각도를 0도로 지정하므로 현재 자세에서 항상 연속적으로 보간하는 구현은 아니다. 이 문서에서는 이를 속도 기반 자세 제어나 정교한 비행 모델로 설명하지 않는다.

파이프 두 쌍을 재사용하는 스크롤​

새의 앞쪽으로 장애물이 다가오도록 파이프 부모 Transform을 초당 50 단위씩 왼쪽으로 이동시킨다. 초기에는 X가 85와 170인 파이프 두 쌍을 생성한다. 각 부모에는 위·아래 파이프와 득점 센서를 자식으로 둔다.

왼쪽 경계인 X -85를 넘으면 같은 부모를 X 85로 옮기고 Y를 [-30, 100)에서 다시 뽑는다. 자식 센서의 득점 완료 표시도 제거해 다음 통과를 받을 수 있게 한다. 매번 파이프를 생성·삭제하지 않고 기존 엔티티를 재배치하는 작은 재사용 구조다.

지면도 별도 스프라이트를 왼쪽으로 이동시키다가 경계에서 되돌린다. 지면의 충돌체는 따로 두므로 시각적 스크롤과 바닥 충돌을 구분한다.

파이프 부모는 Static 강체지만 이동 자체는 Update의 Transform 변경으로 수행한다. 따라서 속도를 지정한 Kinematic 강체 이동이나 물리 고정 스텝 기반 장애물 제어로 설명하면 실제 코드와 다르다. 경계 재배치는 초과 이동 거리를 보존하지 않아 긴 프레임에서는 파이프 간격이 달라질 여지도 있다.

충돌 역할을 마커 Component로 구분​

bird_colliding_check()는 새의 CollidingEntities를 읽고 상대 엔티티의 Component를 조회한다.

상대 역할구성과 처리
Pipe위·아래 직사각형 Sensor. 닿으면 충돌음과 ResultEvent 발생
GroundColliderStatic 지면 Collider. 닿으면 ResultEvent 발생
PipePoint파이프 중앙의 폭 5, 높이 300인 Sensor. 통과하면 ScoreUpEvent 발생
PointEarned해당 센서에서 이미 점수를 얻었다는 표시. 다음 득점 조회에서 제외

장애물 파이프도 Sensor이므로 새를 물리적으로 밀어내는 대신 접촉을 게임 종료 조건으로 사용한다. 득점 센서 역시 물리 반응 없이 통과를 감지하지만, 별도 역할 마커를 통해 다른 게임 규칙으로 연결된다.

PointEarned는 겹쳐 있는 동안 매 프레임 점수가 증가하는 것을 막는다. 파이프 재배치 시 이 마커를 제거해 같은 센서를 다시 사용한다. 점수는 GameConfig에 누적하고 숫자 Sprite들을 갱신한다. 장애물 재사용과는 별개로 점수 UI 자식은 갱신 시 다시 생성하므로 게임 전체를 무할당 구조로 구현한 것은 아니다.

동시에 장애물과 득점 센서에 겹친 경우에는 충돌 목록 순회 중 먼저 처리된 결과가 영향을 줄 수 있다. 장애물 발견 시 반환하지만 이미 보낸 점수 이벤트를 취소하지는 않는다. 사망 프레임의 점수 우선순위까지 명시적으로 정한 구현과는 구분한다.

일시정지는 시스템 조건과 물리 시간을 함께 제어​

Pause 상태로 바꾸는 것만으로 물리나 외부 Tween까지 자동으로 멈추지는 않는다. 구현에서는 세 가지를 함께 처리한다.

  • Guide 또는 Game을 각각의 Pause 상태로 바꿔 게임 시스템 실행을 막는다.
  • Time<Physics>::pause()로 물리 진행을 멈춘다.
  • 새의 Animator<Transform>을 Paused로 바꿔 기울기 연출을 멈춘다.

재개할 때는 기존 Guide/Game 구간으로 돌아가고 물리 시간과 Animator를 다시 실행한다. 날개 애니메이션과 스크롤은 State 조건으로 정지하므로 처리 방식이 다르다. 모든 오디오·UI 연출을 일괄 정지시키는 범용 Pause 서비스는 아니다.

충돌에서 결과 화면으로 연결​

충돌 시스템은 결과 화면 자체를 생성하지 않고 ResultEvent를 보낸다. on_result()가 이를 받아 Pause 버튼을 숨기고 화면 마스크를 0.3초 동안 흰색으로, 다음 0.3초 동안 투명하게 바꾸며 Result 상태를 예약한다. Tween 완료 이벤트는 다음 결과 연출을 연결하는 지점이 된다.

메인 메뉴로 돌아갈 때는 점수와 광고 관련 상태를 초기화하고 InGame 루트 엔티티를 재귀 제거한다. 반면 Result에서 Game으로 돌아오는 경로에는 기존 판을 유지하는 부활 처리가 있으므로, 모든 재진입을 새 판 생성으로 취급하지 않는다. AdRespawn 마커가 있는 새는 일반 충돌 검사에서 제외된다.

작성 근거와 확인 범위​

이 작업의 기여는 물리 엔진을 직접 만든 것이 아니라, Bevy의 State·Event·Query와 Avian2D를 이용해 입력부터 한 판 종료까지 연결한 데 있다. 짧은 플레이 규칙에도 안내·정지·결과·재사용 수명을 구분하고 각 기능의 실행 조건을 코드로 표현했다.

분석은 현재 소스와 Git 이력을 기준으로 했으며 이번 문서화에서 게임을 실행하거나 프레임 성능을 측정하지는 않았다. TARGET_FRAME_RATE 상수는 있지만 App의 명시적인 물리 60Hz·프레임 제한 설정은 주석 상태이므로 자체 고정 60Hz 루프를 완성했다는 주장도 제외했다.

주요 소스는 src/plugins/game.rs, src/plugins/picking_callback.rs, src/systems/on_game.rs, src/systems/picking_callback.rs, src/systems/movement.rs, src/systems/bird.rs, src/systems/on_result.rs, src/systems/resize.rs다.

관련 구현 이력은 810876d의 초기 게임 작성, 9279b25의 점수 처리, f7a8afb의 새 Tween, 46163c4의 회전 잠금, a57e830의 Pause 수정이다. 모두 lsy969999 작성 이력으로 확인했다.
