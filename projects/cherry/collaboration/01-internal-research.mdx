# 사내 연구 프로젝트와 기술 지식 공유

## 개요 {/* #article-introduction */}

사내 연구 프로젝트로 Flutter와 Firebase를 연결해 데이터를 읽고 쓰고 사진을 저장하는 앱을 만들었다. 서비스 기능 개발과 별개로 새로운 기술을 작은 앱에서 다뤄 보고 관련 지식을 공유한 경험이다.

이 문서는 정규 신입 온보딩 교육 과정이 아니라 **사내 연구 프로젝트와 기술 학습·공유 활동**으로 정리한다. 원래 업무 노트의 교육 항목에 함께 기록돼 있었지만, 활동의 성격은 후속 회고를 반영해 구분했다.

## Flutter·Firebase 앱 연구

Flutter의 pub 패키지를 이용해 Firebase와 연결하고 데이터 읽기·쓰기와 사진 저장 기능을 구현하는 내용을 다뤘다. 화면만 만드는 예제를 넘어 외부 데이터 연동을 포함한 작은 앱으로 기술을 살펴본 프로젝트였다.

| 연구 내용 | 다룬 범위 |
| --- | --- |
| Flutter 앱 구성 | 앱에서 동작하는 기능 구현 |
| 패키지 연결 | pub 패키지를 이용한 Firebase 연동 |
| 데이터 처리 | 데이터 읽기·쓰기 |
| 사진 처리 | 사진 저장 기능 |

이 앱을 실제 서비스로 출시했다거나 기존 C\*erry 앱 전체를 Flutter로 전환한 것은 아니다. 당시 기록에는 Firebase의 구체적인 데이터베이스 제품과 인증·보안 규칙까지 남아 있지 않아 해당 구현을 임의로 추가하지 않았다.

## 함께 진행한 기술 학습과 공유

관련 기록에는 JWT, JPA·QueryDSL, ORM과 N+1도 남아 있다. Flutter 앱의 기능 목록과 이 학습 주제를 같은 것으로 묶지는 않는다. 특히 JPA와 QueryDSL은 관심을 갖고 공부한 내용을 공유했으며, 당시 실무 서비스에 사용한 기술은 아니었다.

ORM 개념에 대한 학습은 이후 NestJS를 공부하며 Prisma를 이해하는 데에도 도움이 됐다. 이는 기술 간 개념을 연결한 학습 경험이지, C\*erry 서비스를 NestJS·Prisma로 개발했다는 의미는 아니다.

실제 운영 DB의 조회 병목을 분석하고 인덱스를 개선한 작업은 [C\*erry Run PostgreSQL 실행계획 개선](/projects/cherry/postgresql-query-plan)에 따로 정리했다. 학습 중 다룬 N+1과 운영 중 풀스캔 대응은 서로 다른 사례다.

## 서비스 구현·업무 전달과의 구분

이 활동의 중심은 새 기술을 직접 다뤄 보고 이해한 내용을 공유한 것이다. 정해진 기수·평가·교육 과정이나 온보딩 시간 단축 성과로 소개하지 않는다.

[광고 공통 계층 설계·SDK 연계](/projects/cherry-world/ads-offerwall-integration)에서 Android 인턴 개발자에게 업무를 전달한 경험은 실제 기능 개발 과정의 협업이다. 사내 연구 프로젝트와 해당 업무 전달은 별도로 구분한다.

## 작성 근거와 확인 범위 {/* #작성-근거 */}

업무 노트에 남긴 Flutter·Firebase 앱 구현 및 JWT·JPA·QueryDSL·ORM 학습 내용과 후속 회고를 바탕으로 작성했다. Flutter 관련 활동을 사내 연구 프로젝트로 설명해 달라는 정정을 반영했다. 서비스 출시·전체 앱 전환·연구 성과 수치 등 확인되지 않은 실적은 덧붙이지 않았다.
