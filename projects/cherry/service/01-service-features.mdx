# 사용자·관리자 기능과 제휴·시즌 이벤트

## 개요 {/* #article-introduction */}

기존 기부 플랫폼에서 기능을 추가하는 작업은 화면 한 장을 만드는 것만으로 끝나지 않았다. 사용자에게 보여 줄 정보와 관리자가 수정할 데이터, 기존 페이지 흐름을 함께 고려해야 했다. 반복되는 관리자 구성은 공통화하고, 제휴·행사 화면은 각 요구사항에 맞춰 구현했다.

운영자와 요구사항을 확인하는 과정에서는 Excel로 정리할 수 있는 내용을 문서화했다. 구현뿐 아니라 반복되는 업무 협의 방식을 개선하는 작업도 함께 수행했다.

## 관리자 화면의 반복 구조

업무 기록에는 Thymeleaf와 `thymeleaf-layout` 기반으로 검색 조건과 데이터 테이블을 공통화한 내용이 남아 있다. 관리자 기능은 목록을 검색하고 결과를 확인하는 형태가 반복되므로, 각 화면을 완전히 독립적으로 만드는 대신 공통 구성을 활용했다.

| 구성 | 역할 |
| --- | --- |
| 페이지별 검색 조건 | 해당 업무에서 필요한 조회 기준 입력 |
| 공통 레이아웃 | 여러 관리자 화면에서 반복되는 화면 구성 재사용 |
| 데이터 테이블 | 검색 결과 표시와 관리 작업의 진입점 |
| 페이지별 처리 | 업무마다 다른 입력·조회 조건을 적용 |

검색 조건과 데이터 테이블 등 관리 화면에서 반복되는 구성을 재사용하도록 했다.

## 소울: 외부 회사 연계 후원 페이지

외부 회사와 연계한 소울 후원 페이지를 개발했다.

외부 회사의 요구사항을 기존 기부 플랫폼의 사용자 화면에 연결한 작업이었다.

## C\*erry Run: 시즌별 챌린지 이벤트

C\*erry Run은 C\*erry에서 시즌별로 진행한 챌린지 이벤트다. 기존 기능을 인수인계받아 유지보수했다.

기존 동작과 운영 목적을 먼저 파악하고, 시즌별 요구사항에 맞춰 유지보수할 수 있도록 인수인계 내용을 정리했다.

후속 운영에서는 이벤트 개시 후 가입 요청이 급증하면서 발생한 DB 스파이크를 분석했다. 사용자 조회의 풀스캔을 확인하고 일반·표현식 인덱스를 적용한 내용은 [C\*erry Run 가입 스파이크 대응](/projects/cherry/postgresql-query-plan)에 별도로 정리했다.

## 캠페인별 기능 개발과 외부 서비스 연동

행사별 사용자 화면 개발과 외부 서비스 연동도 맡았다. 주요 작업은 다음과 같다.

| 작업 | 기록에 남은 담당 내용 |
| --- | --- |
| C\*erry 캠페인 | 캠페인 상세 페이지 개발 |
| C\*erry 스니커즈 데이 | 행사 페이지 개발 |
| Strava | 외부 활동 서비스 연동 |
| 재고관리 | 재고관리 기능 개발 |
| 댄스 챌린지 | 기능 개발과 Safari WebView 성능 문제 조사 |

### 공통 관리자 화면과 개별 행사 화면의 차이

관리자 화면은 검색 조건과 데이터 테이블처럼 반복되는 구성을 공통화했다. 반면 이벤트 페이지는 요구조건마다 페이지를 개발했다고 기록했다. 모든 행사 화면을 하나의 공통 틀로 처리한 것이 아니라, 공통으로 사용할 수 있는 관리자 구성과 행사별로 구현할 화면을 구분해 작업했다.

## 운영자 요구사항의 Excel 문서화

요구사항이 생길 때마다 운영자와 미팅하는 부담이 있었다. 이를 개선하기 위해 Excel 문서로 정리할 수 있는 내용은 문서화했다. 기능을 구현하는 것에 더해 요구사항을 전달하고 확인하는 과정도 정리한 것이다.

화면 항목과 처리 조건처럼 문서로 전달할 수 있는 내용은 남기고, 판단이 필요한 부분은 운영자와 협의했다.

팀 안에서 기술을 연구하고 공유한 다른 경험으로는 [사내 연구 프로젝트와 기술 지식 공유](/projects/cherry/internal-research)가 있다.

## 다른 캠페인 작업과 개발 중 피드백

댄스 챌린지 개발 중에는 Safari WebView에서 느려지는 현상을 디버깅하며 CSS blur 관련 성능 문제를 조사했다. 이 내용은 [iOS WebView 성능·문법 호환성 분석](/projects/cherry-world/ios-webview-compatibility)에 모았다. 같은 문서의 C\*erry World 메인 페이지 문법 오류와는 발생 서비스와 증상이 다른 사례다.

초기 개발 당시 동기 AJAX를 사용해 UI가 멈추는 문제를 겪고 비동기 처리에 대한 피드백을 받은 기록도 있다. 이 경험은 요청 처리 결과를 기다리는 동안 화면이 어떻게 동작하는지까지 고려하게 된 계기다. 이후의 [Native–JS 비동기 브리지](/projects/cherry-world/native-js-bridge)는 다른 플랫폼 경계에서 호출 흐름을 정리한 사례다.

## 구현 결과 {/* #정리 */}

이 작업 묶음에서는 관리자 화면의 반복 구조를 공통화하고, 제휴·행사별 요구사항을 구현하거나 인수인계했다. 운영자와의 협의 중 문서화할 수 있는 요구사항은 Excel로 정리했다. 기존 서비스의 기능 개발, 유지보수와 업무 전달 방식 개선을 함께 수행한 경험이다.
