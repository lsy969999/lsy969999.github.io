# C\*erry Walk의 시작과 C\*erry World로의 확장

## 개요 {/* #article-introduction */}

C\*erry Walk는 C\*erry에서 시작된 걷기 기능이다. 이후 그 걷기 기능을 바탕으로 C\*erry World가 만들어졌다. 두 이름을 서로 무관한 프로젝트로 소개하면 기존 기능의 개발 경험이 신규 서비스로 이어진 맥락이 사라지므로, 이 문서에서 관계를 구분한다.

## 서비스와 기능의 관계

| 구분 | 역할 |
| --- | --- |
| C\*erry | 기존 기부 플랫폼 |
| C\*erry Walk | C\*erry 안에서 시작한 걷기 기능 |
| C\*erry World | C\*erry Walk의 걷기 기능을 기반으로 만들어진 서비스 |

이 관계가 두 서비스의 코드나 데이터베이스를 완전히 동일하게 사용했다는 뜻은 아니다. 공통 저장소의 범위와 이관 단위까지 확인된 것은 아니므로 서비스의 출발점과 담당 업무를 연결하는 수준으로 설명한다.

## 걷기 기능이 만든 플랫폼 간 요구사항

걸음 수를 화면에 표시하고 보상과 연결하려면 웹 화면만으로 모든 처리를 끝낼 수 없었다. 네이티브가 읽는 걸음 정보, 웹에서 표현하는 상태, 서버가 관리하는 보상 사이의 연결이 필요했다.

Native–JS 통신 설명 자료에는 C\*erry Walk의 반복적이고 복잡한 통신을 다루면서 기존 콜백 방식의 불편함을 느끼고 개선 방식을 고안했다는 내용이 남아 있다. 브리지 개선은 C\*erry Walk에서 발생한 문제를 배경으로 설명하되, 상세 문서는 이후 앱 개발과 함께 읽을 수 있도록 C\*erry World에 둔다.

## 관련 문서 {/* #이후의-기술-문서 */}

후속 브리지 설계와 2023년 걸음 정책 검토는 C\*erry World 문서에 모았다. 초기 기능의 출시와 이후 변경안을 구분하며, 세부 설계와 적용 범위는 각 문서에서 설명한다.

- [Native–JS 비동기 브리지 개선](/projects/cherry-world/native-js-bridge): 반복되는 웹·앱 호출 흐름의 정리.
- [걸음 수와 보상 정책의 책임 분리](/projects/cherry-world/step-reward-policy): 기존 동기화 방식의 문제와 변경안.
- [C\*erry World 개요](/projects/cherry-world/overview): 신규 앱과 서비스 유지보수에서 맡은 역할.

## 작성 근거와 확인 범위 {/* #작성-근거와-범위 */}

C\*erry Walk의 시작과 C\*erry World의 관계는 담당자 회고를 기준으로 정리했다. 세부 기술 맥락은 「C\*erry Native–JS 통신」과 2023년 5월 걸음 정책 자료를 참고했다. 초기 기능의 정확한 출시일, 단계별 사용자 수, 코드 이관 규모는 이 자료만으로 확정하지 않는다.
