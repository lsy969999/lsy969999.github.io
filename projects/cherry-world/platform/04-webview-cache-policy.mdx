# Android WebView 데이터 사용량과 캐시 정책 개선

## 개요 {/* #article-introduction */}

Android 사용자로부터 앱의 데이터 사용량이 많다는 제보를 받아 WebView의 리소스 로딩을 점검했다. 캐시해야 할 리소스가 재사용되지 않는 현상을 확인했고, 캐시 모드와 생성 시점의 캐시 삭제 로직을 함께 수정했다.

이 작업은 광고 SDK 자체의 문제가 아니라 앱의 웹 리소스 로딩 정책에 관한 운영 개선이다. 기존 광고 연계 문서에 함께 있던 내용을 별도 사례로 분리했다.

## 사용자 제보에서 설정과 수명 주기 확인으로

당시 기록에는 디버거로 확인한 결과 캐시가 되어야 할 리소스가 캐시되지 않고 있었다고 남아 있다. 코드를 살펴보니 서로 다른 두 지점이 영향을 주고 있었다.

| 확인 지점 | 변경 전 | 적용한 변경 |
| --- | --- | --- |
| WebView 캐시 모드 | `LOAD_NO_CACHE` | `LOAD_DEFAULT`로 변경 |
| 생성 시점의 처리 | `onCreate` 시점에 캐시 삭제 | 해당 캐시 삭제 로직 제거 |

캐시 모드만 바꾸더라도 생성할 때마다 기존 캐시를 지우면 재사용 효과가 제한될 수 있다. 반대로 삭제 로직만 제거하고 캐시를 사용하지 않는 모드를 유지해도 원하는 동작이 되지 않는다. 그래서 두 설정을 함께 확인하고 수정했다.

## 변경이 의미하는 것

Android 공식 문서에서 `LOAD_NO_CACHE`는 캐시 대신 네트워크로 읽는 모드다. `LOAD_DEFAULT`는 기본 캐시 정책으로, 탐색 동작에 별도 조건이 없다면 사용 가능하고 만료되지 않은 캐시를 활용하며 그렇지 않으면 네트워크로 읽는다. 항상 캐시만 사용하거나 네트워크 요청을 없애는 설정은 아니다. [Android Developers: WebSettings](https://developer.android.com/reference/android/webkit/WebSettings#LOAD_DEFAULT)

이번 변경의 목적은 재사용 가능한 리소스의 캐시를 처음부터 배제하고 생성 때마다 지우던 처리를 바로잡는 것이었다. 모든 캐시 삭제를 없애거나 리소스 갱신을 막는 방향으로 설명하지 않는다. 서비스별 갱신·초기화 요구는 별도로 고려해야 한다.

## 반복 실행으로 사용량 비교

설정 변경 과정에서 설치·로그인 이후 반복 실행 횟수에 따른 데이터 사용량을 표로 남겼다. 아래는 당시 기록의 제목과 값을 그대로 옮긴 것이다.

<details>
<summary>당시 데이터 사용량 비교 기록</summary>

| load_no_cache | load_defualt | clearAppCache 제거까지 한 버전 |
| --- | --- | --- |
| 설치하고 로그인 | 0m | 13.21m |
| 5번 | 141m (+141) | 126m (+113) |
| 10번 | 302m (+161) | 242m (+124) |
| 15번 | 470m (+168) | 353m (+111) |

원문의 `load_defualt` 철자와 `m` 표기를 유지했다. 첫 열 제목은 설정명인데 행에는 실행 단계가 적혀 있어, 각 수치 열이 정확히 어느 설정·초기 조건에 대응하는지 이 표만으로는 확정하기 어렵다.

</details>

따라서 표를 임의로 재배치하거나 사용량 절감률을 계산하지 않았다. 특히 마지막 행의 두 값을 곧바로 ‘수정 전·후 동일 조건’으로 간주하지 않는다. 확인 가능한 것은 설정을 수정하고 반복 실행 사용량을 비교하는 과정까지이며, 현재 자료만으로 정확한 개선 비율을 주장하지 않는다.

## 결과와 돌아볼 점

캐시를 사용하지 않던 모드를 기본 모드로 변경하고, 생성 시점에 캐시를 지우던 로직을 제거했다. 사용자 제보를 화면 기능만의 문제로 보지 않고 네트워크 리소스 재사용과 앱의 초기화 처리까지 연결해 살핀 경험이다.

회고하면 측정표에는 변경 조합, 실행 횟수의 의미, 초기 캐시 상태와 측정 단위까지 함께 남겼어야 했다. 설정 변경 내용을 확인하는 것과 그 효과를 재현 가능한 수치로 증명하는 것은 다른 단계라는 점도 이 기록에서 드러난다.

관련 기능 연계는 [광고 공통 계층 설계·SDK 연계 문서](/projects/cherry-world/ads-offerwall-integration), 실행 환경별 화면 문제는 [iOS WebView 성능·문법 호환성 문서](/projects/cherry-world/ios-webview-compatibility)에서 이어 볼 수 있다.

## 작성 근거와 확인 범위 {/* #작성-근거 */}

업무 노트의 Android 데이터 사용량 제보, `no_cache` 설정 확인, `onCreate`의 캐시 삭제 제거 및 비교 표를 사용했다. 원문의 `clearAppCache`를 특정 네이티브 API의 실제 호출 코드로 단정하지 않았다. 공식 API 문서는 설정 의미를 설명하기 위한 참고 자료이며, 당시 작업 결과를 증명하는 자료와는 구분한다.
