추석 운영 모니터링 중 MyBatis 사용 쿼리의 파싱 오류 추적

개요​

C*erry World 운영 중 추석 연휴 모니터링에서 쿼리 파싱 문제를 발견해 추적했다. 당시 업무 메모에는 MyBatis 쪽에서 띄어쓰기를 넣었지만 DB에서 실행되는 SQL의 줄바꿈과 관련해 파싱이 되지 않던 현상을 트러블슈팅했다고 남겼다. 서비스 귀속은 담당자 회고로 확인했고, 원본 로그 캡처에는 2023년 10월 1일이 표시돼 있다.

확인한 현상과 로그​

연휴 모니터링 때 남긴 원본 로그 일부. 날짜와 오류 메시지는 유지하고 서버 주소·DB명·사용자명·프로세스 식별정보와 SQL 원문은 가렸다. 원래 캡처의 빨간 표시도 그대로 남겼다. 이미지를 클릭하면 크게 볼 수 있다.

캡처에는 닫는 괄호 근처의 syntax error와 이어지는 current transaction is aborted 메시지가 보인다. 단순히 조회가 느렸던 사례가 아니라, DB가 SQL을 해석하지 못한 오류를 확인하던 기록이다. 이는 AWS의 높은 대기 부하나 7월 인덱스 개선과 별개의 운영 사례다.

매퍼와 실제 실행 SQL의 차이를 추적​

이 작업의 초점은 매퍼 편집 화면에서 보이는 공백·줄바꿈과 DB에서 해석하는 SQL을 구분하는 것이었다. 코드에 띄어쓰기가 있다는 사실만으로 실행되는 SQL이 올바르다고 판단하지 않고, DB 오류 위치와 실제 문장을 함께 살펴야 했던 상황이다.

다만 PostgreSQL은 일반적으로 공백·탭·줄바꿈을 토큰 구분자로 허용한다. 따라서 이 기록을 “줄바꿈이 있으면 SQL이 파싱되지 않는다”는 일반 규칙으로 설명하지 않는다. PostgreSQL — Lexical Structure.

현재 남아 있는 것은 당시 메모와 오류 캡처이며, 재현 가능한 전체 매퍼, 바인딩 값, 수정 전후 diff는 아니다. 동적 SQL 조립, 주석, 문장 경계 중 무엇이 직접 원인이었는지나 MyBatis 라이브러리 자체 결함인지는 확정하지 않는다. 캡처에 보이는 오류들을 모두 하나의 원인으로 묶지도 않는다.

결과와 확인 범위​

추석 운영 모니터링에서 발생한 쿼리 오류를 확인하고, MyBatis 작성 내용과 DB 실행 SQL의 파싱 문제를 추적한 경험으로 정리한다. 복구 시간이나 영향 사용자 수, 최종 수정 방식은 남은 자료로 확인되지 않아 성과 수치로 기재하지 않았다.

같은 유형을 다시 기록한다면 개인정보를 제거한 매퍼·최종 SQL·파라미터와 수정 전후 재현 결과를 함께 남길 것이다. 이는 당시 완료했다고 주장하는 조치가 아니라, 후속 검증 자료를 보강할 방향이다.

작성 근거와 확인 범위​

  • 업무 노트의 추석 모니터링·MyBatis 공백 및 줄바꿈 관련 트러블슈팅 메모.
  • 같은 노트에 첨부한 2023.10.01 PostgreSQL 오류 캡처.
  • C*erry World 운영 중 발생했다는 담당자 회고.
  • PostgreSQL 공식 문서는 일반적인 SQL 어휘 규칙 해석에만 참고했다. 당시 서버 버전을 증명하는 자료는 아니다.

원본 로그와 내부 SQL은 배포하지 않는다. 공개 이미지는 민감 영역을 불투명하게 가리고 메타데이터를 제거한 사본이다.
