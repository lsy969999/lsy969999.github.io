선과 면을 모아 그리는 공통 디버그 시각화 렌더러

도입 배경과 현재 실행 상태​

충돌 형상·광원 범위·좌표축·망토 입자처럼 게임의 논리 상태를 화면에서 확인할 일이 많았다. 각 기능이 별도 버퍼와 Shader를 관리하는 대신, 위치와 색 또는 기본 형상만 요청하면 같은 경로로 표시할 수 있도록 CDbgLineRender를 구성했다.

기본 선 도형과 PhysX 연결에서 시작해 깊이 검사 선택, Cylinder·Wedge, 반투명 Solid 형상과 메시 표시를 보강했다. 이름은 Line Renderer지만 현재 인터페이스는 선과 삼각형 면을 모두 지원한다. 이는 게임 오브젝트의 일반 재질 렌더러나 조명·그림자 시스템을 대신하는 기능은 아니다.

호출자는 형상을 제출하고 렌더러는 모아서 그린다​

AddLine, AddBox, AddSphere 등은 호출 즉시 Draw를 하지 않는다. 형상을 World 공간 정점으로 변환해 CPU 배열에 넣는다. CGameInstance는 이 렌더러를 RENDERGROUP::COLLIDER에 등록하고 FrameEnd에서 임시 데이터를 비운다.

Plain Text
물리·망토·에디터의 Add 요청
       ↓
프레임 정점 목록에 누적
       ↓
Render: 동적 버퍼 업로드 → 종류별 Draw
       ↓
FrameEnd: 목록 Clear → 다음 프레임 재제출

한 번 요청하면 영구적으로 남는 방식이 아니다. 계속 보일 형상은 매 프레임 제출해야 한다. 반대로 객체 포인터나 형상 소유자의 수명을 렌더러가 장기간 보관할 필요도 없다.

선·면과 깊이 정책으로 나눈 네 목록​

수집 단계에서 깊이 정책과 도형 종류를 나눠 보관한다.

목록토폴로지목적
Depth LinesLine List장면 깊이를 검사하는 윤곽선
No-Depth LinesLine List가려진 위치도 확인하기 위한 선
Depth SolidsTriangle List깊이를 검사하는 반투명 면
No-Depth SolidsTriangle List깊이 가림 없이 확인하는 면

SetDepthMode는 이후 Add 요청이 어느 배열로 들어갈지를 결정한다. 이미 추가한 선을 다른 목록으로 옮기는 명령은 아니다. 기본 Color도 이후 생성하는 정점에 기록한다.

여러 시스템이 같은 인스턴스를 공유하므로 호출자는 자신이 변경한 Color·Depth 상태를 복구해야 한다. 충돌 에디터도 이전 상태를 저장하고 그리기 요청이 끝나면 되돌린다.

Solid Depth Bias는 별도 주의가 필요하다. 현재는 정점별로 저장하지 않고 Render 시점의 전역 옵션 하나를 사용한다. 따라서 같은 프레임에 제출된 각 Solid가 서로 다른 Bias 값을 보존하는 구조는 아니다.

기본 형상 API와 좌표 규칙​

Box·Sphere·Capsule·Cylinder·Cone·Wedge 외에 Axis·Grid·Circle·Ray·Arrow·Frustum·Triangle과 Mesh를 지원한다. 복잡한 객체를 직접 렌더링하지 않아도 범위·방향·좌표계를 확인할 수 있다.

크기 인자의 의미는 호출자가 맞춰야 한다. AddBox는 전체 Size가 아닌 Half Extents를 받고, Capsule·Cylinder는 Radius와 Half Height를 받는다. 로컬 형상을 만든 뒤 전달된 World 행렬로 정점을 변환한다.

특히 디버그 Capsule은 로컬 Y축 방향인데 PhysX Capsule의 Pose 기준은 다르다. 충돌 에디터는 Z축 90도 보정 행렬을 추가해 축을 맞춘다. 디버그 도형이 Collider와 다르게 보일 때는 크기뿐 아니라 이런 축·행렬 조합부터 확인해야 한다.

Triangle Mesh와 Convex Hull API는 정점·삼각형 인덱스를 받아 윤곽선을 만든다. Convex를 새로 Cooking하거나 Hull을 생성하는 함수가 아니다. Solid Mesh도 넘겨받은 삼각형을 면으로 제출하는 기능이다.

간단한 제출 예시​

World 행렬을 가진 객체가 매 프레임 디버그 형상을 제출하는 예시다.

C++
auto* debug = CGameInstance::Get().GetDbgLineRender();
if (!debug)
{
    return;
}

const auto previousColor = debug->GetColor();
const auto previousDepth = debug->GetDepthMode();

debug->SetDepthMode(DBG_LINE_DEPTH_MODE::ENABLED);
debug->SetColor({ 0.f, 1.f, 1.f, 1.f });
debug->AddBox({ 0.5f, 1.f, 0.5f }, world);
debug->AddAxis(1.f, world);

debug->SetColor(previousColor);
debug->SetDepthMode(previousDepth);

이 호출은 Box Collider를 생성하거나 물리 판정을 추가하지 않는다. 보여 줄 형상만 제출한다.

동적 버퍼 업로드와 Draw 구조​

현재 정점은 float3 Position + uint32_t Color의 16바이트 구조다. 일반 색 입력은 채널을 0~1로 제한해 8비트씩 포장하고, Shader는 ViewProjection 변환과 색 출력만 수행한다. 이 Packed 정점 경로는 이후 팀 변경이 합쳐진 현재 구조다.

Render 본문은 비어 있지 않은 네 배열을 한 동적 Vertex Buffer에 이어서 복사한다. D3D11_MAP_WRITE_DISCARD로 한 번 Map한 뒤 배열별 오프셋을 사용한다. 먼저 Solid, 다음 Line을 그리며 각 종류를 Depth 여부로 나누므로 해당 호출에서 최대 네 번 Draw한다. 장면 전체 Draw Call이 네 번이라는 뜻은 아니다.

Solid에는 Alpha Blend와 Cull None Rasterizer를 사용하고, 선택적으로 Depth Bias를 적용한다. 렌더 전의 Depth·Blend·Rasterizer·Topology 상태를 저장하고 이후 복구한다. Shader·Input Layout·Vertex Buffer 등 전체 파이프라인 상태를 모두 저장하는 범용 State Guard는 아니다.

FrameEnd는 네 목록을 Clear하고 Depth Mode와 Solid Bias 기본값을 복원한다. Color는 이 함수에서 초기화하지 않는다. vector::clear는 크기를 비우는 동작이므로 매 프레임 용량 전체를 해제하고 재할당하는 구조와도 구분된다.

PhysX와 다른 엔진 기능의 연결​

PhysX Manager는 디버그 표시가 켜져 있을 때 PxRenderBuffer의 선 데이터를 가져온다. 현재 경로는 PxDebugLine과 엔진 정점의 크기·멤버 오프셋을 static_assert로 확인하고 Packed 정점 배열로 복사한다. 전달받은 포인터를 다음 프레임까지 보관하지는 않는다.

NvCloth Manager도 같은 렌더러에 디버그 요청을 제출한다. 충돌 배치 에디터는 편집 데이터에서 Wire·Solid를 만들고, 선택·Trigger·비활성 상태를 색으로 표현한다. 시뮬레이션 결과를 보여주는 경로와 편집 중인 설정을 보여주는 경로가 같은 출력 기반을 공유하는 것이다.

공통 출력 경로를 사용해도 데이터가 자동으로 일치하는 것은 아니다. 에디터의 미리보기 데이터와 실제 PhysX 객체가 다른 시점에 갱신되면 서로 다른 위치를 그릴 수 있다. 색과 표시 토글을 나눠 어떤 데이터인지 식별해야 한다.

디버그 표시 자체의 비용도 줄이기​

기본 구와 Capsule 분할 수가 높으면 작은 형상을 여러 개 표시할 때 CPU의 삼각함수 계산·정점 변환·배열 추가량이 커진다. 게임의 렌더 메시가 아니라 범위 확인용이므로 윤곽을 알아볼 수 있는 수준으로 기본 해상도를 낮췄다.

c732977d에서 Wire Sphere의 Slice/Stack을 24/12에서 8/4로, Wire Capsule의 Slice/Arc를 24/12에서 8/4로 변경했다. 이 값은 물리 Geometry의 정확도를 바꾸지 않는다. 모든 Solid 도형이나 Mesh 해상도까지 일괄 낮춘 작업도 아니다.

정점 용량과 제출 방식​

정점 상한은 네 목록을 합쳐 3,000,000개다. CanAddVertices에서 남은 공간을 확인하고 초과 요청을 거부한다.

초기화할 때 GPU 버퍼와 CPU Vector 용량을 미리 확보한다.

Add API는 메인 스레드에서 호출하며, 공용 Vector에 정점을 추가한다.

Solid는 추가 순서대로 묶어 그린다. Depth Bias를 적용해 면과 선이 겹칠 때의 깜빡임을 줄였다.

구현 결과​

각 기능이 Shader·Buffer를 따로 준비하지 않고도 엔진의 논리 형상을 같은 경로로 확인할 수 있는 기반을 마련했다. 선 중심의 초기 기능에서 Depth 선택과 Solid 표시를 확장해 물리 배치 도구에도 재사용했다.

초기 디버그 렌더러와 깊이 검사 전환, Cylinder·Wedge, Solid·메시 표시를 구현하고 기본 분할 수를 조정했다. Packed 정점과 PhysX 직접 복사 경로는 이후 팀원이 보강했다.
