# PhysX D6 Joint 물리 문과 CCT 상호작용

## 배경과 목표 {/* #목표 */}

호그와트 월드의 문은 정해진 애니메이션을 재생하는 장치가 아니라, 플레이어가 어느 쪽에서 어느 위치를 미느냐에 따라 열리고 놓으면 천천히 닫히는 물리 오브젝트여야 했다.

RigidBody 문짝에 회전 Joint만 연결하면 기본 동작은 만들 수 있다. 그러나 Character Controller와 함께 사용하면서 다음 문제가 드러났다.

- CCT가 회전하는 문짝 아래로 투영되어 문 위로 올라감
- 문이 CCT를 입력과 무관한 옆 방향으로 밀어 슬라이딩함
- CCT와 Dynamic Body가 직접 힘을 주고받으며 문이 요동함
- 빠르게 왕복하면 닫히는 문을 관통함
- 배치 위치·회전·비균일 Scale을 바꾸면 문짝과 Joint Anchor가 어긋남

이를 하나의 Collider 설정으로 해결하지 않고, 문짝의 물리 운동과 통로 제어, 힌지 보호, 통과 감지를 역할별 Shape로 분리했다.

## 하나의 문, 네 개의 Shape 역할

```text
CPhysicsDoor
├─ Door Leaf
│  ├─ Dynamic RigidBody
│  └─ Box Collider + D6 Joint
├─ Hinge Blocker
│  └─ Static Query Shape
├─ Passage Barrier
│  └─ Static Query Shape
└─ Passage Trigger
   └─ Static Trigger Shape
```

각 Shape는 `SHAPE_SUB_INDEX`로 구분한다.

| Shape | 역할 | Simulation | Query |
| --- | --- | --- | --- |
| `DOOR_LEAF` | 실제로 회전하고 렌더링되는 문짝 | CCT·월드 정적 지형 제외 | 활성 |
| `HINGE_BLOCKER` | 힌지 틈으로 CCT가 파고드는 경로 차단 | 비활성 | 활성 |
| `PASSAGE_BARRIER` | 문이 충분히 열리기 전 통과 방지 | 비활성 | 조건부 활성 |
| `PASSAGE_TRIGGER` | 플레이어 진입·이탈 상태 감지 | Trigger Event | 비활성 |

문짝은 `DOOR_DYNAMIC`, 고정 차단 Shape는 `DOOR_HINGE_BLOCKER` Layer를 사용한다. Player CCT의 Query Mask에는 두 Layer를 포함하지만, 문짝의 Simulation Mask에서는 `PLAYER_BODY`를 제외했다.

즉 CCT 이동 Sweep은 문을 장애물로 인식하되, CCT와 Dynamic RigidBody 사이의 직접 Simulation Pair는 만들지 않는다. 문을 여는 힘은 아래의 CCT Hit Callback에서 제한된 토크로만 전달한다. 물리 반응 경로가 두 개 생겨 문이 과하게 흔들리는 문제를 피하기 위한 선택이다.

## D6 Joint로 Hinge 구성

문짝은 World에 고정된 Frame A와 Dynamic RigidBody의 Local Frame B를 D6 Joint로 연결한다. 문이 회전할 자유도 하나만 남기고 Twist 축을 `LIMITED`로 설정했다.

PhysX D6의 Twist는 Joint Local X축 회전이다. 문의 실제 세로 회전축은 Y축이므로 Joint Frame을 Z축으로 90도 회전해 Local X를 문의 Y축에 맞춘다.

```cpp
const matrix localHingeRotation = RotationZ(90_degrees);

joint.motions[TWIST] = LIMITED;
joint.twistLimit.lower = -110_degrees;
joint.twistLimit.upper =  110_degrees;
```

왼쪽·오른쪽 힌지는 문 Half Extent의 X 부호만 바꿔 같은 계산을 사용한다.

```text
LEFT  Hinge Local Position = (-HalfExtent.x, 0, 0)
RIGHT Hinge Local Position = (+HalfExtent.x, 0, 0)
```

Joint 생성은 `Initialize()`가 아니라 `OnRegisteredToManager()`에서 수행한다. Component와 RigidBody 생성뿐 아니라 GameObject의 Manager 등록과 Handle 확정까지 끝난 뒤 Joint를 Registry에 추가하기 위해서다.

## 놓으면 천천히 닫히는 Twist Drive

닫힌 Joint 상대 자세를 Drive Target으로 삼고 Twist Drive에 Stiffness, Damping, Force Limit을 설정했다.

| 값 | 의미 |
| --- | --- |
| Stiffness | 닫힌 자세로 되돌아가려는 힘 |
| Damping | 복귀 중 진동과 Overshoot 억제 |
| Force Limit | 지나치게 강한 복귀력 제한 |
| Angular Damping | 문짝 자체의 회전 감쇠 |

테스트 레벨과 실제 월드의 체감이 달랐기 때문에, Hogwarts World 배치에서는 복귀 Stiffness를 낮추고 Damping을 높여 문이 더 천천히 닫히도록 조정했다.

복귀 Drive를 제거한 것은 아니다. 플레이어가 통과 중일 때만 Stiffness를 0으로 바꾸어 잠시 멈추고, 통과가 끝나면 원래 설정으로 복구한다. 문이 플레이어 뒤에서 즉시 닫히며 CCT를 미는 상황을 줄이면서도 자동 닫힘 성질은 유지한다.

## CCT 접촉을 문 토크로 변환

CCT는 Dynamic Body처럼 Contact Force를 자연스럽게 전달하지 않는다. `OnCCTShapeHit()`에서 받은 접촉점과 CCT 이동 방향으로 Y축 토크를 계산해 문짝에 적용했다.

```text
lever = hitPosition - hingePosition
push  = normalize(horizontalMoveDirection)
torqueY = (lever.z × push.x - lever.x × push.z) × pushForce
```

힌지에서 먼 곳을 밀수록 Lever Arm이 커지고, 문의 반대쪽에서 밀면 토크 부호가 바뀐다. 따라서 별도의 “앞에서 열기/뒤에서 열기” 분기 없이 양방향으로 작동한다.

Callback은 다음 조건을 모두 만족할 때만 토크를 전달한다.

- 상대 Shape가 문짝 또는 Passage Barrier일 것
- CCT의 이동 길이가 0보다 클 것
- 수평 이동 방향과 계산된 토크가 유효할 것

CCT가 가만히 접촉해 있을 때 지속적으로 힘이 들어가거나, 힌지 Blocker를 밀어 문이 열리는 경우를 차단한다.

## 문 위로 올라가는 문제

회전하는 문짝이 CCT 아래로 들어오면 PhysX CCT의 충돌 해결 결과에 위쪽 변위가 추가될 수 있다. Climbing Mode를 전역 변경하면 계단과 지형 이동까지 영향을 받으므로, 문 Shape와 부딪힐 때만 적용하는 Engine 확장 Behavior를 추가했다.

```cpp
PREVENT_UPWARD_PROJECTION
```

CCT Move 전후 Y를 비교하고 사용자가 요청한 상승량보다 커진 부분만 제거한다.

```text
maximumY = beforeMove.y + max(requestedDisplacement.y, 0)
correctedY = min(afterMove.y, maximumY)
```

점프나 비행처럼 입력으로 요청한 상승은 보존하고, 문 충돌 투영이 추가한 상승만 제한한다. Hit Report가 발생하지 않는 Standing 접촉도 `PxControllerState::touchedActor`를 조회해 같은 정책을 적용한다.

## 입력에 없던 측면 슬라이딩 제거

문이 회전하며 CCT를 옆으로 밀면 플레이어 입력 방향과 실제 수평 변위 사이에 차이가 생긴다. 두 번째 Engine 확장 Behavior로 이 차이를 보정했다.

```cpp
CONSTRAIN_HORIZONTAL_TO_INPUT
```

실제 이동 벡터를 입력 방향 성분과 측면 성분으로 분해하고, 측면 성분의 반대 방향으로 CCT Move를 한 번 더 수행한다.

```text
actual = positionAfter - positionBefore
forward = project(actual, requestedDirection)
lateral = actual - forward
correction = -lateral
```

위치를 강제로 덮어쓰지 않고 동일한 Query Filter를 사용하는 역방향 Sweep으로 보정한다. 따라서 보정 경로에 다른 벽이나 Shape가 있으면 그 지점에서 안전하게 멈춘다. 보정 Move 중에는 Hit Callback을 다시 처리하지 않아 재귀적인 토크와 접촉 Event도 방지한다.

두 Behavior는 PhysX의 기본 CCT Flag가 아니라 프로젝트 Engine에서 확장한 정책이다. GameObject의 `GetCCTShapeBehavior()`가 접촉 상대에 따라 Flag를 반환하므로, 다른 CCT 동작을 전역으로 바꾸지 않고 Player–PhysicsDoor 조합에만 적용할 수 있다.

## 관통을 막는 Passage Barrier

문짝 Collider만 사용했을 때는 좁은 문을 빠르게 왕복하거나 닫히는 문과 비비는 상황에서 CCT가 반대편으로 넘어가는 경우가 있었다. 문이 닫힌 동안 출입구 중앙에 얇은 Query 전용 `PASSAGE_BARRIER`를 두어 통로 자체를 차단했다.

```text
플레이어가 Passage Trigger 진입
        ↓
문을 밀어 Opening Angle 증가
        ↓
|Angle| >= Open Threshold
        ↓
Barrier Query 비활성 + Return Drive 일시 정지
        ↓
플레이어 Trigger 이탈, 문이 절반 이하로 닫힘
        ↓
Return Drive 복구 + Barrier Query 재활성
```

플레이어가 Barrier와 겹친 상태에서는 다시 활성화하지 않는다. Trigger를 완전히 벗어나고 문 각도가 Open Threshold의 절반 아래로 돌아온 다음에만 다음 진입을 차단한다. 이 Hysteresis는 임계 각도 주변에서 Barrier와 Drive가 매 Frame 켜졌다 꺼지는 현상을 막는다.

## Fixed Hit와 애니메이션 상태 연결

물리 문을 미는 동안 왼손 밀기 애니메이션을 재생하되 문 회전은 계속 PhysX가 담당한다.

- CCT Hit Callback은 문 접촉 시간을 갱신하고 상태 전환만 요청
- 다음 Priority Update에서 `DOOR_PUSH` 상태 진입
- Root Motion Translation과 Rotation은 비활성화
- 이동 잠금은 하지 않아 CCT가 계속 문을 밀 수 있음
- 접촉 또는 이동 입력이 끝나면 Locomotion으로 복귀

CCT Hit는 Fixed Tick에서 발생하지만 상태는 Render Update에서도 평가된다. 두 Tick 사이에서 상태가 한 Frame씩 꺼지는 것을 막기 위해 접촉에 0.15초의 짧은 Grace Time을 두었다. Callback 안에서 매번 애니메이션을 다시 재생하지 않아 재생 위치가 계속 초기화되는 문제도 피했다.

## 런타임 배치와 비균일 Scale

Transform만 바꾸면 PhysX가 다음 동기화에서 값을 덮어쓰고, 기존 World Anchor가 문짝을 이전 위치로 끌어당긴다. 그래서 `SetPlacement()`가 관련 상태를 하나의 작업으로 갱신한다.

1. 문짝 Collider와 세 개의 보조 Shape Extent 조정
2. 변경된 문 폭에 맞춰 Joint Local Hinge Frame 이동
3. Dynamic 문짝 Pose와 World Anchor 동시 재배치
4. Hinge Blocker와 Trigger Actor Pose 재배치
5. 렌더 Transform과 GUI 입력 상태 갱신

각 단계가 실패하면 이전 Collider 크기와 Pose로 되돌린다. 비균일 XYZ Scale도 각 Shape의 Half Extent와 Hinge 위치에 함께 반영한다.

Hogwarts World에서는 배치 함수를 통해 위치, Euler XYZ, Scale을 전달한다.

```cpp
SpawnPhysicsDoor(
    {134.1f, 3.7f, -93.5f},
    {0.f, -60.f, 0.f},
    {0.9f, 0.8f, 1.f});
```

물리 동기화 결과와 사용자가 편집하는 배치 값을 별도 멤버로 유지해, ImGui에서 값을 조절한 뒤에도 입력 필드가 시뮬레이션 Pose로 계속 덮어써지지 않게 했다.

## 안정화를 위한 보조 설정

- 문짝 Gravity 비활성화
- Angular Damping으로 불필요한 회전 감쇠
- Max Depenetration Velocity 제한으로 겹침 복구 시 폭발적인 반발 억제
- Joint Collision 비활성화로 연결된 Frame과 문짝의 자체 충돌 제거
- Hinge Blocker는 Simulation Pair 없이 CCT Query만 차단
- Shape SubIndex로 문짝·Barrier·Trigger Callback을 하나의 객체 안에서 구분

Debug View에서는 문짝 Collider, Hinge 위치, Blocker, Passage Barrier를 서로 다른 선으로 표시하고 현재 Twist Angle과 Drive 값을 확인할 수 있게 했다. 모델과 물리 Shape의 배치 불일치를 월드에서 바로 조정하기 위한 도구다.

## 한계와 개선 방향 {/* #트레이드오프 */}

Passage Barrier는 실제 문짝 외에 논리적인 차단면을 하나 더 사용하는 방식이다. 문 형상이 복잡하거나 문이 완전히 파괴될 수 있다면 Barrier 상태도 그 수명주기에 맞춰 별도로 꺼야 한다.

수평 보정은 문 접촉 시 CCT Sweep을 최대 한 번 더 수행하므로 비용이 0은 아니다. 전역 적용하지 않고 Behavior Flag가 설정된 Shape에서만 실행한 이유다. 반대로 위치 직접 보정은 더 저렴할 수 있지만 벽을 통과시킬 위험이 있어 선택하지 않았다.

현재 Door Push State는 애니메이션 표현만 담당한다. 손 IK로 실제 문 접촉점을 맞추거나, 문 재질과 각속도에 따라 소리를 변화시키는 작업은 별도의 표현 계층으로 확장할 수 있다.

## 구현 결과 {/* #결과 */}

D6 Joint 하나에 모든 책임을 맡기지 않고, 동적 문짝의 운동과 CCT 통로 제어를 분리했다. 접촉 위치 기반 토크로 양방향 물리 반응을 유지하면서도 비의도성 상승·횡이동·관통을 문 전용 정책으로 제한했고, 테스트용 Debug Shape에서 실제 Hogwarts World 모델 배치까지 같은 Component 구성을 재사용했다.
