# NvCloth 기반 스키닝 망토 시뮬레이션

## 배경과 목표 {/* #문제 */}

캐릭터의 망토는 뼈에 고정된 일반 Skinned Mesh처럼 렌더할 수 없다. 상단은 캐릭터 애니메이션을 따라야 하지만, 나머지 영역은 중력과 관성, 바람, 신체 충돌에 반응해야 한다. 빗자루처럼 이동 속도와 방향이 급격히 바뀌는 상황에서는 한 Frame의 좌표 불일치만으로도 망토가 몸을 관통하거나 파티클이 멀리 이탈할 수 있다.

반대로 화면에 보이는 고해상도 망토를 그대로 시뮬레이션하면 파티클과 Constraint 수가 늘어 비용이 커진다. 물리용 저해상도 메시를 따로 사용하면 성능은 좋아지지만, 물리 결과를 렌더 메시의 모든 정점으로 다시 전달해야 한다.

이를 해결하기 위해 시스템을 다음 네 계층으로 나눴다.

```text
Skinned Model Resource
   ↓
CResNvClothMesh
   ├─ 저해상도 Simulation Mesh → Fabric·Particle·Skin Binding
   └─ 고해상도 Render Mesh     → Triangle·Barycentric Mapping
                         ↓
CComNvCloth → CNvClothManager → CPU / DX11 Solver
                         ↓ Particle SRV
CNvClothCape → 일반 렌더·Directional/Spot/Point Shadow
```

`CResNvClothMesh`는 시뮬레이션에 필요한 정적 데이터를 준비하고, `CComNvCloth`는 Fabric과 Cloth Handle의 수명을 소유한다. `CNvClothManager`는 NvCloth Backend와 Solver를 관리하며, `CNvClothCape`는 캐릭터 애니메이션·이동 상태·충돌 리그를 매 Fixed Tick의 Cloth 입력으로 변환한다.

## 저해상도 Simulation Mesh와 고해상도 Render Mesh 분리

Resource를 읽을 때 Simulation Mesh와 Render Mesh를 따로 선택한다. 명시하지 않으면 가장 작은 Mesh를 Simulation용으로, 가장 큰 Mesh를 Render용으로 선택할 수 있으며 실제 콘텐츠에서는 Index를 지정해 의도를 고정한다.

두 Mesh는 모두 Simulation Anchor Bone의 Local Space로 변환한다. 물리와 렌더가 서로 다른 기준 좌표계를 사용하면 캐릭터가 회전하거나 Scale을 가질 때 오차가 증폭되므로, 전처리 단계에서 기준 공간을 하나로 통일했다.

Simulation Mesh는 다음 순서로 Fabric 데이터가 된다.

1. 원본 Skeleton의 Rest Pose로 저해상도 정점을 Skinning한다.
2. 같은 위치의 정점을 허용 오차 기준으로 Weld한다.
3. Weld된 파티클에 위치와 역질량, Bone Influence를 저장한다.
4. Weld 때문에 같은 Index가 되었거나 면적이 사라진 삼각형은 제거한다.
5. 유효한 Particle와 Triangle로 NvCloth Fabric을 Cook한다.

UV Seam 때문에 공간상 같은 정점이 여러 번 존재해도 하나의 물리 파티클로 합쳐진다. Authored Constraint를 사용할 때 Weld 대상들의 값이 다르면 더 작은 Max Distance를 채택한다. 느슨한 값으로 합쳐져 고정 경계가 풀리는 것보다 제한적인 값을 보존하는 편이 안전하기 때문이다.

고해상도 Render 정점은 저해상도 메시의 가장 가까운 삼각형을 찾고 다음 정보를 저장한다.

```cpp
struct CLOTH_RENDER_VERTEX
{
    uint3 particleIndices;
    float3 barycentric;
    float3 positionOffset;
    float3 normalFrame;
    float4 tangentFrame;
};
```

단순히 가장 가까운 파티클 하나를 따라가면 표면이 찌그러지고 정점이 한곳으로 몰린다. 세 파티클의 Barycentric 좌표로 삼각형 표면 위치를 복원하고, Rest Pose에서 계산한 Local Frame Offset과 Normal·Tangent를 현재 삼각형 Frame에 다시 적용한다. 물리 비용은 저해상도로 유지하면서도 원래 망토의 두께감과 실루엣, Normal Mapping을 보존한다.

## Fabric과 Cloth Instance 분리

Fabric은 Triangle Topology에서 Cook된 Constraint 집합이다. 같은 망토 Resource를 사용하는 객체끼리 공유할 수 있다. Cloth는 현재·이전 Particle 위치, 바람, 충돌체, Solver 설정처럼 Instance마다 달라지는 상태다.

엔진 외부에는 NvCloth Pointer 대신 `NVCLOTH_FABRIC_HANDLE`과 `NVCLOTH_CLOTH_HANDLE`을 노출했다. Component가 두 Handle을 소유하고 해제하므로 GameObject는 NvCloth 객체의 생성·소멸 순서에 의존하지 않는다.

```text
한 번 Cook한 Fabric
   ├─ Player A Cloth State
   ├─ Player B Cloth State
   └─ Preview Cloth State
```

Cloth Descriptor에서는 중력, 감쇠, 관성, Solver Frequency, 구조·전단·굽힘 Stiffness, Self Collision, Virtual Particle을 독립적으로 설정한다. Self Collision과 Virtual Particle은 품질을 높이지만 계산량도 증가하므로 콘텐츠별 선택 사항으로 남겼다.

## 애니메이션을 Motion Constraint로 전달

망토를 하나의 Bone에 매달기만 하면 어깨와 등 움직임을 충분히 따라가지 못한다. Resource를 만들 때 각 저해상도 Particle에 최대 네 개의 Bone Influence와 Bone Local Rest Position·Normal을 저장했다.

Fixed Update에서는 현재 Character Bone Matrix를 Simulation Local Space로 변환하고, Influence 가중합으로 Particle별 애니메이션 Target을 계산한다.

```text
현재 Bone Pose
   ↓ Skin Binding 가중합
Particle Animation Target
   ↓ + Max Distance
NvCloth Motion Constraint Sphere
```

`Max Distance == 0`인 Particle은 애니메이션에 고정되고, 값이 커질수록 Target 주변에서 더 자유롭게 움직인다. 고정 Particle도 매 Tick 현재 Target으로 갱신해 캐릭터를 따라가게 한다.

이때 Previous Particle을 매번 Target으로 덮어쓰지 않는다. 현재와 이전 위치가 속도를 결정하므로 매 Tick 둘 다 초기화하면 관성과 흔들림이 사라진다. 첫 초기화, 순간이동, 리그 전환, 렌더 억제 상태가 바뀐 경우에만 Previous Position까지 Reset한다.

### Constraint를 두 방식으로 저작

초기 망토는 높이를 기준으로 상단을 고정하는 `HEIGHT_RATIO` 방식을 사용했다. 빠르게 적용할 수 있지만, 머리카락이나 곡선형 부착 경계처럼 높이만으로 자유도를 표현하기 어려운 Mesh에는 맞지 않는다.

이를 위해 `AUTHORED_WEIGHTS` 방식을 추가했다. 정점별 0~1 Weight를 직접 제공하거나 JSON에서 읽고 Max Distance로 변환한다. JSON에는 Simulation Mesh Index, Vertex Count, Mesh Signature를 함께 저장해 다른 버전의 Mesh에 오래된 Weight가 잘못 적용되는 상황을 Load 단계에서 차단한다.

현재 망토는 기존 Height Ratio와 호환되며, Authored Weight 경로는 향후 머리카락과 복잡한 Cloth 경계를 위한 기반이다. 머리카락 전용 Attachment와 콘텐츠는 아직 구현 범위에 포함하지 않았다.

## 몸 관통을 줄이는 Backstop과 충돌 리그

Motion Constraint는 Particle이 애니메이션 Target에서 얼마나 멀어질 수 있는지만 제한한다. 몸의 어느 방향을 통과하면 안 되는지는 알려주지 않는다. 각 Particle의 애니메이션 Normal을 이용해 Separation Sphere, 즉 Backstop을 추가했다.

```text
Animated Target ●──── 허용 이동 영역
                 ◯   Backstop Sphere
                몸 안쪽 진입 제한
```

Backstop Radius와 Offset으로 구의 위치를 정하고, 망토 상단에서 하단으로 갈수록 영향이 완만하게 줄어들도록 Smoothstep Profile을 적용한다. 빗자루 탑승 중에는 별도 Offset·Fade·Minimum Influence Profile을 사용한다. 하단 Particle의 Backstop을 완전히 없애면 수직 상승 때 망토가 몸 아래로 통과하기 쉬워지므로 최소 영향도를 남길 수 있게 했다.

Backstop만으로 몸의 전체 부피를 표현할 수 없어 Bone 기반 Collision Rig도 함께 사용한다. Rig는 Sphere와 Capsule 같은 단순 Primitive, 대상 Bone 이름, Local Transform을 데이터로 보관한다. 매 Fixed Tick 현재 Bone 자세를 Simulation Space로 변환해 NvCloth Collision에 전달한다.

일반 상태와 빗자루 상태는 서로 다른 리그를 사용한다.

- 기본 Body Rig: 척추·목·어깨를 중심으로 캐릭터 몸통을 보호
- Broom Body Rig: 탑승 자세에 맞춘 신체 충돌 범위
- Broom Object Rig: 빗자루 자체가 망토를 관통하지 않도록 추가

부착 객체의 Cached Combined Matrix는 Fixed Update 시점에 한 Frame 늦을 수 있다. 빗자루 Collision은 현재 Local Transform과 Parent World를 즉시 조합해 World Matrix를 만들고, 이를 Simulation Space로 변환한다. 렌더 메시와 파란 Collision Debug Shape가 어긋났던 원인을 갱신 순서에서 해결한 부분이다.

## Fixed Step 실행 순서

게임의 Fixed Tick에서 GameObject가 먼저 Cloth 입력을 준비한 뒤 PhysX, NvCloth 순서로 Simulation을 진행한다.

```text
GameObject FixedUpdate
   ├─ 탑승 상태에 맞는 Collision Rig 후보 준비
   ├─ Attachment Transform·Animation Constraint 갱신
   ├─ 런타임 Solver Profile 선택
   ├─ 이상 Particle 검사와 복구
   ├─ 이동 속도 기반 Virtual Wind 갱신
   └─ Bone·Broom Collision 갱신
        ↓
PhysX StepSimulation
        ↓
NvCloth beginSimulation
   → simulateChunk × N
   → endSimulation
        ↓
LateUpdate에서 Render Group 등록
```

Simulation에 전달하는 Delta Time은 엔진의 Scaled Fixed Delta다. Time Scale이 0이면 PhysX와 NvCloth Step을 모두 건너뛰므로 정지 중에 Cloth만 계속 흐르지 않는다. Slow Motion에서는 다른 물리와 같은 시간축을 사용한다.

리그를 바꾸는 Tick에는 새 Collision을 적용할 준비가 모두 끝난 뒤 상태를 Commit한다. 중간 단계가 실패하면 기존 프로필을 유지하고, 부분적으로 갱신된 자세는 렌더하지 않은 채 다음 Fixed Tick에서 다시 동기화한다.

## 이동 속도를 바람으로 변환

빗자루 이동에서는 실제 World Wind보다 캐릭터의 상대 속도가 시각적으로 더 중요하다. Character Motor Velocity의 반대 방향을 목표 풍속으로 만들고, 지수 응답식으로 현재 풍속을 보간한다.

```text
targetWind = externalImpulse - characterVelocity × velocityScale
blend = 1 - exp(-response × fixedDelta)
currentWind = lerp(currentWind, targetWind, blend)
```

단일 사인파만 사용하면 망토가 기계적으로 반복된다. 서로 다른 주기의 파형을 섞어 횡방향 Flutter와 저주파 Gust를 만들고, 수평 속도가 임계 구간에 들어오면 Smoothstep으로 강도를 높인다. 수직 성분에는 고속 증폭을 적용하지 않아 상승 중 몸 관통이 다시 심해지는 것을 막았다.

최종 풍속은 최대값으로 Clamp한다. 외부 Gameplay는 제한 시간 동안의 Wind Impulse를 추가할 수 있고, 대시처럼 망토 렌더를 억제하는 동안에는 Wind와 누적 관성을 제거한다. 다시 표시할 때 현재 Animation Pose에서 Simulation을 재시작한다.

## 고속 수직 이동 안정화

빗자루의 급상승·급하강에서는 한 Fixed Tick 동안 Attachment가 크게 이동한다. 이때 낮은 Solver 반복과 강한 수직 관성이 겹치면 Particle이 몸 뒤로 넘어가거나 유효 범위를 벗어날 수 있었다.

Motor의 수직 속도와 Tick 간 차분으로 가속도를 구하되, 차분 노이즈가 과장되지 않도록 저역 통과 필터를 적용했다. 속도 또는 가속도가 진입 임계값을 넘으면 고부하 Profile로 전환한다.

- Solver Frequency: 기본 60Hz, 고부하 120Hz
- 빗자루 수직 Linear Inertia: 기본값보다 낮게 제한
- 진입·해제 임계값 분리: 경계에서 60/120Hz가 반복 전환되는 현상 방지
- 검증 간격: 평상시 30 Tick, 고부하 상태 10 Tick

Frequency를 항상 높이지 않고 문제가 발생하기 쉬운 구간만 비용을 지불한다. Hysteresis를 둬 설정 변경 자체가 흔들림의 원인이 되지 않게 했다.

Attachment가 설정 거리보다 이동하거나 Quaternion 각도가 임계값을 넘으면 Teleport로 판단한다. NvCloth의 현재·이전 Transform과 Particle Previous Position을 함께 재설정해, 순간 이동량이 거대한 가짜 속도로 변환되지 않게 한다.

## Simulation 검증과 복구

고속 이동 안정화만으로 모든 외부 입력과 수치 오류를 막을 수는 없다. 현재 클라이언트가 사용하는 CPU Backend에서는 빗자루 상태일 때 일정 간격으로 Particle을 읽어 다음을 검사한다.

- Position에 NaN 또는 Infinity가 포함됐는가
- Animation Target과 Particle 사이 거리가 허용 범위를 크게 벗어났는가
- 한두 개가 아닌 넓은 영역에서 이탈했는가
- 경고 범위 이탈이 연속 Sample에서 유지되는가

Soft 범위 이탈은 먼저 기록하고, Hard Runaway·광범위 이탈·지속 이탈일 때만 복구한다. 순간적인 큰 Flutter까지 매번 Reset하지 않기 위한 구분이다.

복구 시에는 누적 Wind와 Impulse를 제거하고 현재 Animation Target으로 현재·이전 Particle을 모두 되돌린다. 다음 Tick부터 Wind를 다시 부드럽게 적용한다. 복구 횟수, Runaway 횟수, 경고 Particle 수, 최대 이탈 거리는 GUI에서 확인할 수 있다.

DX11 Backend에서는 같은 검사가 GPU Readback 동기화를 유발할 수 있어 자동 검증을 수행하지 않는다. Backend별 비용 구조를 숨기지 않고 검증 정책도 분리했다.

## CPU와 DX11 Backend를 같은 렌더 경로로 연결

Manager는 CPU와 DX11 NvCloth Factory를 모두 지원한다. 현재 게임은 실제 부하 측정 결과를 바탕으로 CPU Backend를 선택했다. GPU라는 이유만으로 소수 Cloth에서도 항상 빠른 것은 아니며, Dispatch·동기화·Readback 비용까지 포함해 판단해야 했다.

렌더러에는 Backend와 관계없이 `NVCLOTH_RENDER_PARTICLE_VIEW`를 제공한다.

| Backend | Render Particle 제공 방식 |
| --- | --- |
| CPU | Simulation 후 Dirty 표시, 필요한 Render 시점에 Dynamic Buffer로 업로드 |
| DX11 | NvCloth GPU Particle Buffer의 현재 Offset으로 SRV 생성 |

Vertex Shader는 `ByteAddressBuffer`에서 세 Particle을 읽고 Barycentric Position과 Local Frame을 재구성한다. 같은 변형 함수를 일반 Pass뿐 아니라 Directional·Spot Shadow와 Point Shadow에도 적용해, 화면의 망토와 그림자 형상이 서로 다르게 움직이지 않게 했다.

망토는 두께가 없는 면이므로 고속 이동 중 Normal 방향이 뒤집혀도 통째로 사라져 보이지 않도록 No-Cull Rasterizer로 양면 렌더한다. Draw가 끝나면 기존 Rasterizer와 SRV 상태를 복원해 다른 Render Object에 영향을 주지 않는다.

## 디버깅과 성능 판단

Manager GUI에서는 Backend, Fabric·Cloth Handle, Particle·Constraint·Virtual Particle 수, Render SRV 상태를 확인할 수 있다. Debug Renderer로 Particle, Fabric Edge, Motion Constraint Weight, Bone Collision Primitive를 표시해 물리 결과와 Render Mesh의 불일치를 분리해서 추적했다.

Tracy Zone은 Fabric 생성, Cloth 생성, Animation Constraint 갱신, Simulation의 Begin·Chunk·End, CPU Particle Upload를 각각 나눈다. 전체 `NvCloth` 비용만 보는 대신 Cook·Solver·Upload 중 어느 단계가 병목인지 확인할 수 있다.

## 구현 결과 {/* #결과 */}

물리용 저해상도 메시와 화면용 고해상도 메시를 분리하면서도 Barycentric Mapping으로 하나의 자연스러운 망토처럼 렌더했다. Character Animation은 Particle별 Motion Constraint로, 몸과 빗자루는 Backstop과 Bone Collision Rig로 연결했다.

또한 Teleport 감지, 고속 수직 이동 전용 Solver Profile, 풍속 Clamp, Runaway 검증·복구를 단계적으로 추가해 일반 보행부터 빗자루 급상승까지 같은 Cloth Component를 유지할 수 있게 했다. 이 구조는 망토 하나에 종속되지 않고, Authored Weight와 별도 Rig Profile을 제공하면 치마·장식 천·머리카락처럼 부착 경계가 다른 시뮬레이션에도 확장할 수 있다.
