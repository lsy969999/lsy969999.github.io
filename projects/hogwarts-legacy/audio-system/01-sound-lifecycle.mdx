# FMOD 사운드 재생과 생명주기 관리

## 배경과 목표 {/* #문제 */}

게임의 사운드는 파일을 한 번 재생하는 것보다 수명 관리가 더 중요했다. 같은 효과음은 여러 객체가 동시에 재생할 수 있고, 반복 BGM은 레벨이 바뀌거나 플레이어가 사망할 때 자연스럽게 사라져야 한다. 3D 효과음은 객체를 따라 이동해야 하며, 재생이 끝난 Channel과 이를 보유한 Component의 참조도 안전하게 정리되어야 한다.

FMOD Channel Pointer를 게임 코드가 직접 보관하는 방식은 다음 문제를 만들었다.

- 자연 종료된 Channel을 다시 제어할 수 있다.
- 동일한 사운드의 여러 재생 인스턴스를 구분하기 어렵다.
- FMOD Callback Thread에서 게임 객체를 직접 변경하게 된다.
- 재생 중 Resource가 제거되면 `FMOD_SOUND`의 수명이 Channel보다 먼저 끝날 수 있다.
- Fade 도중 새로운 Fade를 요청하면 현재 들리는 볼륨에서 이어지지 않고 튈 수 있다.

이를 해결하기 위해 Resource, 재생 Instance, Component 소유권을 분리했다.

```text
Sound File Path
   ↓
CResFmodSound ── 경로 기반 공유 Resource
   ↓
CSoundManager ── SOUND_ID와 FMOD Channel 관리
   ↓
CComSound ────── GameObject 단위 소유권과 Named Slot
   ↓
Gameplay / Ambient Object
```

## 경로 기반 Sound Resource

`CResFmodSound`는 `FMOD_SOUND*`를 엔진 Resource로 감싼다. Sound Manager는 입력 경로를 정규화한 뒤 공용 Resource Manager의 Path Cache에서 기존 Resource를 찾고, 없을 때만 새로 생성한다.

같은 파일을 여러 객체가 재생해도 Sound Data는 한 번만 로드하고 Channel만 각각 만든다. Resource는 별도의 `SOUND_RESOURCE` Group에도 등록해 Preload, 개별 경로 제거, 전체 제거를 지원한다.

두 가지 Load 방식을 호출 시점에 선택한다.

| Load Type | 용도 |
| --- | --- |
| `SAMPLE` | 짧고 반복 재생되는 효과음을 메모리에 로드 |
| `STREAM` | 긴 BGM과 Ambient를 스트리밍 |

재생 중인 `SPlayingSound`는 `shared_ptr<CResFmodSound>`를 보관한다. Resource Manager의 Registry에서 항목을 제거하더라도 활성 Channel이 사용하는 Sound Resource는 마지막 재생이 끝날 때까지 살아 있다.

Resource를 명시적으로 제거할 때는 해당 경로를 재생 중인 Channel을 먼저 정지한 뒤 Registry에서 제거한다. 전체 Resource 제거도 모든 Channel을 먼저 멈추고 Sound Group을 비운다.

## Channel Pointer 대신 SOUND_ID 사용

사운드를 재생하면 외부에는 FMOD Pointer 대신 64비트 `SOUND_ID`를 반환한다. `0`은 Invalid 값으로 예약하고, Manager는 현재 사용 중인 ID와 충돌하지 않는 값을 생성한다.

```cpp
struct SPlayingSound
{
    std::shared_ptr<CResFmodSound> pSound;
    FMOD_CHANNEL* pChannel;
    SOUND_BUS_ID sBusID;
    bool b3D;
    SOUND_3D_DESC t3DDesc;
};
```

게임 코드는 ID로 다음 기능을 요청한다.

- Stop, Pause
- Volume, Pitch
- Fade, Fade-out 후 Stop
- 3D Position·Velocity 갱신
- Min·Max Distance 변경
- 재생 및 유효 상태 확인

ID가 활성 Map에 없으면 이미 종료되었거나 명시적으로 정지된 사운드다. 게임 객체는 FMOD Channel의 내부 재사용 정책을 알 필요가 없다.

## 설정을 끝낸 뒤 재생 시작

`Play2D()`와 `Play3D()`는 공통 `PlayInternal()`을 사용한다. FMOD Channel을 Paused 상태로 먼저 생성하고 다음 설정을 모두 적용한다.

- 2D 또는 3D Mode
- Loop 여부
- Volume과 Pitch
- Channel Priority
- 3D Position·Velocity
- Min·Max Distance와 Rolloff 방식
- 종료 Callback과 SOUND_ID

하나라도 실패하면 Channel을 즉시 정지하고 Invalid ID를 반환한다. 설정이 완료된 Channel만 요청된 Pause 상태로 전환하므로, 기본값으로 한 Frame 재생된 뒤 속성이 바뀌는 현상을 피한다.

```cpp
SOUND_PLAY_DESC playDesc{
    .sBusID = SOUND_BUS_ID{"SFX"},
    .fVolume = 0.8f,
    .fPitch = 1.f,
    .iPriority = 96,
    .bLoop = false
};

const SOUND_ID soundID = soundManager->Play2D(path, playDesc);
```

## FMOD Callback과 Main Thread 경계

Channel의 자연 종료는 FMOD Callback으로 전달된다. 이 Callback은 게임의 Main Thread가 아닌 FMOD 내부 Thread에서 실행될 수 있으므로 `m_mapPlayingSounds`나 GameObject를 직접 수정하지 않는다.

Channel User Data에 저장한 `SOUND_ID`만 꺼내 Mutex로 보호된 완료 Queue에 넣는다.

```text
FMOD Channel 종료
   ↓ FMOD Callback Thread
Completed SOUND_ID Queue
   ↓ Main Thread Update
FlushCompletedSounds()
   ↓
Playing Sound Map에서 제거
```

Main Thread의 Sound Manager Update는 `FMOD_System_Update()` 이후 Queue를 Swap해 가져오고 완료된 ID를 제거한다. Callback Thread가 Map의 Iterator나 Resource 소유권을 건드리지 않게 만든 경계다.

## GameObject 단위 소유권과 Named Slot

`CSoundManager`가 전체 재생 Instance를 관리한다면, `CComSound`는 한 GameObject가 시작한 사운드를 관리한다. Component는 자신이 만든 ID를 Set에 보관하고 소멸할 때 모두 정지한다.

효과음 하나를 이후에 다시 제어해야 할 때 매번 ID를 멤버로 추가하지 않도록 `StringID` 기반 Named Slot을 제공한다.

```cpp
pSound->PlaySlot2D(
    StringID{"SPELL_VOICE"},
    soundPath,
    playDesc,
    SOUND_SLOT_PLAY_MODE::REPLACE);
```

Slot에는 두 가지 재생 정책이 있다.

- `REPLACE`: 같은 Slot의 기존 Sound를 정지하고 새 Sound 재생
- `OVERLAP`: 같은 Slot에 여러 Sound ID를 함께 보관

이후 `StopSlot`, `SetSlotVolume`, `SetSlotPitch`, `FadeSlotTo`처럼 의미 있는 이름으로 묶어서 제어한다. Component Update에서는 Manager에서 이미 자연 종료된 ID를 확인해 소유 Set과 Slot 참조를 함께 정리한다.

## Fade 후 소유권 분리

일반 `FadeOutAndStopSlot()`은 Component가 ID를 계속 보유한 상태로 Fade 종료를 기다린다. 하지만 레벨 BGM이나 Ambient Object가 제거되는 순간에도 Fade가 계속 들려야 하는 경우가 있다.

`FadeOutAndDetachSlot()`은 Fade-out과 정지를 Sound Manager에 예약한 뒤, 성공한 ID를 Component의 소유 Set과 Slot에서 제거한다.

```text
Ambient Object 제거
   ↓
FadeOutAndDetachSlot
   ├─ Component: ID 참조 제거
   └─ Sound Manager: Channel과 Resource 계속 보유
                         ↓ Fade 종료
                    FMOD Callback으로 정리
```

GameObject 수명과 남아 있는 소리의 수명을 분리해 레벨 전환 시 BGM이 갑자기 끊기는 문제를 피할 수 있다.

## DSP Clock 기반 Fade

Fade는 Frame Delta를 누적해 Volume을 매 Frame 변경하는 방식이 아니라 FMOD의 DSP Clock과 Fade Point를 사용한다. 초 단위 Duration을 Software Sample Rate와 곱해 종료 Clock을 계산한다.

```text
durationTicks = ceil(durationSeconds × sampleRate)
endClock = currentParentClock + durationTicks
```

현재 Clock과 종료 Clock에 각각 Fade Point를 배치하면 Audio Thread가 Sample 단위로 Volume을 보간한다. 게임 Frame이 일시적으로 느려져도 Fade 속도가 Frame Rate에 의존하지 않는다.

`FadeOutAndStop()`은 목표 Volume을 0으로 설정하고 종료 Clock에 Channel Stop Delay도 함께 예약한다. 따라서 Update에서 남은 시간을 직접 계산하거나 0이 되는 순간을 Polling하지 않는다.

## 연속 Fade의 시작 Volume 보존

Fade 도중 새로운 Fade를 요청할 때는 기존 Fade Point를 지우기 전에 현재 들리는 실제 Volume을 계산해야 한다. 현재 DSP Clock이 두 Point 사이에 있으면 두 Volume을 선형 보간한다.

FMOD는 완료된 Fade Point를 이후 조회에서 제거할 수 있다. 이때 Channel 기본 Volume만 읽으면 마지막 목표값이 아니라 정규화 과정에서 설정한 `1.0`이 나올 수 있다. `SPlayingSound`는 마지막 Fade 목표를 별도로 보관해 다음 Fade가 그 값에서 이어지도록 한다.

새 Fade 예약 과정은 다음과 같다.

1. 기존 Fade Point와 현재 DSP Clock으로 실제 출력 Volume 계산
2. 완료된 Fade라면 저장해 둔 마지막 목표 Volume 사용
3. 기존 Fade Point와 Stop Delay 제거
4. Channel 기본 Volume을 1로 정규화
5. 현재 Volume과 새로운 목표 Volume에 Fade Point 추가
6. Fade-out이면 종료 Clock에 Stop 예약

중간 단계가 실패하면 Fade Point와 Delay를 제거하고 계산해 둔 현재 Volume으로 복구한다. Fade 재예약 실패가 갑작스러운 음량 변경으로 이어지지 않게 한 것이다.

## Bus 단위 제어

개별 Channel 외에도 `StringID` 기반 Sound Bus를 제공한다. 초기화 시 FMOD Master Channel Group을 `MASTER` Bus로 등록하고, Client가 만든 Bus는 Master 아래에 연결한다.

Bus 단위로 다음 기능을 적용할 수 있다.

- Volume과 Fade
- Mute와 Pause
- Bus에 속한 모든 Sound 정지
- Runtime Bus 생성과 제거

BGM, SFX, UI, Voice를 Bus로 나누면 옵션 화면이나 장면 전환에서 개별 Sound ID를 순회하지 않고 그룹 전체를 제어할 수 있다. Bus Fade도 Channel과 동일하게 DSP Clock을 사용한다.

## 3D Sound와 Listener

3D Sound는 Position·Velocity, Min·Max Distance와 Rolloff 정책을 가진다. Inverse Rolloff는 현실적인 거리 감쇠에, Linear Rolloff는 연출상 명확한 범위가 필요할 때 사용한다.

매 Frame 활성 Camera의 Position, Forward, Up을 FMOD Listener 0에 반영한다. `CAmbientSound3DObject`는 Transform 위치가 실제로 변경된 경우에만 Slot의 3D Attribute를 갱신한다.

Debug GUI에서 3D Sound 범위를 켜면 Min Distance는 노란 구체, Max Distance는 청록 구체로 표시한다. 감쇠가 시작되는 지점과 완전히 멀어지는 범위를 게임 화면에서 직접 조정할 수 있다.

## 데이터 기반 Ambient Sound

2D와 3D Ambient Sound는 직렬화 가능한 Data와 Runtime GameObject로 나눴다.

데이터에는 경로, 위치, 음량, Pitch, Fade 시간, Priority, Bus, Load Type, Loop·Auto Play·Enabled 상태가 들어간다. 3D 데이터는 Min·Max Distance와 Rolloff도 가진다.

Runtime Object는 데이터를 정리한 뒤 Auto Play를 수행하고, Inspector에서 Play·Stop·Fade를 시험할 수 있다. 데이터를 다시 적용할 때는 기존 Sound를 정리하고 이전 재생 상태와 Auto Play 정책에 맞춰 재생을 복원한다.

## 종료 순서

Sound Manager를 해제할 때는 Master Bus를 먼저 정지하고 활성 Sound Map을 비운다. Map의 `shared_ptr<CResFmodSound>`가 해제되면서 `FMOD_SOUND`가 FMOD System이 살아 있는 동안 정리된다.

그다음 사용자 Bus를 해제하고, FMOD System의 User Data를 끊은 뒤 Close와 Release를 수행한다. 마지막으로 Callback 완료 Queue를 비운다.

이 순서는 Channel과 Sound Resource가 FMOD System보다 늦게 해제되는 상황을 방지한다. Resource Manager의 Registry가 먼저 사라지더라도 활성 재생 Map이 Resource의 실제 수명을 유지한다.

Sound Resource 중복 로드를 방지하면서 동일 파일의 여러 재생 Instance를 독립적으로 제어할 수 있게 됐다. 자연 종료 Callback, Component 제거, 레벨 전환, Resource 삭제와 Engine 종료가 서로 다른 시점에 발생해도 각 소유 계층이 맡은 범위에서 안전하게 정리된다.

또한 DSP Clock Fade, Named Slot, Bus, 3D Listener와 Ambient Object를 공통 API로 연결해 BGM·효과음·환경음을 같은 Runtime 체계에서 재생하고 조정할 수 있게 했다.
