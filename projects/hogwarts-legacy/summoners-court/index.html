소환사의 코트 — 물리 판정을 턴제 경기로 연결하기

목표와 담당 범위​

소환사의 코트는 아씨오로 공을 끌어와 점수 구역에 멈추게 하는 미니게임이다. 공을 움직이는 기능 외에도 누구의 턴인지, 언제 점수를 확정할지, 상대 공에 밀려 기존 점수가 바뀌면 어떻게 반영할지, NPC가 언제 공을 놓을지를 결정해야 했다.

경기 규칙과 점수 판정, NPC 턴 제어, 대화·사운드·UI 연결을 구현했다. 팀의 GameObject·PhysX·Animation·UI 기반을 사용했으며, UI 프리팹과 퀘스트 연동은 담당 팀원과 연결했다.

공의 Force·Torque와 조작권 API는 아씨오와 고대마법 투척에서 설명한다. 이 문서는 물리 동작을 경기 전체의 진행으로 연결한 부분에 집중한다.

경기 규칙과 NPC 행동의 책임 분리​

구성책임
CAccioActivity_Base참가자·공 등록, 조작 규칙, 턴·라운드, 점수 판정
CAccioBall실제 물리 이동, 조작권, 정지 상태, 구름·충돌 사운드
CAccioActivity_NpcController전략 선택, 이동 위치, 조준·당김·해제, 대화 진행
CAccioActivity_NpcCharacter실제 NPC Pawn의 이동·Animation·외형
UIManager경기 UI 생성, 점수 표시 순서, 결과 표시와 HUD 복원

NPC 판단용 Controller와 실제 캐릭터를 분리했다. 경기 참가자와 공의 제어자로 등록하는 Handle은 Controller가 아니라 실제 NPC Character의 Handle이다. 공은 제어자의 위치를 향해 당겨지므로 이 구분이 물리 동작에도 영향을 준다.

경기 Base는 NPC가 어떤 Animation을 재생하는지 알 필요가 없고, NPC는 점수를 직접 확정하지 않는다. 둘은 경기 상태와 공 조작 API를 통해 협력한다.

입력 해제와 턴 종료를 분리​

현재 경기는 기본 3라운드이며 라운드마다 양쪽이 공 하나씩 사용한다. 선공은 설정으로 바꿀 수 있다. 플레이어 선공일 때의 기본 흐름은 다음과 같다.

Plain Text
READY
  ↓ 시작 검증·초기화·경기 UI 준비
PLAYER_TURN
  ↓ 플레이어가 공의 조작권 해제
WAIT_PLAYER_BALL_SETTLED
  ↓ 경기장 안의 공 정지·점수 표시 처리
NPC_TURN
  ↓ NPC가 공의 조작권 해제
WAIT_NPC_BALL_SETTLED
  ↓ 공 정지·점수 표시 처리
다음 라운드 또는 MATCH_END

입력을 놓은 순간에도 공은 관성으로 움직이고 다른 공과 충돌할 수 있다. 따라서 조작권을 해제하면 바로 다음 턴으로 넘기지 않고 별도의 WAIT 상태로 진입한다.

조작한 공만 기다리지도 않는다. 경기장 안에 있는 등록 공 전체의 정지 상태를 확인한다. 상대 공을 밀어낸 뒤 아직 그 공이 움직이고 있는데 결과를 확정하는 상황을 피하기 위해서다.

경기장 밖으로 벗어난 공은 정지 대기 대상에서 제외한다. 낙하한 공이 계속 움직이거나 바닥에 도달하지 않아 경기 전체가 기다리는 것을 방지한다. 경기장 안 여부는 보드의 로컬 XZ 범위와 하단 높이를 기준으로 검사하며, 별도의 접촉 지지면 검사는 아니다.

조작 가능 여부를 경기 규칙으로 일원화​

Base의 CanControlBall은 경기 상태, 참가자, 공 색상, 이미 사용한 공인지, 다른 공이 활성 상태인지를 검사한다. 플레이어는 Blue, NPC는 Red 공을 사용한다.

공을 획득하면 활성 공 Handle을 기록하고, 해제하면 사용한 공 Set에 넣은 뒤 해당 참가자의 정지 대기 상태로 전환한다. 같은 턴에 다른 공을 바꾸어 잡거나, 상대 공을 직접 조작하거나, 사용한 공을 다시 당기는 것을 제한한다.

READY에서는 경기 측 제약을 완화해 자유 테스트가 가능하지만, 공 자체의 중복 제어 검사는 유지된다. UI 선택 표시와 실제 공 획득도 같은 규칙을 사용하도록 연결했다.

경기 시작 전에는 참가자 Handle과 등록 공을 검증한다. 양쪽 모두 라운드 수만큼의 공이 있어야 하며, 삭제 예약된 공이나 색상이 없는 공은 허용하지 않는다. 실제 진행 중에도 참가자·공이 사라졌는지 검사하고, 유효성을 잃으면 경기를 종료하고 활성 조작과 경기 UI를 정리한다.

Trigger는 후보 추적, 점수는 정지한 공 중심으로 확정​

보드의 점수 구역은 10·20·30·50점 Trigger Shape로 구성한다. 각 Shape에 해당 값을 SubIndex로 등록하고, OnTriggerEnter/Exit의 자기 Shape SubIndex로 어느 구역인지 구분한다. 구역마다 별도의 Trigger GameObject를 만드는 대신 같은 Base에서 구분할 수 있도록 했다.

공은 경계에서 두 Trigger와 동시에 겹칠 수 있다. 그래서 공 Handle별로 구역 Bit Mask를 보관하고 진입·이탈 때 해당 Bit만 갱신한다. Trigger 진입만으로 점수를 더하지는 않는다.

점수 확정에는 두 조건이 필요하다.

  1. 해당 공이 실제 턴에 사용되었을 것
  2. 공의 IsSettled()가 참일 것

조건이 충족되면 현재 RigidBody 중심을 점수 구역의 로컬 좌표로 변환해 최종 구역을 결정한다. 공유 경계에서는 50 → 30 → 20 → 10 순서로 검사해 높은 점수를 우선한다. 구체 표면이 높은 점수 Trigger에 조금 닿았다고 그 점수를 받는 방식은 아니다.

이 좌표 변환에는 구역의 로컬 배치와 보드 Actor의 회전을 함께 사용한다. 보드를 World에 회전 배치해도 고정된 World Z값만으로 점수를 판단하지 않도록 했다.

상대 공을 밀어내면 기존 점수도 다시 계산​

이미 점수가 확정된 공이 충돌로 깨어나 다시 움직이면 확정 점수를 지운다. 다시 정지하면 새 위치에서 점수를 확정하고, 모든 점수 Trigger에서 빠져나가면 점수 추적 항목을 제거한다.

양 팀의 합계는 확정된 공 점수를 합산해 계산한다. 매 턴 점수만 누적하는 방식이 아니므로 이전에 50점을 얻은 공이 밀려나 0점이 되는 변화도 반영할 수 있다.

UI에도 이번 공의 점수뿐 아니라 현재 Player·NPC 총점을 함께 전달한다. 그래야 상대 공의 점수 감소를 단순한 ‘이번 턴 득점 추가’와 구분해 표시할 수 있다.

점수 UI가 끝나는 시점과 다음 턴 연결​

경기 시작 시 기존 HUD를 숨기고 Coat UI 프리팹을 준비한다. 필수 UI를 확보하지 못하면 StartMatch를 실패시켜 보이지 않는 경기를 시작하지 않는다.

공의 결과가 정해지면 Base가 AddScore를 요청한다. UI가 이전 표시를 처리 중이라 요청을 받지 못하면 다음 Tick에 다시 시도한다. 수락되면 제출 플래그를 세워 같은 점수를 중복 제출하지 않는다.

일반 턴은 UI가 다음 점수를 받을 수 있는 상태로 돌아온 뒤 전환한다. 마지막 점수는 MATCH_END로 넘어갈 수 있지만, 결과 대화는 최종 점수·승패 UI가 모두 종료된 뒤에만 시작한다. 물리 결과, 점수 표시, 결과 대화의 완료 시점을 각각 구분한 것이다.

이 구조에서 점수의 원본은 Base이며 UI는 전달된 결과를 표현한다. 다만 현재 Base가 UIManager의 준비 상태를 직접 조회하므로 UI와 경기 진행이 완전히 독립적인 구조는 아니다.

NPC는 같은 공 조작 API로 플레이​

NPC의 기본 행동은 다음 순서로 진행한다.

Plain Text
IDLE → MOVING → AIMING → PULLING
                            ↓ 조작권 해제
                     PULL_RECOVERY
                            ↓ Animation 마무리
                     WAIT_BALL_SETTLED
                            ↓ 경기 Base가 결과 확정
                         RETURNING

NPC는 조작 가능한 Red 공을 찾고, 설 위치를 계산해 이동한 뒤 조준한다. 공은 플레이어와 동일한 TryAcquireControl·ReleaseControl API로 제어한다. 점수를 맞추기 위해 공을 목적지로 순간 이동시키는 방식은 아니다.

조준 지연이 끝나면 계획을 다시 계산한다. 이동·조준 중 다른 공 배치가 바뀌어 새로운 위치가 필요하면 다시 이동한 뒤 조작한다. 공이 사라지거나 조작권 획득에 실패하면 턴을 중단하고 가능한 경우 Skip 경로로 넘긴다.

공을 놓은 직후에는 걷기 시작하지 않고 당김 Animation의 나머지를 먼저 마친다. 이후 Base가 공 정지·점수 처리를 끝낼 때까지 지켜보고 대기 위치로 복귀한다.

득점과 상대 공 밀어내기 전략​

기본 전략은 SCORE다. NPC 이동 영역의 로컬 좌표에서 자기 공과 X를 맞춘 위치로 이동해 정해진 시간 동안 당긴다. 이 위에 조건을 만족하는 ATTACK 계획이 있으면 상대 공을 밀어내는 전략으로 바꾼다.

공격 후보와 가능한 시전 위치​

공격 후보는 이미 사용되어 점수를 얻은 플레이어 공 중에서 고른다. 기본 최소 점수는 30이므로 50점·30점 공을 높은 점수 순으로 검사한다. 같은 점수에서는 등록 순서를 유지해 판단이 불필요하게 바뀌지 않도록 한다.

NPC의 선택 공에서 공격할 공으로 향하는 선을 NPC의 이동선까지 연장하면, 해당 공을 향해 당길 수 있는 시전 위치가 나온다. 이 위치가 이동 영역 밖에 있거나 목표가 당김 방향의 유효한 구간에 없으면 후보를 제외한다.

항상 정중앙만 충돌시키지 않도록 목표 공 중심에 좌우 Offset을 더한다. Offset의 방향과 크기는 턴 계획을 준비할 때 정하고 같은 턴의 재계산에 재사용한다. 매 Tick마다 새로운 난수를 뽑아 시전 위치가 흔들리는 방식은 아니다.

경로에 다른 공이 있으면 계획 기각​

목표 공이 경로에서 처음 부딪히는 플레이어 공인지 확인한다. 낮은 점수 공이 먼저 있으면 그 뒤의 고득점 공을 직접 공격한다고 가정하지 않는다. 같은 경로에 NPC 공이 있으면 자기 공을 보호하기 위해 공격을 포기한다.

이 검사는 PhysX Scene Sweep이나 미래 물리 시뮬레이션이 아니다. 등록 공들의 XZ 위치와 반지름을 이용해 경로 방향 거리·옆 거리·두 반지름의 합으로 최초 접촉 거리를 추정하는 기하 검사다.

마지막으로 목표 공에서 보드 끝까지의 거리를 구한다. 너무 멀어 밀어내기 어려운 후보는 제외한다. 계획 후보를 평가하는 도중에는 현재 행동 상태를 바꾸지 않고, 완성된 ATTACK_PLAN만 한 번에 반영한다.

당김 종료 시간은 근사값​

득점 전략은 설정된 고정 당김 시간을 사용한다. 공격 전략은 예상 충돌점까지의 이동 시간에 목표 공을 가장자리로 밀어낼 거리 비례 시간을 더한다.

Plain Text
AttackPullDuration = CollisionDistance / EstimatedPullSpeed
                   + TargetDistanceToEdge × HoldSecondsPerUnit

계산값에는 최소·최대 유지시간을 적용한다. 실제 해제는 계획보다 조금 앞당기고, 별도 Pull Timeout도 둔다. 현재 기본 Lead Time은 0.12초다.

AI의 힘 계산은 게임 조정용 휴리스틱이다. 전략을 고른 뒤 공의 이동과 최종 점수는 물리 Simulation 결과에 따라 결정된다.

NPC 이동과 경기 진입·퇴장 연출​

시전 위치는 Platform이 제공하는 World OBB를 로컬 좌표로 변환해 계산한다. 따라서 플랫폼 방향에 맞춰 이동 가능 폭과 시전선을 사용할 수 있다.

이동은 목표까지의 거리로 제동 속도를 계산하고 가속·감속을 적용해 Move Intent로 전달한다. 진입·복귀·퇴장에는 별도의 곡선 경로를 사용하며, 경기 중에는 중앙 뒤쪽, 종료 후에는 측면 대기 위치로 이동한다. 이 경로는 해당 플랫폼에 맞춘 제어이며 일반적인 NavMesh 탐색을 구현한 것은 아니다.

판단 Controller는 행동을 지정하고 실제 Character가 이동·Animation을 수행한다. 경기의 공 제어자를 실제 Pawn으로 등록하는 구조와도 일치한다.

대화부터 재경기까지 하나의 흐름으로 구성​

READY 상태에서 플레이어가 상호작용 거리 안에 있으면 NPC 대화를 시작할 수 있다. 대화 데이터는 텍스트·표정 Animation·반복 여부·Sound 경로로 구성하고, 시작 대화와 승리·패배·무승부 대화를 분리한다.

대화 시작 시 플레이어 이동을 잠그고 HUD를 숨긴 뒤 Fade로 카메라 전환을 가린다. 시작 대화가 끝나면 카메라와 이동 제어를 복구하고 경기를 시작한다. 시작 검증이나 UI 준비에 실패하면 상호작용을 다시 열어 재시도할 수 있게 한다.

경기 종료 후에는 NPC가 측면 대기점으로 돌아오고 결과 UI가 끝날 때까지 기다린다. 이후 양 팀 점수를 비교해 결과 대화를 선택한다. 결과 대화가 끝나면 ResetMatch(true)로 공과 점수를 초기화하고 다시 말을 걸 수 있게 한다.

Reset은 조작권, 사용한 공 Set, 점수 상태, 라운드와 제출 플래그를 정리한다. 공은 초기 Pose로 옮기고 선속도·각속도를 지운 뒤 깨운다. 리셋 도중 공을 복구하지 못하면 실패를 반환한다.

Runtime Despawn이나 Level 정리에도 대비해 NPC Controller의 Free에서 대화 카메라·플레이어 이동 잠금·사운드·Effect·경기 UI를 정리한다. 정상 결과 화면만 종료 경로로 가정하지 않았다.

구현 결과​

공의 물리 이동 위에 참가자·턴·라운드·점수 규칙을 연결하고, 같은 조작 API를 사용하는 NPC를 구현했다. 점수는 정지한 공의 중심으로 확정하며, 충돌로 기존 공이 움직이면 총점을 다시 계산한다. NPC는 득점과 공격 계획을 선택하고 결과를 기다린 뒤 복귀한다. 대화·UI·사운드와 재경기까지 연결해 하나의 플레이 흐름으로 구성했다.
