아씨오와 고대마법 투척 — 물체의 제어권과 물리 이동

같은 ‘끌어오기’에 서로 다른 이동 방식을 선택​

소환사의 코트에서 아씨오로 공을 당길 때는 바닥 마찰, 회전, 충돌과 입력을 놓은 뒤의 관성이 남아야 한다. 반면 전투 중 배럴을 들어 던지는 고대마법은 지정한 위치로 물체를 빠르게 끌어오고, 짧게 공중에 유지한 뒤 목표를 향해 발사하는 연출의 일관성이 중요했다.

두 동작을 같은 이동 함수로 처리하지 않고 목적에 맞게 분리했다. 아씨오 공은 Dynamic RigidBody에 Force·Torque를 적용하고, 배럴은 제어 중 Kinematic으로 전환해 위치를 직접 결정한다.

현재 코드에서 배럴을 던지는 기능의 이름은 AncientThrow다. 오푸그노와 동일한 기능으로 표기하지 않으며, 이 문서는 아씨오의 공 조작 분기와 고대마법의 배럴 투척 분기를 다룬다. 몬스터 대상 아씨오와 고대마법 번개 공격 전체를 구현 범위로 포함하지 않는다.

항목아씨오 공고대마법 배럴 투척
대상CAccioBallCPropBarrel
이동 주체PhysX Dynamic SimulationState의 끌어오기 + Barrel의 Kinematic 비행
입력 해제당기는 힘 적용을 중지, 관성 유지발사 전 취소 시 Dynamic으로 복구
충돌실제 Sphere Collider의 Simulation비행 경로의 Sphere Sweep
중심 요구사항공의 물리 위치 기준모델 피벗과 시각적 중심을 분리

아씨오: State는 조작권, 공은 물리 힘을 관리​

플레이어는 자동 선택된 대상이 CAccioBall이고 조작 가능한 경우 아씨오 State를 요청한다. State는 공의 Handle을 보관하고 Animation·Effect·조작 해제를 관리한다. 실제 당기는 힘은 공의 FixedUpdate에서 계산한다.

이렇게 역할을 나누면 렌더 프레임마다 실행되는 플레이어 연출 코드에서 물리 힘을 중복 적용하지 않아도 된다. 입력으로 State를 시작하는 역할과 일정한 물리 Tick에서 운동을 계산하는 역할을 분리한 것이다.

선택 표시와 실제 획득에 같은 규칙 사용​

공은 CanAcquireControl, TryAcquireControl, ReleaseControl API를 제공한다.

CanAcquireControl은 상태를 변경하지 않고 조작 가능 여부를 검사한다. 플레이어의 대상 선택과 실제 획득이 이 검사를 함께 사용하므로, 선택 가능하게 표시한 공을 다른 규칙 때문에 잡지 못하는 불일치를 줄인다.

연결된 경기 객체가 있으면 경기 상태, 사용한 공인지 여부, 현재 활성 공, 참가자와 공 색상을 검사한다. 이미 다른 유효한 객체가 제어하는 공은 빼앗지 않으며, 기존 제어자가 삭제되었다면 새로 획득할 수 있다. 경기 READY에서는 경기 측 제한이 완화되지만 공 자체의 중복 제어 검사는 남는다.

획득하면 제어자 Handle을 기록하고 RigidBody를 깨운다. 해제는 현재 제어자와 요청자가 일치할 때만 가능하며, 경기 객체에 획득·해제를 통지한다. 공이 선택되었다는 것과 실제 조작권을 획득했다는 것을 구분했다.

현재 Physics Pose에서 당김 방향 계산​

공의 FixedUpdate는 제어자 Handle을 다시 조회하고, 제어자가 사라졌거나 PendingDestroy이면 조작권을 해제한다. 유효한 경우에는 공에서 제어자로 향하는 XZ 방향을 계산한다.

이때 공의 위치는 이전 LateUpdate의 Transform이 아니라 RigidBody의 현재 Pose에서 읽는다. 낮은 프레임률에서 한 렌더 프레임에 FixedUpdate가 여러 번 실행되어도 이미 이동한 공을 오래된 위치에서 다시 계산하지 않기 위해서다.

목표 속도를 힘으로 바꾸기​

공을 Transform으로 순간 이동시키거나 선속도를 매번 덮어쓰지 않는다. 당김 방향의 목표 속도와 현재 수평 속도의 차이를 가속도로 바꾸고, 가속도 상한을 적용한 뒤 질량을 곱해 Force로 전달한다.

Plain Text
DesiredVelocity = PullDirection × TargetSpeed
Acceleration = (DesiredVelocity - HorizontalVelocity) × Response
Acceleration = 길이를 MaxPullAcceleration 이하로 제한
Force = Mass × Acceleration

목표에 가까워지면 거리 비율에 Smoothstep을 적용해 TargetSpeed를 낮춘다. 멀리서는 빠르게 끌어오고, 근처에서는 목표 속도를 줄이는 구조다. 여기서 최대 속도는 목표 속도의 설정값이며 충돌로 발생한 모든 실제 속도를 강제로 Clamp하는 것은 아니다.

질량을 곱해 Force로 전달하므로 당김의 목표 가속도는 질량 변화에 덜 민감하다. 그렇다고 마찰·충돌 등 전체 물리 반응까지 질량과 무관해지는 것은 아니다.

회전은 Up × PullDirection으로 구름축을 만들고 Torque를 추가한다. 해당 축의 각속도가 설정 상한의 65%를 넘으면 Smoothstep으로 추가 Torque를 줄인다. 이미 상한에 도달한 경우 더 가속하지 않지만 기존 회전을 강제로 0으로 만들지는 않는다.

손을 놓았다고 공을 멈추지는 않는다​

입력을 놓으면 조작권을 해제하고 더 이상 당기는 힘을 추가하지 않는다. 기존 속도는 남으므로 공은 마찰·감쇠·충돌에 따라 계속 움직인다. 공이 어디에서 멈출지 판단하는 소환사의 코트 조작감을 위한 선택이다.

다만 거의 정지한 뒤의 미세한 움직임이 끝없이 남지 않도록, 제어 중이 아닐 때 선속도와 각속도가 모두 임계값 아래인 시간이 누적되면 Sleep시킨다. 제어 중에는 이 자동 Sleep 검사를 건너뛴다. 같은 Tick에서 힘을 가한 직후 다시 잠들면 당김이 끊길 수 있기 때문이다.

이동을 허용하면서 상체만 당김 자세 유지​

공 아씨오 State는 플레이어 이동을 허용하고 Spine1을 기준으로 상체 Animation을 재생한다. 입력을 유지하는 동안 상체 재생률이 0.45 이상에 도달하면 상체 재생 속도를 0으로 만들어 당기는 자세를 유지한다.

입력을 놓으면 속도를 1로 복구해 나머지 Animation을 이어 재생한다. 동시에 공의 조작권은 먼저 해제하므로, 시각적 마무리 때문에 공에 계속 힘을 가하지 않는다. 시작 시 공을 향하는 Facing Intent도 설정하고 해제 시 정리한다.

연출은 지팡이와 공을 연결하는 AccioBallPull, 공 주변에 붙는 AccioBallGrab으로 분리한다. 입력 중에는 Beam 양 끝점과 공 주변 Effect 위치를 갱신하고, 해제 후에는 각각의 Blend를 줄인 뒤 Stop한다. 정상 해제에서는 Animation과 Effect가 끝난 다음 Locomotion으로 복귀하지만, 강제 Exit에서는 조작권·상체 속도·Facing·Effect를 즉시 정리한다.

현재 Effect 콜백은 State의 this를 캡처하므로 State 수명과 Exit 정리에 의존한다. 모든 비동기 참조가 Handle 기반이라고 설명할 수는 없다.

해제 연출 중 재입력을 잃지 않기​

같은 State의 종료 연출이 남아 있을 때 다시 입력하면 즉시 같은 State로 진입하지 못할 수 있다. 이 경우에 한해 대상 Handle을 Pending으로 보관하고 Locomotion으로 돌아왔을 때 요청한다.

입력을 놓거나 대상이 바뀌거나 UI가 입력을 가져가면 Pending을 지운다. 피격 등 다른 State로 넘어간 경우에도 지운다. 모든 실패한 입력을 무조건 나중에 재생하는 버퍼가 아니라, 같은 아씨오의 마무리 때문에 거절되는 재입력만 보존한 것이다.

고대마법: 배럴 선택과 공격 목적지를 분리​

고대마법 투척은 던질 배럴과 맞힐 대상을 별도 Handle로 관리한다. FindAncientThrowTarget은 객체 Layer들을 순회하며 아직 파괴되지 않은 CPropBarrel을 찾고, Camera View·Projection으로 화면 안에 있는 후보를 거른다. 이후 카메라 전방과 후보 방향의 내적이 가장 큰 배럴을 선택한다.

즉 ‘가장 가까운 배럴’보다 ‘시선 중앙에 가까운 배럴’을 선택하는 방식이다. 현재는 후보 점의 화면 포함 여부만 검사하며 별도 가림 Raycast나 월드 거리 상한은 없다. 화면 안에 투영된다고 벽에 가리지 않았다는 뜻은 아니다.

State 진입 시 선택된 배럴 Handle을 소비하고 공격 목적지 Handle도 보관한다. 발사할 때 목적지를 다시 조회해 몬스터라면 HurtBox 위치를 사용한다. 타깃 객체는 시전 시작 시 정해지지만 발사 좌표는 발사 시점에 읽는 구조이며, 발사 후 지속 유도는 하지 않는다.

Dynamic 배럴의 제어권을 연출로 넘기기​

BeginAncientThrowControl은 배럴의 기존 선속도·각속도를 지우고 Kinematic으로 바꾼 뒤 Collider의 Simulation과 Query를 끈다. 이 전환에 실패하면 CancelAncientThrowControl로 복구를 시도한다.

끌어오는 동안 주변 물체와 Solver 반응을 일으키거나 플레이어가 공중의 배럴을 밟는 대신, State가 지정한 연출 위치로 이동하도록 한 선택이다. 이 구간에는 경로 Sweep도 없으므로 장애물을 피해 끌어오는 알고리즘은 아니다.

끌어오기 목표는 플레이어의 Right·Look과 높이 Offset으로 계산한다. 현재 값은 오른쪽 3, 위 4.2, 앞 1.2이며, Animation 진행률로 시작 위치에서 대기 위치까지 Smoothstep 보간하고 중간에 Sine 높이 Offset과 회전을 더한다.

피벗이 아니라 시각적 중심을 이동​

배럴 모델의 피벗은 바닥 쪽에 있다. 이 피벗을 직선 이동시키면서 회전하면 배럴 중심이 피벗 둘레를 돌아, 물체가 의도한 경로에서 흔들려 보인다.

모델 Local Bounds의 중심에 Scale을 반영해 중심 Offset을 구하고, 원하는 시각적 중심에서 회전된 Offset을 빼 실제 Actor 피벗을 계산했다.

Plain Text
VisualCenter = Pivot + Rotate(LocalCenterOffset, Rotation)
Pivot = DesiredVisualCenter - Rotate(LocalCenterOffset, Rotation)

끌어오기와 비행에 같은 보정식을 사용한다. 따라서 배럴을 회전시키면서도 시각적 중심의 이동 경로를 독립적으로 제어할 수 있다. 이것은 모델 Bounds 중심을 이용한 연출 보정이지 질량 중심을 새로 계산한 것은 아니다.

수동 자세를 설정한 뒤에는 Physics 보간 캐시도 무효화한다. Update에서 바꾼 자세가 LateUpdate의 오래된 Physics 캐시에 의해 한 프레임 되돌아가는 문제를 막기 위한 처리다.

공중 유지와 슬로모션의 시간을 분리​

끌어오기는 Animation Ratio 0.1까지 진행한다. 도착 후에는 Animation 속도를 낮추고 슬로모션·FOV 조정·Blur를 적용하며, 실시간 기준 0.5초 동안 배럴을 공중에 유지한다. 유지 중에도 회전을 이어 간다.

이 대기 시간은 Scaled Delta가 아니라 Unscaled Delta로 계산한다. 월드를 느리게 만들면서 대기 타이머까지 같은 비율로 느려져 연출 시간이 예상보다 길어지는 것을 피하기 위해서다.

Time Scale은 AncientThrow_PreLaunch 태그로 요청하고 해당 요청만 종료한다. 최대 Unscaled 지속시간도 설정해 안전 종료 경로를 둔다. 발사 후 짧은 유지 시간을 거쳐 복원하며, 강제 Exit에서도 Animation 속도·Facing·FOV·Blur·Time Scale을 정리한다. Blur는 이전 값을 저장했다가 복구하는 방식이므로 모든 후처리가 태그 기반 중첩 요청으로 관리되는 것은 아니다.

발사 이후에도 Kinematic을 유지하는 이유​

발사는 목표 방향의 선속도와 회전축의 각속도를 배럴에 전달한다. 현재 기본 선속도는 220이며, 이 값은 RigidBody에 Impulse로 적용하는 속도가 아니라 Barrel이 FixedUpdate에서 직접 적분하는 비행 속도다.

배럴은 발사 후에도 Kinematic 상태와 비활성 Collider를 유지한다. 현재 시각적 중심에서 Velocity × DeltaTime만큼 다음 중심을 계산하고, 회전된 중심 Offset을 보정해 Kinematic Target을 갱신한다.

이 구간은 공 아씨오와 달리 바닥 마찰이나 충돌 반발로 진행 방향이 변하는 Dynamic 비행이 아니다. 빠르게 목표로 날아가는 공격 연출을 직접 제어하고 충돌 검사는 별도 Query로 수행한다.

중심의 이동 구간에 Sphere Sweep​

현재 중심에서 다음 중심까지 Sphere Sweep을 수행한다. World Static·World Dynamic·Moving Platform·Enemy Body·Enemy HurtBox를 대상으로 하고 자기 객체와 Trigger는 제외한다. Player Body는 이 비행 Query Mask에 포함하지 않는다.

충돌하면 Hit Distance만큼 이동한 구체 중심에서 멈추고 피벗을 역보정한다. 충돌 Effect·소리는 별도의 Hit Position과 Normal을 사용한다. 비행 플래그를 먼저 해제하고 파괴 요청을 세워 중복 충돌 처리를 막는다.

Sweep 반지름은 모델 Bounds의 스케일 적용 Extents 중 최솟값을 기준으로 정한다. 배럴 전체를 감싸는 보수적인 구체가 아니며, 회전하는 Convex의 모든 모서리를 정확하게 검사하는 방식도 아니다. 고속 이동 구간의 판정을 보강하되 정밀한 회전 형상 Sweep까지 해결했다고 보지는 않는다.

현재 충돌 대상이 CSkillTarget이면 파괴 계열 판정을 전달하고 Impact Dust와 사운드를 재생한 뒤 파편 전환을 요청한다. 이후 자세 캡처·파편 생성·원본 제거는 Runtime Object를 PhysX Debris로 전환하는 수명주기에서 별도로 다룬다.

취소와 정상 발사를 다른 종료 경로로 처리​

발사 전 취소되면 배럴을 Dynamic으로 되돌리고 Gravity·Simulation·Query를 켜며 속도를 초기화해 현재 위치에서 물리 상태로 복귀시킨다. 끌어오기 전의 위치나 운동량까지 되감는 Undo는 아니다.

발사가 완료되면 State가 끝나더라도 배럴 비행은 계속되어야 한다. 따라서 State Exit는 아직 발사하지 않은 배럴에만 Cancel을 호출하고, 발사된 배럴의 이동·충돌은 Barrel에 맡긴다.

Hold·Flight 사운드는 배럴 Component Slot으로 관리해 각 단계에서 중지하고, Impact는 객체가 곧 제거돼도 남을 수 있도록 독립적인 사운드로 재생한다. 객체 참조가 유효한지뿐 아니라 현재 제어 단계와 종료 책임이 누구에게 있는지를 함께 관리한 것이다.

결과와 한계​

아씨오에는 관성과 충돌을 보존하는 힘 기반 제어를, 고대마법 투척에는 경로와 타이밍을 우선하는 Kinematic 제어를 적용했다. 공의 조작권·물리 Tick·상체 Animation을 분리했고, 배럴에서는 시각적 중심 보정과 Physics 캐시 무효화로 수동 제어와 물리 자세의 충돌을 줄였다.

현재 구조에서 추가로 검토할 부분도 있다.

  • 배럴 선택은 전체 Layer 순회와 화면 중심 정렬 기준이다. 대상이 많아지면 후보 Registry나 공간 Query로 범위를 줄일 수 있다.
  • 배럴에는 공과 같은 제어자 Handle 기반의 배타적 획득 API가 없다. 여러 캐릭터가 같은 배럴을 조작하려면 별도의 조작권 규칙이 필요하다.
  • 끌어오기 중에는 장애물 경로 검사가 없고, 비행에는 별도 Lifetime·최대 이동 거리 종료 조건이 없다. 빗나간 배럴을 정리하는 정책이 필요하다.
  • 공의 조작 중에는 자동 Sleep을 건너뛰지만, 비조작 상태의 저속 Sleep은 공중 여부를 별도로 확인하지 않는다. 낙하 상황까지 일반화하려면 지지면 검사를 함께 검토해야 한다.
  • Cancel은 기본 Dynamic 상태로의 복구를 시도하지만 모든 Setter 결과를 검사하는 완전한 Transaction은 아니다. 실패 로그와 복구 검증을 보강할 여지가 있다.

작성 근거와 협업 범위​

공의 물리 제어와 조작권은 AccioBall.cpp, State·상체 Animation·Effect는 Player_AccioSkill_State.cpp, 입력 연결은 Player.cpp, 경기 제약은 AccioActivity_Base.cpp에서 확인할 수 있다.

배럴 이동·Sweep·취소는 PropBarrel.cpp, 시전 타이밍·대기·발사는 Player_AncientAttack_State.cpp에 있다. 이 State는 이전의 Player_AcientAttack_State에서 이름이 수정되었으므로 기여 이력은 이름 변경을 따라 확인해야 한다.

주요 근거는 257c47a0의 AncientThrow 통합과 ee5bc43d의 Accio Activity 보강이다. 기존 플레이어 State·Animation 시스템에 물체 제어를 연결한 작업이며, 이후 팀원이 조정한 타이밍·공통 State 정리까지 단독 구현 범위로 포함하지 않는다.
