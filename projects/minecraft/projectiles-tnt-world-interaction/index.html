화살 투사체와 TNT 폭발의 월드 상호작용

배경과 목표​

화살은 발사자와 초기 속도를 기억하고, 지형에 멈추거나 엔티티를 맞힌 뒤 수명이 종료되어야 한다. TNT는 점화된 순간부터 고정된 지형 블록과 다른 상태로 움직이며, 폭발하면 지형·주변 엔티티·다른 TNT에 영향을 줘야 한다.

이 프로젝트에서는 개별 화살을 CArrowEntity로 관리하고, 점화된 TNT는 CActivatedTNT가 여러 데이터 항목으로 묶어 관리한다. 폭발의 공통 진입점은 블록 제거, 범위 피해, 소리, 연기를 함께 호출한다.

복셀 AABB 이동, 블록 편집, 인벤토리와 보관함을 전투 상호작용으로 연결한 사례다. PhysX 투사체나 메시 파편 파괴가 아니라 복셀 기반 게임 로직으로 구현했다.

점화·폭발 연기의 수명과 아틀라스 재생, 실제 GPU 출력은 CPU 파티클 시뮬레이션과 Geometry Shader 빌보드에서 별도로 설명한다.

화살과 TNT의 상태 관리 차이​

대상관리 단위주요 상태
화살화살마다 GameObject발사자 Handle, 속도, 수명, 지형에 멈춘 상태, 폭발 화살 여부
점화 전 TNT월드의 TNT 블록복셀 위치와 블록 타입
점화 후 TNT공통 오브젝트 내부의 리스트 항목위치·속도, 접지, 도화선 시간, 점멸 상태
폭발공통 함수 호출중심, 반경, 피해량, 연기 입자 수

따라서 TNT 하나를 점화할 때마다 GameObject와 렌더링 컴포넌트를 새로 만드는 구조는 아니다. 이미 배치된 89_ACTIVATED_TNT 레이어의 관리 오브젝트를 찾아 데이터를 추가한다.

화살 발사: 방향과 속도를 한 번 전달​

Shoot()는 발사자 Handle, 시작 위치, 방향, 속도, 폭발 화살 여부를 받는다. 시작점은 정규화한 방향으로 0.3만큼 앞에 놓고, 초기 속도를 방향 × 속력으로 설정한다.

Plain Text
start = requestedStart + normalize(direction) × 0.3
velocity = normalize(direction) × speed

플레이어의 활성 BOW_PULLING 경로는 머리 부근인 위치 Y + 1.8에서 카메라 Ray 방향으로 발사한다. 일반 활은 당긴 진행률에 따라 15·25·45의 초기 속도를 선택한다. 화살 보유량과 축복 상태에 따른 무한 화살·연사·폭발 화살 분기도 발사 측에서 처리한다.

스켈레톤도 같은 화살 클래스를 생성해 자신의 위치 Y + 1.5에서 목표 방향으로 속도 30을 전달한다. 확인한 추적 분기에서는 플레이어가 거리 7 이내에 있으면 정지하고, 발사 타이머가 1초를 넘을 때 화살을 생성한다.

발사 이후 플레이어 위치를 계속 추적하지 않으며 목표의 이동을 예측하는 탄도 해법도 사용하지 않는다. 공통 투사체는 초기 조건을 받고, 어떤 입력이나 AI로 그 조건을 만들지는 발사 측이 결정한다.

ProcessRightClick()에 남은 이전 활 발사 코드는 if (false && ...)로 비활성화되어 있다. 현재 동작 설명에는 활성 BOW_PULLING 경로를 사용했다.

중력과 저항으로 궤적 만들기​

UpdateArrowVelocity2()는 지형에 멈추지 않은 화살에 중력 9.8을 적용하고 X·Z 속도에 저항을 준다.

Plain Text
velocity.y -= 9.8 × dt
dragFactor = pow(0.99, dt × 60)
velocity.xz *= dragFactor
nextPosition = currentPosition + velocity × dt

저항을 단순히 매 프레임 0.99배로 적용하지 않고 시간에 따른 지수 형태로 계산한다. 다만 이것이 충돌과 위치 적분까지 모든 프레임 속도에서 완전히 같다는 의미는 아니다. Y에는 저항을 적용하지 않고, 시간 간격에 따라 중력을 더한 뒤 위치를 계산한다.

모델은 속도에서 Yaw·Pitch를 구해 진행 방향을 바라보게 한다. 엔티티 모델 렌더링을 사용하되, 비행 방향은 오브젝트 Transform의 회전으로 표현한다.

현재 회전 계산은 갱신 중인 지역 속도 vVel이 아니라 아직 이전 값인 m_vVelocity를 읽고, 함수 끝에서 새 속도를 저장한다. 따라서 자세가 이번 프레임의 중력·저항 계산보다 한 단계 이전 속도를 기준으로 잡는 점은 개선 대상으로 구분했다.

지형 충돌과 엔티티 피격은 다른 검사​

지형: 이동 후 위치의 AABB 검사​

화살은 예측한 nextPosition에서 Half Extents가 각 축 0.05인 작은 AABB로 복셀 겹침을 검사한다. 겹치면 위치를 진행시키지 않고 m_bOnGround를 켠다. 변수 이름과 달리 바닥뿐 아니라 벽에 막힌 상태도 포함한다.

이 검사는 이전 위치부터 다음 위치까지의 선분이나 부피를 훑는 Sweep이 아니다. 최종 위치에서 겹치지 않으면 중간의 얇은 벽을 지나갈 수 있다. 예를 들어 속도 45에서는 60 FPS에서도 한 프레임 이동 거리가 약 0.75이며, 긴 프레임에서는 한 블록보다 멀리 이동한다.

충돌 시 정확한 접촉 위치로 이동시키거나 속도를 0으로 만드는 코드도 없다. 기존 위치와 속도를 보관한 채 다음 예측 위치를 다시 검사한다. 막던 블록이 제거되어 통과하게 되면 이전에 멈췄던 화살의 속도를 0.01배로 줄이지만, 그 프레임의 nextPosition은 감속 전에 이미 계산되어 있다.

따라서 현재 구현은 지형에서 멈춰 보이는 상태를 만드는 방식이다. 정확한 접촉점에 박힌 뒤 지지 블록이 없어지면 자연스럽게 떨어지는 완성된 고정·해제 시스템과는 차이가 있다.

엔티티: Collider Group 순회​

화살은 작은 Box Collider를 Coll_ArrowHead에 등록하고, 플레이어·돼지·닭·소·좀비·크리퍼·스켈레톤의 몸통 Collider Group을 순회해 교차 여부를 확인한다.

일반 화살의 전달 피해량은 2다. 발사자 Handle과 같은 대상은 생성 후 1초가 지난 경우에만 피해를 전달하는 분기가 있다. 영구적으로 발사자를 제외하는 정책은 아니며, 대상의 실제 체력 감소나 피격 무적은 각 TakeDamage() 구현에 맡긴다.

콜라이더는 Update에서 현재 Transform으로 갱신하고, 피해 검사와 이동은 LateUpdate에서 수행한다. 이 때문에 피해 검사는 이번 LateUpdate의 이동 구간을 검사하는 것이 아니라 먼저 갱신된 콜라이더 위치를 검사한다. 빠르게 움직이는 엔티티 피격에도 연속 충돌이 제공되는 것은 아니다.

피해를 준 뒤에는 SetPendingDestroyCascade()로 제거를 예약한다. 그러나 검사 함수는 첫 명중 후 즉시 반환하지 않으며 공통적인 처리 완료 가드도 없다. 여러 대상이 겹친 상황에서는 같은 프레임에 추가 피해나 폭발 호출이 이어질 수 있는 구조다.

수명 종료와 화살 회수​

화살의 기본 수명은 15초이며 LateUpdate에서 감소한다. 지형에 멈춘 동안에도 수명은 감소하고, 0 미만이 되면 제거를 예약한다. 연사 화살을 만드는 일부 플레이어 경로에서는 수명을 5초로 변경한다.

플레이어가 Coll_ArrowHead와 겹쳤을 때 해당 화살의 IsGround()가 참이면 화살 아이템 1개를 인벤토리에 넣으려 한다. 획득에 성공한 경우에만 화살을 제거하고 회수 소리를 재생한다.

이 경로는 발사자 소유권이나 일반·폭발 화살 타입을 별도로 제한하지 않는다. 회수 가능 여부를 더 세밀하게 만들려면 지형 접촉 상태와 회수 정책을 분리해야 한다.

TNT 점화: 블록을 실행 상태로 전환​

플레이어는 우클릭 Ray로 TNT를 선택하고 부싯돌과 부시를 들고 있으면 TNT 관리 오브젝트를 찾는다. 이후 원래 월드 블록을 AIR로 바꾸고, 동일한 블록 원점에 위쪽 초기 속도 3을 가진 TNT 데이터를 추가한다.

Plain Text
월드 TNT 블록 선택
  → 원래 블록을 AIR로 편집
  → TNT 데이터에 위치·초기 속도 설정
  → AddBlock()
  → 이동·점멸·도화선 진행
  → 폭발 후 리스트에서 제거

월드에 남은 고정 블록과 움직이는 TNT를 동시에 그리는 것이 아니라, 블록 편집과 별도 실행 상태를 연결한다. 이때 청크 메시 갱신은 기존 블록 편집 파이프라인을 따른다.

AddBlock()은 입력 데이터의 도화선 목표 시간을 3.5 + (rand() % 100) / 100으로 덮어쓴다. 따라서 실제 목표값은 3.50부터 4.49까지이며, 구조체의 기본값 4초나 호출자가 넣은 값이 그대로 사용되지는 않는다.

움직이는 TNT와 폭발 예고​

TNT의 위치는 블록 원점 기준으로 저장한다. 충돌 검사에서는 각 축에 0.5를 더해 중심으로 바꾸고 Half Extents 0.49의 AABB를 사용한다. 중력 20, 접지 시 수평 마찰, Y·X·Z 순서의 이동 보정으로 지형을 따라 움직인다.

Rigidbody나 TNT끼리의 물리 접촉을 푸는 시뮬레이션은 아니다. 다른 TNT에 속도를 더하는 폭발 밀어내기는 별도의 게임 로직이다.

도화선 진행 중에는 매 LateUpdate마다 윗부분에 점화 입자 1개를 요청한다. 점멸 주기는 누적 시간이 2를 넘기 전에는 0.5초, 이후에는 0.1초다. 목표 시간의 마지막 0.5 구간에는 렌더링 크기를 1에서 1.2로 키운다. 이 팽창은 렌더링 행렬에 적용하며 충돌 AABB 크기를 함께 키우지는 않는다.

LateUpdate에서 fElapsedTime += dt를 두 번 수행하므로 설정값 3.504.49에 도달하는 시간은 약 1.752.25초다.

점화 입자는 프레임마다 생성 요청을 보낸다.

여러 TNT를 인스턴싱으로 그리기​

관리 오브젝트는 TNT 데이터를 std::list에 보관하고, 렌더링용 Transform·Color 배열을 별도로 구성한다. 공통 TNT 메시와 인스턴스 버퍼를 함께 바인딩해 DrawIndexedInstanced()로 그린다.

매번 TNT 메시를 복제하는 대신 위치·팽창·점멸 색상만 인스턴스 데이터로 전달한다. 다만 CPU의 이동·타이머 처리는 여전히 항목마다 수행하며, 인스턴싱이 게임 로직 비용까지 없애는 것은 아니다.

동적 GPU 버퍼는 인스턴스 1,000개 크기로 생성한다.

폭발의 공통 진입점​

ExplodeAndDamageColliding()은 폭발 위치·반경·피해량·연기 입자 수를 받고 다음 작업을 수행한다.

  1. 활성 카메라와의 거리에 따라 음량을 계산해 폭발음 4개 중 하나를 재생한다.
  2. VoxelProcessExplodeBlock()으로 범위 안의 블록을 제거한다.
  3. 폭발 연기를 요청한다.
  4. 같은 중심·반경의 임시 Sphere로 엔티티 Collider Group을 검사하고 피해를 전달한다.
호출 대상반경전달 피해량연기 입자 수
점화된 TNT4825
폭발 화살5315
크리퍼 폭발105100

이 값은 TakeDamage()에 전달하는 피해량이다. 대상이 추가 정책을 적용하면 최종 체력 감소량은 달라질 수 있다.

TNT는 저장 위치에서 (0.5, 1.0, 0.5)를 더한 윗면 중앙 부근을 폭발 중심으로 사용한다. 블록 중앙 (0.5, 0.5, 0.5)과는 다르다. 다른 TNT를 밀어내는 로직은 저장 원점을 기준으로 하므로 두 효과의 중심도 완전히 같지는 않다.

음량은 카메라 거리 32를 기준으로 감쇠한다. 벽에 의한 차폐나 음향 공간 시뮬레이션이 아니라 거리 기반 음량 조절이다.

구형 범위에서 블록 제거​

ProcessExplodeBlock()은 중심을 floor()하고 반경을 ceil()한 정수 범위에서 X·Y·Z를 순회한다. 각 블록 좌표와 폭발 중심의 거리 제곱이 반경 제곱 이하이면 후보로 취급한다.

Plain Text
distanceSquared = (x - center.x)^2
                + (y - center.y)^2
                + (z - center.z)^2
destroyCandidate = distanceSquared <= radius^2

이때 거리 계산 대상은 블록 중심이나 블록 AABB 전체가 아니라 정수 좌표다. 구형 폭발 범위를 격자에 근사한 방식이므로 경계의 포함 여부가 블록 중심 기준 구현과 다를 수 있다.

BEDROCK과 OBSIDIAN은 제외하고, 나머지 비어 있지 않은 블록은 ProcessPlayerBlockSet(..., AIR, false)로 제거한다. 블록마다 폭발 저항을 차감하거나 광선을 전파해 벽 뒤를 보호하는 모델은 아니다. 보호 블록 자체는 남아도 그 뒤의 일반 블록이 같은 반경 안에 있으면 제거될 수 있다.

이 편집 함수는 AIR 변경을 Edit Shadow에 기록하고 물·용암 갱신과 조명 제거 처리를 호출한다. 개별 블록 파괴음은 끄되 월드 후처리는 재사용한다. 청크 메시를 폭발 함수 안에서 직접 즉시 다시 만드는 구조는 아니다.

드롭과 연쇄 점화​

범위 안에서 TNT를 발견하면 원래 블록을 제거한 뒤 관리 오브젝트에 새 TNT 데이터를 넣는다. 새 항목에도 AddBlock()의 무작위 도화선이 적용된다. 즉시 모든 TNT를 재귀 폭발시키는 방식이 아니라 점화 상태를 이어 붙이는 연쇄 반응이다.

실행 중인 리스트에 새 항목이 추가되는 구조라 같은 LateUpdate 순회에서 새 TNT까지 도달할 수 있다. 새 항목을 다음 프레임으로 고정하는 별도 대기 큐나 스냅샷은 없다.

TNT가 아닌 블록은 Randf(0, 1) > 0.9일 때만 드롭 후처리와 아이템 변환을 수행한다. 따라서 일반적인 난수 분포를 가정하면 약 10% 확률의 드롭 요청이지만, 변환 함수가 실패하면 최종 아이템이 생성되지 않는다.

주의할 점은 DestoryBlockAfterProcess()도 이 확률 분기 안에 있다는 것이다. 보관함 내용물 방출·저장 정보 제거와 같은 후처리가 이 함수에 연결되어 있으므로, 블록은 항상 제거하면서 관련 저장 데이터는 확률적으로만 정리하는 경로가 된다. 확장 시에는 필수 제거 후처리와 선택적인 아이템 드롭을 나눌 필요가 있다.

주변 TNT 밀어내기​

점화된 TNT가 폭발한 뒤에는 현재 활성 TNT 리스트를 한 번 더 순회한다. 거리 3 이내의 다른 TNT에 바깥 방향과 위쪽 성분을 섞은 속도를 더한다.

Plain Text
ratio = (3 - distance) / 3
pushDirection = normalize(normalize(other - center) + (0, 0.5, 0))
otherVelocity += pushDirection × ratio × 10

가까울수록 크게 밀리고 위로 튀게 하는 연출이며 질량이나 접촉 충격량을 푸는 물리 계산은 아니다. 해당 로직은 TNT의 LateUpdate에 있으므로, 공통 폭발 함수만 호출하는 화살·크리퍼가 기존 활성 TNT에 동일한 밀어내기를 자동 적용하는 것은 아니다.

폭발 화살의 현재 처리 범위​

폭발 화살은 지형에 멈춘 상태이거나 지원하는 몬스터와 교차하면 공통 폭발 함수를 호출한다. 지형 충돌 판정은 LateUpdate의 폭발 검사보다 뒤에 있으므로, 그 프레임에 처음 지형에 막힌 경우 다음 LateUpdate의 검사에서 폭발하게 된다.

플레이어와의 직접 교차 분기에는 폭발 호출이 주석 처리되어 있다. 반면 몬스터와의 교차나 지형 충돌로 발생한 범위 폭발은 공통 함수에서 플레이어도 검사한다. 따라서 직접 접촉과 범위 피해의 정책이 동일하지 않다.

또한 제거 예약 후에도 검사와 이동이 계속되는 경로가 있다. 단일 명중·단일 폭발을 보장하려면 명중 처리 완료 상태를 두거나 처리 직후 흐름을 종료하는 정책을 먼저 정해야 한다.

폭발 범위 순회​

폭발은 격자 후보를 순회한 뒤 구형 범위로 거른다. 반경 4이면 최대 9³ = 729개, 반경 10이면 21³ = 9,261개 좌표가 후보가 된다.

제거되는 블록마다 유체·조명 후처리도 호출한다. 엔티티 피해는 등록 그룹들을 선형 순회하며, TNT가 여러 번 폭발하면 활성 TNT 밀어내기 순회도 반복한다.
